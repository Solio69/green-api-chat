# Конституция GREEN-API Chat

**Версия**: 1.0.0
**Дата**: 2026-09-29
**Основание**: согласованные правила разработки и спецификация E02.1.

## C1. Участие пользователя
Русский язык, краткие объяснения причин и вариантов при груминге. Существенные
решения о поведении, данных, безопасности, стоимости и границах принимаются
с пользователем. Неизвестное не выдаётся за факт.

## C2. Последовательные задачи
Один каталог feature — одна небольшая задача. Одобрение эпика не разрешает
его целиком реализовать. Следующая задача обсуждается отдельно.

## C3. Два решения
Согласование spec.md разрешает техническую подготовку. Полный отчёт после
планирования и анализа предшествует отдельному разрешению на реализацию.
Существующая авторизация из переписки не теряется и повторно не запрашивается.

## C4. Политика Git
Применяется только [GIT_POLICY.md](../../GIT_POLICY.md). Все запреты и узкое
исключение staging сохраняются. Служебные скрипты не вызывают Git.

## C5. Действия пользователя
Агент не скачивает и не устанавливает пакеты или ПО, не выполняет миграции и
изменения данных БД. Если требуется действие, объясняет его и передаёт команды
пользователю. Разрешение писать код не отменяет этих ограничений.

## C6. Данные и изоляция
Выбор feature явный, существующие документы сохраняются при подготовке.
Работа ограничена выбранным проектом и задачей. Реальные секреты и персональные
реквизиты в документации, тестах и выводах отсутствуют.

## C7. Проверяемость
Анализ не пишет файлы; исправления выполняются после завершения прохода.
Результаты различают Passed, Failed, Blocked, NotRun. Проверки соответствуют
риску изменения; словесное ревью не выдаётся за выполнение инструмента.
Завершение включает соответствие спеке, предкоммитное ревью, дальнейшие шаги
и английское название коммита.

## C8. Соразмерность
Переносятся только нужные правила и инструменты. Не вводить чужие продуктовые
решения, преждевременные требования к БД, UI и архитектуре ради шаблона.
Документы содержат текущее состояние; история изменений не встраивается.

## Управление
[AGENTS.md](../../AGENTS.md) задаёт поведение агента,
[описание процесса](../../docs/spec-kit-workflow.md) — этапы и артефакты.
При конфликте шаблона с принципами исправляется шаблон. Существенное изменение
принципа сначала обсуждается; документ не является самостоятельной авторизацией.
