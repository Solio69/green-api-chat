# GIT_POLICY.md

## Политика работы агента с Git

### 1) Что агенту запрещено
По умолчанию агенту запрещено выполнять Git-команды, которые изменяют коммиты, ветки, теги, индекс или рабочее дерево. Единственное исключение для индекса описано в разделе 3.

В том числе запрещены:
- `git commit`
- `git push`
- `git pull`
- `git merge`
- `git rebase`
- `git cherry-pick`
- `git reset` (любой режим)
- `git revert`
- `git tag` (создание/удаление)
- `git stash` (все варианты)
- `git checkout` (переключение веток или откат файлов)
- `git switch`
- `git restore`
- `git clean`
- любые другие команды Git с записью/изменением состояния репозитория

### 2) Что агенту разрешено
Разрешен только read-only доступ к Git для анализа и отчетности.

Разрешенные примеры:
- `git status`
- `git log`
- `git diff`
- `git show`
- `git blame`
- `git branch --show-current`
- `git rev-parse`

### 3) Staging по прямой просьбе пользователя
Агент может изменять Git index только по прямой просьбе пользователя в текущем диалоге.

Разрешено:
- выполнить `git add -- <явно перечисленные пути>` для файлов, относящихся к работе этого агента;
- выполнить `git restore --staged -- <явно перечисленные пути>` только по прямой просьбе пользователя об удалении этих файлов из staging.

Перед staging агент обязан:
- проверить `git status --short` и содержимое diff каждого добавляемого файла;
- убедиться, что файл целиком относится к работе этого агента и не содержит несогласованных изменений другого агента;
- остановиться и сообщить о конфликте, если принадлежность изменений неоднозначна.

Запрещено использовать широкие команды `git add .`, `git add -A`, `git add --all` и пути, способные захватить чужие файлы. После staging агент обязан проверить `git diff --cached --check` и `git diff --cached --name-status`, затем перечислить пользователю все добавленные в индекс файлы. Staging не даёт разрешения создавать коммит.

### 4) Приоритет правила
- Эта политика имеет приоритет над привычными агентными практиками.
- Если задача пользователя предполагает коммит, push, слияние или другое запрещённое изменение Git, агент должен остановиться и сообщить об ограничении. Staging выполняется только по правилам раздела 3.
- Изменение этой политики возможно только через явное редактирование этого файла пользователем/командой.
