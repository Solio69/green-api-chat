# GREEN-API Chat

Учебный проект по тестовому заданию: интерфейс текстовой переписки в Telegram
через GREEN-API с собственной серверной частью на Next.js.

## Текущее состояние

Подготовлена локальная основа приложения:

- Стартовая страница `/`.
- Серверный обработчик `GET /api/health`.
- TypeScript в строгом режиме, SCSS Modules с БЭМ, общие константы и миксины.
- Отдельные команды проверки типов, линтера, форматирования и сборки.

Подключение инстанса, чаты, отправка, получение и сохранение сообщений ещё
не реализованы. Публикация на Vercel запланирована отдельной задачей.
Фактические результаты приёмки основы — в
[отчёте E02.2](specs/002-nextjs-foundation/verification.md).

## Требования

- Node.js 24.x.
- npm 11.x; версия подготовки проекта — 11.11.0.
- Современный браузер.

Проверить окружение:

```powershell
node --version
npm --version
```

PowerShell 7 требуется только для служебных скриптов Spec Kit. Команды приложения
можно запускать из обычного терминала Windows, macOS или Linux.
Токены, инстанс GREEN-API, Telegram и база данных для запуска этой основы не нужны.

## Установка

Откройте терминал в корне полученного репозитория, где находится `package.json`.

Если `package-lock.json` уже есть:

```powershell
npm ci
```

Команда устанавливает зафиксированные зависимости, пересоздавая `node_modules`.
Её нужно выполнять при остановленных серверах приложения.

При первой подготовке проекта, пока lock-файла нет:

```powershell
npm install
```

Эта команда создаёт `package-lock.json`; он должен храниться в репозитории.
После этого установка воспроизводится через `npm ci`.

Проверьте полноту установки:

```powershell
npm ls --depth=0
```

При ошибках `missing` или `invalid` сначала исправьте установку.
Не обходите конфликты с помощью `--force` или `--legacy-peer-deps`.

## Локальная разработка

```powershell
npm run dev
```

Откройте [главную страницу](http://localhost:3000/). Для остановки сервера
нажмите `Ctrl+C` в его терминале.

Если порт 3000 занят, выберите свободный:

```powershell
npm run dev -- --port 3001
```

Используйте выбранный порт и при проверке API.

## Проверки качества

Выполняйте команды по очереди, продолжая после успешного результата каждой:

```powershell
npm run typecheck
npm run lint
npm run format:check
```

- `typecheck` генерирует служебные типы маршрутов и проверяет TypeScript.
- `lint` проверяет правила Next.js, React и TypeScript; предупреждения также
  требуют исправления.
- `format:check` проверяет оформление кода без изменения исходников.

Чтобы явно применить форматирование:

```powershell
npm run format
```

Форматтер охватывает приложение, его конфигурации и README. Документы и служебные
файлы Spec Kit исключены из этой проверки; SCSS проверяется форматтером,
компилятором при сборке и ревью. ESLint не проверяет SCSS.

## Организация стилей

Цвета и общие значения оформления находятся в `src/styles/_tokens.scss`.
Повторяющиеся группы свойств — в `src/styles/_mixins.scss`; миксин `typography`
используется для заголовка и описания. SCSS-файлы подключают эти определения
через `@use` с пространствами имён `tokens` и `mixins`.
Правило действует для всех новых стилей проекта и закреплено в `AGENTS.md`.

## Production-сборка

Сначала остановите dev-сервер, затем выполните:

```powershell
npm run build
npm run start
```

Запускайте `start` только после успешной сборки. Проверьте страницу и health
по тому же локальному адресу. По окончании остановите сервер через `Ctrl+C`.
Эти команды запускают приложение локально и не публикуют его на Vercel.

## Проверка сервера

При запущенном приложении откройте
[health endpoint](http://localhost:3000/api/health)
или выполните во втором терминале PowerShell:

```powershell
$taskHealth = Invoke-WebRequest -UseBasicParsing -Uri 'http://localhost:3000/api/health'
$taskHealth.StatusCode
$taskHealth.Headers['Content-Type']
$taskHealth.Headers['Cache-Control']
$taskHealth.Content
```

Ожидается HTTP 200, `Content-Type: application/json`,
`Cache-Control: no-store` и тело:

```json
{ "status": "ok" }
```

Ответ подтверждает, что серверный обработчик отвечает на запросы.
Он не проверяет подключение к GREEN-API или Telegram. Ответ не кешируется;
обработчик не создаёт сессию и не обращается к внешним сервисам.
При остановленном сервере соединение недоступно.

## Если запуск не удался

| Проблема                                | Что проверить                                             |
| --------------------------------------- | --------------------------------------------------------- |
| Зависимости отсутствуют                 | Выполнить установку и `npm ls --depth=0`                  |
| Версия Node не подходит                 | Проверить `node --version` и выбранную среду              |
| Порт занят                              | Остановить свой предыдущий сервер или выбрать другой порт |
| `start` не находит сборку               | Сначала успешно выполнить `npm run build`                 |
| Проверка качества завершилась с ошибкой | Исправить указанную причину и повторить команду           |

Не запускайте dev и production одновременно в одной рабочей папке.
Локальные секреты, зависимости и результаты сборки исключены из Git.
Реальные токены и персональные данные нельзя добавлять в исходники или документы.
