# GREEN-API Chat

Учебный проект по тестовому заданию: минимальный интерфейс переписки в Telegram через GREEN-API с серверной частью на Next.js. Разработка идёт небольшими согласованными задачами; чат и отправка сообщений пока не реализованы.

## Что работает

- Вход на /login проверяет реквизиты через серверный GetStateInstance и создаёт зашифрованную HttpOnly-cookie на 24 часа. Ошибки объясняются на форме; токен можно показать и скрыть.
- Защищённая главная проверяет сессию и получает безопасный профиль через GetAccountSettings. Она показывает аккаунт, поиск и адаптивный каркас MAX: две панели на широком экране, одну на телефоне. Системные светлая и тёмная темы поддерживаются.
- Поиск по телефону или username вызывает серверный CheckAccount. Результат, отсутствие получателя и сбои различимы. Кнопка «Написать» пока не открывает переписку.
- GetChats → GET /api/chats → useChats реализованы и проверены. TanStack Query 5.104.0 хранит список только в памяти текущего подключения: staleTime 60 секунд, gcTime 5 минут, без polling, запросов по focus и автоматического клиентского retry. Видимый список подключён в 015: личные чаты, загрузка, подтверждённая пустота, ошибки и ручное обновление/повтор.
- Выход удаляет cookie текущего браузера и очищает Query-кэш после успешного ответа. При подтверждённой потере доступа сессия завершается; временный сбой сохраняет её и предлагает повторить проверку. Другие устройства сохраняют свои сессии.
- GET /api/health проверяет доступность нашего обработчика. История, отправка и получение сообщений — последующие задачи; собственной БД и постоянного браузерного хранилища переписки нет.

Контракты: [вход](specs/006-login-session/spec.md), [выход](specs/008-logout/spec.md), [поиск](specs/009-recipient-lookup/spec.md), [профиль](specs/013-account-profile/spec.md), [слой списка](specs/014-chat-list-query/spec.md), [каркас](specs/015-chat-workspace-ui/spec.md), [оформление поиска](specs/016-recipient-search-ui/spec.md). [Обзор эпиков](docs/project-overview.md) отделяет готовые части от следующих шагов.

## Требования и установка

Нужны Node.js 24.x, npm 11.x и современный браузер. В корне проекта выполните `npm ci` для установки зафиксированных зависимостей. Для браузерных тестов один раз нажмите ▶ у `test:install-browser` в панели **NPM Scripts** VS Code или выполните `npm run test:install-browser`. Установку зависимостей и ПО выполняет пользователь.

Для ручной проверки входа нужен авторизованный Telegram-инстанс GREEN-API и его реквизиты. Автоматические тесты работают на фиктивных данных без обращения к реальному инстансу. База данных и миграции для текущего шага не нужны.

## Локальный запуск

Сгенерируйте длинный секрет локально:

```powershell
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Создайте в корне проекта игнорируемый Git файл `.env.local` с одной строкой `SESSION_PASSWORD=<сгенерированное значение>`. Не добавляйте секрет или реквизиты GREEN-API в Git и не присылайте их в переписку. Без этого секрета успешный вход не может создать сессию.

В VS Code откройте **NPM Scripts** и нажмите ▶ у `dev`. Равнозначная команда — `npm run dev`. Откройте [форму входа](http://localhost:3000/login). Для остановки нажмите Ctrl+C в терминале сервера. Если порт 3000 занят, можно запустить `npm run dev -- --port 3001` и открыть адрес с этим портом.

Для ручной проверки откройте `/` без сессии и убедитесь в переходе на `/login`. Введите свои реквизиты: при `authorized` откроется `/` с профилем, поиском и каркасом чата. Слева отображаются личные чаты; «Обновить» запрашивает актуальный список с сохранением предыдущих строк. Открытие переписки — следующий шаг. Обновите страницу и нажмите «Выйти»: должна открыться обычная форма входа, а прямое открытие `/` снова потребует входа. Затем попробуйте неверный токен и исправьте его. Настоящие реквизиты вводятся только в локальном интерфейсе. При публикации секрет задаётся отдельно в настройках окружения Vercel; публикация запланирована на финальный этап проекта.

## Проверки

Команды доступны кнопками в **NPM Scripts** или в терминале:

```powershell
npm run typecheck
npm run lint
npm run lint:styles
npm run format:check
npm run test:integration
npm run test:query
npm run test:e2e
```

`typecheck` проверяет типы приложения и тестов, `lint` — правила кода, `format:check` — форматирование без правки файлов. Для автоисправлений нажмите ▶ у `lint:fix`, затем у `format`: первая команда применяет готовые исправления ESLint, вторая форматирует код. Эти команды изменяют файлы; результат следует просмотреть в diff. `test:integration` проверяет серверную логику, состояния GREEN-API и cookie с фиктивными данными. `test:query` собирает отдельный React-стенд на порту 3102 и проверяет настоящий provider/hook, кэш, смену подключения и выход. `test:e2e` собирает production-приложение, запускает собственный сервер на `http://127.0.0.1:3101` и проверяет маршруты и форму в Chromium. Перед E2E остановите dev-сервер в этой рабочей папке. Для тестов реальный `SESSION_PASSWORD` не требуется: используется фиктивное значение.

Автоматические правила определены в [eslint.config.mjs](eslint.config.mjs), [prettier.config.mjs](prettier.config.mjs) и [stylelint.config.mjs](stylelint.config.mjs). `lint:styles` проверяет все исходные SCSS-файлы без исправления, а Prettier форматирует JS/TS без необязательных точек с запятой. Смысловые соглашения для компонентов и тестов находятся в [правилах написания кода](docs/CODING_RULES.md); [карта правил](docs/CODE_STYLE.md) ведёт к конфигурациям и командам.

Ожидаемый результат проверок — завершение команд с кодом 0 и без пропущенных тестов. Последний HTML-отчёт браузерного прогона можно открыть через `test:report`. Общая предкоммитная проверка описана в [verification.md](specs/017-precommit-refactor/verification.md). Markdown в docs/specs исключён из штатного format:check; для него используется установленный Prettier с --ignore-path NUL.

Для локальной production-проверки при остановленном dev-сервере выполните `npm run build`, затем `npm run start`. Это не публикует приложение. Служебный [health endpoint](http://localhost:3000/api/health) должен вернуть HTTP 200, `Cache-Control: no-store` и JSON `{"status":"ok"}`; он не проверяет GREEN-API.

## Структура и соглашения

Next.js App Router и TypeScript разделяют серверную проверку доступа и клиентскую форму. SCSS Modules используют БЭМ; цвета и повторяемые размеры находятся в `src/styles/_tokens.scss`, общие группы стилей — в `src/styles/_mixins.scss`. Правила разработки: [смысловые правила для агента](docs/CODING_RULES.md), [карта автоматических проверок](docs/CODE_STYLE.md), [процесс Spec Kit](docs/spec-kit-workflow.md), [политика Git](GIT_POLICY.md).

При разработке используется ИИ-агент для подготовки кода, документации и проверок. Автор проекта участвует в обсуждении и согласовании требований и технических решений.
