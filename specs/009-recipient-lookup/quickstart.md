# Проверка E04.1 после реализации

**Статус**: автоматические проверки прошли; ручная проверка реального инстанса ожидается.

## Автоматические проверки

Используются установленные зависимости. Перед production-сборкой и Playwright E2E остановить запущенный `dev` в этой папке; это исключает конфликт процессов и состояния Next.js.

1. `npm run test:integration` — проверка серверного `CheckAccount`, формата ввода, сессии и кодов ответа без реального GREEN-API.
2. `npm run test:e2e` — проверка формы на настоящей странице с фиктивными ответами провайдера; эта команда сама выполняет production-сборку, не использует реальные реквизиты и не расходует лимит инстанса.
3. `npm run typecheck`, `npm run lint`, `npm run format:check` — типы, правила проекта и формат. Отдельная `npm run build` нужна только если E2E не состоялся. Порядок Red/Green и точные результаты записаны в `verification.md`.

Результаты автоматических проверок и поведенческого Red записаны в [verification.md](verification.md). Браузерные тесты используют фиктивные ответы GREEN-API.

## Ручной сценарий пользователя

1. Запустить `dev` через кнопку NPM Scripts в VS Code и войти на `/login` со своими реквизитами GREEN-API. Это подтверждает `GetStateInstance` и открывает главную страницу.
2. Убедиться, что на главной есть одно поле «Телефон / @username», «Найти» и «Выйти», а JSON состояния больше не показан.
3. Ввести номер тестового собеседника с кодом страны и только цифрами, нажать «Найти». При `exist: false` увидеть подсказку, затем выбрать «Найти по @username».
4. Ввести username собеседника с `@` или без него и выполнить поиск. При положительном `CheckAccount` увидеть «Пользователь найден» и `chatId`. Сообщение на этом шаге не отправляется.
5. Проверить пустой ввод и исправление ошибки, а также повторную попытку после безопасной ошибки сервиса, если она встретится. Не вызывать повторные проверки без необходимости: тариф Developer ограничивает `CheckAccount`.
6. Обновить страницу: форма возвращается в исходное состояние; cookie входа продолжает действовать. Проверить «Выйти» и переход на `/login`.

Не присылать токен, номер, `chatId` или вкладку Network Payload в чат. Для отчёта достаточно описать результат словами и, если нужно, безопасный код ошибки без персональных данных. Данные в БД и миграции не затрагиваются.
