# Quickstart: D01 — экран входа в стиле MAX

**Стадия:** разрешённая реализация. Команды выполняются после завершения всей серии правок.

## Перед реализацией

1. Ознакомиться с [spec.md](spec.md), [plan.md](plan.md), [контрактом UI](contracts/login-ui.md) и [tasks.md](tasks.md).
2. Проверить полученное в переписке разрешение на продуктовый код и тесты. Сверить актуальные исходники общих компонентов; не перезаписывать работу другого агента.
3. Установки и перемены `.env.local` не требуются. Существующий `SESSION_PASSWORD` не публикуется и не меняется ради оформления.

## Автоматическая проверка после всей серии правок

Папка: `D:\Pet-projects\green-api-chat`. Можно запускать скрипты через NPM Scripts в VS Code.

Перед `test:e2e` dev-сервер и другие сборки в этой папке должны быть остановлены: Playwright создаёт собственную production-сборку и сервер. Не прерывать чужой процесс самостоятельно; выбрать свободный момент.

```powershell
npm run test:e2e -- tests/e2e/health.spec.ts tests/e2e/home.spec.ts tests/e2e/login-flow.spec.ts tests/e2e/login-form-safety.spec.ts tests/e2e/login-form.spec.ts tests/e2e/login-ui.spec.ts tests/e2e/logout-flow.spec.ts tests/e2e/recipient-search.spec.ts
npm run typecheck
npm run lint
npm run lint:styles
npm run format:check
```

Команды запускаются последовательно. E2E содержит сборку; дополнительный build при её успехе не нужен. `test:integration` не повторяется только ради CSS: серверные файлы и контракты не меняются. При обнаруженном расширении серверного объёма сначала пересогласовать задачу и необходимые проверки.

Результаты и ссылки на скриншоты/trace записываются в `verification.md`. Ошибка окружения — Blocked, провал требования — Failed, отсутствие запуска — NotRun.

## Ручная приёмка

После окончания production-проверок запустить ▶ `dev` и открыть `/login`.

- Сравнить экран с макетом на 390 и 1280 px: спокойный фон, карточка, синий/сиреневый акцент, нет зелёной верхней полосы, есть одна синяя ссылка на кабинет без дополнительных строк. Проверить светлую и тёмную тему устройства, затем сменить её при заполненном токене: значение не должно очищаться.
- Пустой submit и Enter показывают компактный красный текст под полями (12 px, отступ 6 px); исправление обновляет их без изменения высоты карточки; глаз переключает токен внутри поля.
- Проверить Tab-навигацию, видимый обычный и ошибочный фокус, отсутствие перекрытия текста глазом.
- На 320/360/390 px и при низкой высоте убедиться, что нет горизонтального скролла и можно дойти до кнопки вертикальной прокруткой.
- По управляемому E2E проверить задержанное ожидание, доступный статус, reduced-motion, forced-colors и контраст. Не заставлять настоящий сервис отвечать медленно ради скриншота.
- Проверить безопасную новую вкладку кабинета, вход и явный выход без перезагрузки документа; сбой выхода должен оставлять понятную ошибку и повтор.
- Проверить сохранение исходного оформления поиска и выхода после открытия `/`.

Ручные проверки отмечаются в [acceptance.md](checklists/acceptance.md) фактическими статусами. Реальные токены, номера и переписка в отчёт и скриншоты не включаются.
