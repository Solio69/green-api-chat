## Dependencies & Execution Order

`Разрешение кода → T001 → T002 → T003 → T004 → T005 → T006 → T007`.

Это оформление и представление уже существующего ожидания. Тесты UI подготовлены перед соответствующими CSS/JSX-правками; проверка выполняется один раз после завершённой серии. Клиентские переходы и отказ выхода следуют тест → подтверждённый Red в T002 → реализация в T005 → Green в T006. Серверную бизнес-логику не расширять. Если она станет необходима — отдельное согласование и подтверждённый поведенческий Red перед её реализацией, затем Green и Refactor; ошибка окружения Red не заменяет.
