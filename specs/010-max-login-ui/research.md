# Research: D01 — экран входа в стиле MAX

**Дата:** 2026-10-01.
**Статус:** технические решения реализованы; проверка результата описана в verification.md.

## Проверенные локальные факты

- `LoginForm` уже хранит `isSubmitting`, блокирует `fieldset`, предотвращает повторный запрос через `requestPending`, меняет подпись кнопки на «Проверка...» и использует реальный серверный вход. Новое состояние запроса не требуется.
- `CredentialField` и `TokenVisibilityButton` используются экраном входа. `SubmitButton` используется также `RecipientSearchForm`.
- Зелёные цвета и тени находятся в `src/styles/_tokens.scss`; общий `focus-ring` из `_mixins.scss` используется несколькими компонентами. Их замена по умолчанию затронет поиск и выход.
- `globals.scss` задаёт фон и отступы `body`. Страница входа имеет отдельный `LoginPage.module.scss`; менять общий `body` ради одной страницы не требуется.
- Имеются браузерные тесты формы, безопасности, входа, выхода и поиска. Playwright запускает собственную production-сборку с фиктивным GREEN-API. Инструменты устанавливать не требуется.
- `tests/e2e/login-flow.spec.ts` уже проверяет задержанный POST и блокировку повторной отправки. `login-form.spec.ts` проверяет глаз, клавиатуру, ошибки и безопасную ссылку без дополнительных подсказок; `login-form-safety.spec.ts` — защиту реквизитов и геометрию страницы.
- В `src/lib/ui/constants.ts` есть `ROLE_STATUS`; в `LOGIN_COPY` уже есть текст ожидания. Тестовые имена и независимые ожидания находятся в `tests/constants.ts`.

Локальные факты установлены чтением файлов. Результаты будущей реализации и её тестов из этого не следуют.

## Общая системная палитра

CSS custom properties задаются один раз на `:root` миксином `system-theme` из `src/styles/_theme.scss`. Цветовые значения находятся в `_tokens.scss`; `globals.scss` подключает тему и задаёт фон/текст документа. Страницы входа и главная, шапка, аватар, поиск и выход наследуют палитру. Отдельного фонового слоя входа нет.

Передача палитры пропсами требует настройки каждого компонента. React Context нужен для управляемого выбора темы, но для автоматического следования устройству добавляет ненужное состояние. Для текущего приложения выбран CSS-каскад и `prefers-color-scheme`: тема меняется без JS, хранения, запроса и перезагрузки. Проверки подтверждают сохранение полей и темы при навигации.

## Палитра и контраст

Светлая и тёмная палитры макета используются как ориентир; обычный текст должен выполнить FR-010. Цвет второстепенного текста выбран немного темнее мокового референса, чтобы он был читаемым при небольшом размере.

| Назначение             | Цвет                   | Фон проверки | Расчёт контраста |
| ---------------------- | ---------------------- | ------------ | ---------------- |
| Фон страницы           | `#eff5fb`              | —            | Не текст         |
| Карточка и поля        | `#ffffff`              | —            | Не текст         |
| Основной текст         | `#17191d`              | `#ffffff`    | 17.60:1          |
| Второстепенный текст   | `#626e7e`              | `#ffffff`    | 5.18:1           |
| Действие/обычный фокус | `#5266f6`              | `#ffffff`    | 4.58:1           |
| Текст акцентной кнопки | `#ffffff`              | `#5266f6`    | 4.58:1           |
| Ошибка                 | Существующий `#b42318` | `#ffffff`    | 6.57:1           |

Расчёт выполнен по относительной яркости sRGB при подготовке документов, без запуска приложения. Это не проверка вычисленных стилей браузера. Hover должен сохранить контраст, disabled не уменьшает непрозрачность текста до нечитаемой. Значения тени, границы, размеров и animation-duration тоже выносятся в токены, а не копируются из HTML в компоненты.

## Тема устройства и ошибки

`prefers-color-scheme: dark` переопределяет общие переменные корня приложения. Тема обновляется браузером без JS, запроса, хранения или перезагрузки; значения полей сохраняются. На странице нет переключателя. Тёмные токены: фон `#111419`, карточка/поле `#202126`, текст `#f1f3f6`, подсказка `#9298a5`, действие `#6475ff`, ошибка `#ff9391`. Текст кнопки тёмный `#111419`: белый на этом акценте не обеспечивает 4.5:1. Контраст тёмной кнопки и ошибки подтверждён вычисленными стилями в E2E. Ссылка в тёмной теме использует существующий более светлый акцент `#7c89ff` через локальный `--ui-link-color`; обычное состояние и hover должны иметь не ниже 4.5:1.

Под полем ошибка имеет 12 px и отступ 6 px. Постоянный live-region резервирует одну строку ошибки и её отступ; рамка красная, мягкая красная подсветка появляется при фокусе. Под формой одна акцентная ссылка на кабинет с безопасной новой вкладкой, без дополнительных строк.

## Клиентские переходы

При успешном входе `useRouter().replace` открывает главную без загрузки нового документа и не оставляет форму входа в истории переходов. Серверная проверка cookie сохраняется. `LogoutButton` отменяет нативную отправку после гидратации, делает fetch существующего POST выхода, затем `replace` на вход и `refresh` данных маршрутизатора. Fetch следует существующему 303 без навигации документа. При отказе отображается ошибка, повтор доступен; во время запроса кнопка блокируется. Без JavaScript существующая action/method POST работает нативно. Никаких новых HTTP-контрактов нет.

## Индикатор и доступность

| Вариант                                       | Преимущества                                                         | Ограничения                                             | Решение   |
| --------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------- | --------- |
| Новый компонент/пакет Spinner                 | Готовые варианты                                                     | Один индикатор не оправдывает новую зависимость и API   | Не выбран |
| Индикатор внутри существующего `SubmitButton` | Простое представление переданного ожидания; переиспользует компонент | Нужен необязательный проп и сохранение поведения поиска | Выбран    |

`SubmitButton` получает `isLoading?: boolean` со значением `false` по умолчанию. Проп влияет только на декоративный индикатор и `aria-busy` кнопки: не меняет `type`, disabled, label, запрос или обработчик. `LoginForm` передаёт существующий `isSubmitting`.

Живой текстовый статус размещается в постоянно существующей визуально скрытой области `role=status` вне disabled fieldset. У fieldset/кнопки допускается `aria-busy`; статус не помещается внутрь элемента, который занят и может задерживать объявления потомков. Индикатор скрыт от accessibility tree; подпись кнопки остаётся «Проверка...». Изменение статуса не перемещает фокус.

`prefers-reduced-motion: reduce` отключает вращение, сохраняя индикатор и текст. В forced-colors остаётся системный outline; стандартный outline не удаляется без видимой альтернативы. Геометрия кнопки не меняется при появлении индикатора.

## Проверки и соразмерность

Добавляется один браузерный файл `tests/e2e/login-ui.spec.ts` и локальный файл уникальных UI-фикстур `tests/e2e/login-ui.constants.ts`. Общие роли, тексты, фиктивные реквизиты и размеры управления переиспользуются из существующих тестовых констант. Независимые ожидаемые цвета и семантика интерфейса не импортируются из проверяемых токенов/компонентов.

Оформление и визуализация существующего состояния не меняют серверный контракт. Для оформления искусственный Red не требуется; клиентские переходы и отказ выхода проходят подтверждённый Red → Green; тесты представления готовятся до CSS/JSX-правок, итоговый прогон проводится после всей серии. Если понадобится менять правила запроса, задача возвращается на обсуждение; соответствующая логика потребует Red → Green → Refactor.

Новые unit-тесты констант цветов, snapshot всего DOM и новая библиотека тестирования не нужны. Browser assertions проверяют наблюдаемые размеры, семантику ожидания и фокус; визуальная приёмка оценивает композицию.

## Источники

Документация проверена 2026-10-01; используемые зависимости зафиксированы существующим `package.json`.

- [MDN: CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties) — наследование и fallback локальной темы.
- [MDN: role=status](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/status_role) — вежливое объявление динамического статуса без переноса фокуса.
- [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion) — отключение необязательного движения по системной настройке.
- [W3C: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) — требование 4.5:1 для обычного текста.
- [Playwright: Mock APIs](https://playwright.dev/docs/mock) — управляемый ответ нашего API в браузерном тесте.
