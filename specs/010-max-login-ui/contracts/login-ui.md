# Presentation Contract: D01 — экран входа

**Spec:** [spec.md](../spec.md).
**Область:** JSX/SCSS и доступность существующей формы. Новый HTTP-контракт не создаётся.

## Сохраняемый интерфейс

- Маршрут `/login`, два поля, подписи, глаз и коды ошибок сохраняются. Под формой одна акцентная ссылка на кабинет с `target=_blank` и `rel=noopener noreferrer`; дополнительных строк помощи нет.
- `CredentialField` сохраняет controlled value, label/input, required, отсутствие `name`, `aria-invalid`, условный `aria-describedby` и live-region ошибки.
- `TokenVisibilityButton` сохраняет действие, доступное имя и управление клавиатурой.
- `SubmitButton` сохраняет `type=submit`, текущий `label`, размер по контейнеру и обычное поведение при отсутствии новых пропсов.
- `POST /api/auth/login`, `GetStateInstance`, cookie и серверная проверка `/` не изменяются. Клиентская форма открывает `/` через Next.js `router.replace` без загрузки нового документа. Действующие серверные [контракты входа](../../006-login-session/contracts/login-api.md) и [выхода](../../008-logout/contracts/logout.md) остаются основанием.

## `SubmitButton`

| Проп        | Тип/значение                              | Смысл                                         |
| ----------- | ----------------------------------------- | --------------------------------------------- |
| `label`     | Существующий `string`                     | Видимый текст и основное доступное имя кнопки |
| `isLoading` | Необязательный `boolean`, default `false` | Только индикатор и занятость кнопки           |

Нет внутреннего таймера, эффекта, обработчика отправки или отдельного состояния загрузки. Индикатор декоративный, `aria-hidden=true`; не добавляет текст к доступному имени. Без `isLoading` общий компонент не меняет оформление поиска. Disabled по-прежнему задаётся существующим fieldset формы.

## Статус запроса

- `LoginForm` передаёт `isSubmitting` кнопке.
- Постоянная область `role=status` находится вне disabled/busy fieldset, имеет визуально скрытый, но доступный текст существующей проверки во время ожидания.
- `aria-busy` применяется к кнопке и/или fieldset, не к предку live-region.
- При отсутствии ожидания live-region пуста, индикатор отсутствует. Новый текст успеха/выхода не добавляется.
- Фокус не переводится на индикатор или область статуса.

## Изолированное оформление

На оболочке страницы входа задаются следующие CSS custom properties. Их буквальные значения определены только SCSS-токенами; область действия — потомки оболочки.

| Свойство                  | Назначение                                                 | Значение вне оболочки                                          |
| ------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| `--ui-link-color`         | Ссылка на кабинет; светлый токен для контраста тёмной темы | Существующий interactive токен                                 |
| `--ui-action-color`       | Кнопка, глаз, hover поля                                   | Существующий interactive/brand токен соответствующего элемента |
| `--ui-action-hover-color` | Наведение на действие                                      | Существующий hover-токен                                       |
| `--ui-focus-color`        | Обычный фокус                                              | Существующий focus-токен                                       |
| `--ui-field-border-color` | Спокойная рамка поля                                       | Существующий control-border                                    |
| `--ui-text-color`         | Текст интерфейса                                           | Существующий основной цвет                                     |
| `--ui-muted-color`        | Подсказки интерфейса                                       | Существующий второстепенный цвет                               |
| `--ui-focus-shadow`       | Мягкая подсветка поля                                      | Существующая focus-shadow                                      |

Дополнительные тематические переменные оболочки: `--ui-canvas-color`, `--ui-surface-color`, `--ui-on-action-color`, `--ui-error-color`, `--ui-error-shadow`, `--ui-panel-border-color`, `--ui-panel-shadow`. Они определяются SCSS-токенами; общие компоненты используют прежние значения как fallback. `prefers-color-scheme: dark` меняет переменные, `color-scheme: light dark` и палитра задаются один раз на `:root` общим миксином `system-theme`. Ручного управления, React-state или хранения темы нет. Введённые значения сохраняются при смене темы.

В тёмной теме текст акцентной кнопки тёмный для контраста не ниже 4.5:1. Общий миксин `focus-ring` принимает необязательный цвет и по умолчанию использует тематический `--ui-focus-color`. Проверяется сохранение общей темы при переходах `/login` → `/` → `/login`.

Ошибка поля — текст 12 px с отступом 6 px; постоянный live-region заранее занимает одну строку 18 px и отступ 6 px, поэтому появление и исправление однострочной ошибки не меняют высоту карточки. Поле имеет тонкую красную границу и мягкую красную подсветку только при фокусе. В forced-colors остаётся видимый системный outline. Spinner не вращается при reduced motion. На 320 px нет горизонтального переполнения; глаз и кнопка не меньше 44×44 px, поле использует текст не меньше 16 px на телефоне.

## Обратная совместимость

`RecipientSearchForm` и `RecipientSearchField` наследуют общую палитру; их поведение сохраняется. Согласованный клиентский выход обновляет только `LogoutButton`: fetch существующего POST, локальное ожидание/ошибка, переход без перезагрузки и обновление маршрутизатора. Серверный API выхода остаётся 303 и удалением cookie; нативная POST-форма сохранена без JavaScript. Поскольку кнопка и partial-файлы общие, итоговая регрессия проверяет поиск и выход, а код-ревью проверяет сохранение fallback/default значений. Общий фон документа следует теме устройства на обеих страницах; отдельного декоративного слоя входа нет.
