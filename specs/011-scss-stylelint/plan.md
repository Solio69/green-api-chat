**Spec**: [spec.md](spec.md)
**Дата**: 2026-10-01

## Summary

Подключить установленный пользователем Stylelint через стандартную SCSS-конфигурацию, добавить отдельный NPM Scripts для проверки всех исходных SCSS-файлов и адресно согласовать правила с БЭМ, токенами, миксинами и Prettier. Исправить только диагностированные стилевые нарушения без изменения интерфейса.

## Considered Options

| Вариант                            | Преимущества                                        | Ограничения и риски                                        | Выбор     |
| ---------------------------------- | --------------------------------------------------- | ---------------------------------------------------------- | --------- |
| Standard SCSS + адресные настройки | Проверяет синтаксис и единообразие; готовые правила | Нужна точная адаптация camelCase БЭМ и действующих токенов | Выбран    |
| Recommended SCSS                   | Быстрый запуск с меньшим числом замечаний           | Меньше проверок оформления                                 | Не выбран |
| Собственные правила или скрипт     | Можно формализовать любую местную норму             | Поддержка и ложные срабатывания; вне согласованного объёма | Исключён  |

## Technical Context

Проект: Next.js, TypeScript, Sass/SCSS Modules, Node.js 24. Пользователь уже установила `stylelint@17.14.1` и `stylelint-config-standard-scss@17.0.0`; прямые зависимости записаны в `package.json` и `package-lock.json`. Prettier остаётся форматтером. Проверка Stylelint только читает файлы; `--fix` в NPM Scripts не используется. Пробная read-only проверка стандартным конфигом нашла 29 диагностик в 11 исходных SCSS-файлах; это исходный baseline, не подтверждение результата.

## Research and Design

- [research.md](research.md) фиксирует исходные факты, альтернативы и ссылки на официальную документацию.
- [quickstart.md](quickstart.md) задаёт запуск и контрольные проверки.
- `data-model.md` и `contracts/` не применяются: данные, API и серверные контракты не меняются.
- Основное правило `selector-class-pattern` отключается для SCSS-вложенности; подключённое через готовый конфиг правило `scss/selector-class-pattern` проверяет развёрнутые БЭМ-селекторы с проектным camelCase. Шаблон проверяется на положительном и отрицательном примерах.
- Запись цветовых токенов приводится к современному синтаксису с сохранением значений. Системное имя `BlinkMacSystemFont` исключается из `value-keyword-case` точечно.
- `scss/dollar-variable-empty-line-before` отключается для смысловых групп токенов. Явное сравнение optional-параметра с null в миксине сохраняется с локальным пояснением и адресным исключением, если соответствующее правило по-прежнему диагностирует этот участок.

## Project Structure

| Путь                                       | Действие и причина                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `stylelint.config.mjs`                     | Новый конфиг стандартного SCSS-набора с объяснёнными исключениями.                                                 |
| `package.json`                             | Добавить `lint:styles` через Stylelint CLI; сохранить установленные пользователем зависимости и остальные скрипты. |
| `src/styles/_tokens.scss`                  | Привести диагностированные записи к правилам без изменения значений и групп токенов.                               |
| `src/styles/_mixins.scss`                  | Сохранить семантику optional-параметра, адресно объяснить возможное исключение.                                    |
| `src/**/*.scss`                            | Только файлы, реально диагностированные после уточнения конфигурации; не массовый рефакторинг.                     |
| `README.md`                                | Краткая команда проверки стилей рядом с остальными проверками.                                                     |
| `specs/011-scss-stylelint/verification.md` | Результаты проверок, ревью и ограничения после реализации.                                                         |

`package-lock.json` уже изменён пользовательской установкой; агент его не переписывает. Действующие пользовательские и соседние изменения в перечисленных файлах сохраняются.

## Tasks and Dependencies

1. Зафиксировать исходный diff и список SCSS-файлов; не перезаписывать чужие изменения.
2. Настроить `stylelint.config.mjs` и `lint:styles`; проверить корректный и некорректный SCSS через stdin и реальное покрытие glob.
3. Адресно исправить SCSS-диагностики, сохранив значения токенов и поведение миксинов; повторить Stylelint и Prettier.
4. Документировать команду; выполнить `npm run lint:styles`, `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm run build` и подходящие UI-проверки согласно текущему состоянию проекта.
5. Сверить diff и спецификацию, выполнить предкоммитное ревью, сохранить `verification.md`.

Новая/изменяемая бизнес-логика и серверные контракты отсутствуют, поэтому искусственный TDD Red не создаётся. Если при реализации обнаружится необходимость менять поведение, работа останавливается для нового согласования и соответствующих тестов.

## Verification

- Контрольный правильный SCSS с `@use`, Sass-переменной и вложенным БЭМ-селектором получает exit code 0.
- Контрольный ошибочный SCSS получает ненулевой exit code, путь и позицию.
- Glob `src/**/*.scss` содержит все реальные SCSS-исходники, включая partial-файлы; пустой набор — Failed.
- Stylelint и Prettier проходят на одних файлах без циклических автоисправлений. Проверка `lint:styles` не меняет рабочее дерево.
- Сборка, существующие подходящие проверки UI и ревью diff подтверждают сохранение поведения. Недоступная проверка отмечается Blocked/NotRun, не Passed.
- Команды, результаты, изменения и риск записываются в `verification.md`.
