# Tasks: Stylelint для SCSS

**Input**: [spec.md](spec.md), [plan.md](plan.md), [research.md](research.md), [quickstart.md](quickstart.md)
**Статус**: реализация выполнена; проверки записаны в verification.md.
Пути относительны корню проекта. Работа последовательная.

## Phase 1 — контроль исходного состояния

Цель: не повредить пользовательские и соседние изменения, сохранить измеримую базу.

- [x] T001 [US2] Снять `git status --short` и diff только затрагиваемых файлов, перечислить исходные `src/**/*.scss`, подтвердить установленные пользователем версии в `package.json`/`package-lock.json`; зафиксировать baseline без изменения Git index.

## Phase 2 — проверяемая конфигурация

Цель: готовый Stylelint читает SCSS и различает корректный/некорректный пример.

- [x] T002 [US1] Создать `stylelint.config.mjs` на основе `stylelint-config-standard-scss`; подключить `scss/selector-class-pattern` с разворачиванием вложенности, настроить проектный camelCase БЭМ и адресные исключения из `research.md`, объяснить их рядом с правилами.
- [x] T003 [US1] В `package.json` добавить `lint:styles` с CLI-glob `src/**/*.scss` без `--fix`; не менять прочие скрипты и пользовательский lock-файл.
- [x] T004 [US1] Подать корректный SCSS через stdin командой `node ./node_modules/stylelint/bin/stylelint.mjs --stdin --stdin-filename src/styles/control.scss` с вложенным БЭМ-селектором, Sass-переменной и `@use`; подтвердить exit 0. Подать синтаксически неверный SCSS тем же способом; подтвердить ненулевой exit, путь и позицию. Запустить `npm run lint:styles` и подтвердить, что glob охватил все реальные SCSS-файлы. Контрольные примеры не добавлять в продуктовые файлы.

## Phase 3 — приведение существующих стилей

Цель: SCSS проходит проверку без изменения визуального поведения.

- [x] T005 [US2] Исправить только оставшиеся Stylelint-диагностики в `src/styles/_tokens.scss`, `src/styles/_mixins.scss` и других реально диагностированных `src/**/*.scss`; сохранить точные значения цветов, имена семантических токенов, контракт миксинов и пользовательские правки. Локальное исключение для явной проверки null снабдить причиной.
- [x] T006 [US2] Запустить `npm run lint:styles` и `npm run format:check`; проверить, что повторный запуск и проверка без `--fix` не меняют SCSS. Просмотреть diff значений CSS и при необходимости сопоставить сборку/скриншот UI с исходным видом.

## Phase 4 — документация и итог

Цель: команда видна разработчику, результат проверен и готов к пользовательскому коммиту.

- [x] T007 [US1] Обновить `README.md` действующей командой `npm run lint:styles` и границами Stylelint; согласовать её с [quickstart.md](quickstart.md).
- [x] T008 [US1] [US2] Одним итоговым проходом выполнить `npm run lint:styles`, `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm run build` и подходящие существующие UI-тесты. Провести предкоммитное ревью, сверить FR/SC, сохранить команды, статусы и ограничения в `specs/011-scss-stylelint/verification.md`; дать пользователю следующие шаги и английское название коммита без создания коммита.

## Dependencies & Execution Order

T001 → T002 → T003 → T004 → T005 → T006 → T007 → T008. Ошибка установки или окружения в T004/T008 — Blocked, не подтверждение успешного обнаружения нарушения. Задача затрагивает конфигурацию и стиль; бизнес-логика/API не меняются, искусственный TDD Red не нужен. Если потребуется поведенческое изменение, остановить работу для согласования и плана тестов.

## Completion

Готовность означает прохождение положительной/отрицательной проверки, полного SCSS-glob, Prettier и подходящих проектных проверок, соответствие спеке, ревью diff и заполненный `verification.md`. Реальные результаты отделяются от Blocked/NotRun. Агент сообщает дальнейшие действия и английское название коммита; коммит делает пользователь.

## Operator-only actions

Stylelint уже установлен пользователем. Новых установок, миграций и операций БД нет. Git index, коммит, push и публикация агентом не выполняются; действует `GIT_POLICY.md`.
