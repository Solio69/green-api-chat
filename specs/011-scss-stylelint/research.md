# Исследование: Stylelint для SCSS

**Дата**: 2026-10-01
**Spec**: [spec.md](spec.md)

## Факты

- Пользователь установила stylelint 17.14.1 и stylelint-config-standard-scss 17.0.0. Команда npm ls подтвердила обе прямые зависимости; их peer-требования допускают Node.js 24 проекта.
- [Руководство Stylelint](https://stylelint.io/user-guide/get-started/) рекомендует готовый standard-scss для SCSS: он подключает синтаксис и плагин SCSS без отдельных прямых зависимостей.
- Пробный read-only запуск на всех 11 исходных SCSS-файлах со стандартной конфигурацией завершился 29 диагностическими ошибками. Шесть затрагивают корневые camelCase-классы БЭМ; остальные относятся к записи цветов, группировке токенов, имени системного шрифта и явной проверке null в миксине. Это исходное наблюдение, не итоговая проверка.
- [Миграция Stylelint 17](https://stylelint.io/migration-guide/to-17/) объясняет, что основной selector-class-pattern не разворачивает SCSS-вложенность. В уже подключённом SCSS-плагине есть scss/selector-class-pattern с resolveNestedSelectors.
- [Правило selector-class-pattern](https://stylelint.io/user-guide/rules/selector-class-pattern/) принимает строковый regex; [value-keyword-case](https://stylelint.io/user-guide/rules/value-keyword-case/) позволяет адресно исключить написание системного шрифта.
- [CLI Stylelint](https://stylelint.io/user-guide/cli/) принимает glob в кавычках, stdin для контрольных примеров и сообщает ошибку при пустом glob без allow-empty-input.

## Варианты

| Вариант | Плюсы | Риски и цена | Решение |
| --- | --- | --- | --- |
| Готовый standard-scss с адресной адаптацией | Широкая стандартная проверка, без собственного кода; диагностирует новые ошибки | Нужны конкретные исключения под camelCase БЭМ и текущую организацию токенов | Выбран |
| Только recommended-scss | Меньше начальных замечаний | Не проверяет часть оформления и согласованности CSS | Не выбран |
| Собственный валидатор или собственные правила | Можно закодировать любые местные предпочтения | Поддержка, тесты и ложные срабатывания; противоречит согласованной границе | Исключён |

## Технический выбор

- Конфигурация расширяет standard-scss. Вместо ожидания kebab-case включается готовое правило scss/selector-class-pattern с разворачиванием вложенных БЭМ-селекторов и шаблоном под согласованный camelCase. Основное одноимённое правило отключается, чтобы две проверки не спорили.
- Цветовые токены приводятся к допустимой современной записи с теми же компонентами и альфой; Sass-сборка и визуальная проверка подтверждают результат. Системное имя BlinkMacSystemFont сохраняется адресным исключением value-keyword-case.
- Пустые строки между смысловыми группами токенов сохраняются; правило scss/dollar-variable-empty-line-before адресно отключается как несовместимое с согласованной группировкой. Остальные проверки стандартного набора остаются.
- Явная проверка optional-параметра на null в миксине сохраняет различие между null и иными ложными значениями. Для одного места допускается локальное объяснённое исключение scss/at-if-no-null вместо изменения контракта миксина.
- Prettier остаётся форматтером; Stylelint не получает отдельного форматирующего плагина. Команда проверки не использует --fix, чтобы запуск из NPM Scripts не изменял файлы.
- Положительный и отрицательный примеры подаются через stdin, без сохранённого тестового скрипта. Итоговые проверки проводятся после серии правок.

## Неприменимые артефакты

Новой модели данных, HTTP-контракта и внешнего сервиса нет; data-model.md и contracts/ не создаются.
