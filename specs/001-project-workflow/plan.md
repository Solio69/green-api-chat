## Начальная подготовка E02.1

1. Прочитать source skills и шаблоны; не переносить рабочие scripts до разрешения.
2. Выполнить source prerequisite в read-only режиме с абсолютным путём этой feature.
   Вызов PathsOnly уже подтвердил FEATURE_DIR нового проекта.
   REPO_ROOT в его ответе остаётся корнем источника и не используется для выбора
   конституции и проектных документов.
3. Пройти clarify: вопросов, требующих нового решения пользователя, нет.
4. Подготовить документы напрямую по шаблонам, не вызывая перезаписывающий
   source setup-plan. Изменения ограничены этой feature и обзором проекта.
5. Перед генерацией tasks выполнить проверенный read-only source setup-tasks
   с тем же абсолютным каталогом; удостовериться в FEATURE_DIR.
6. После готового tasks.md выполнить source prerequisite RequireTasks/IncludeTasks,
   затем bootstrap-проход процедуры speckit-analyze с явными путями этой feature
   и контрактом project-rules.md вместо чужой constitution.
7. Снимки файлов до и после анализа должны совпасть. Исправления технических
   замечаний допустимы только после окончания прохода; затем анализ повторяется.
8. Предъявить полный отчёт и получить разрешение на реализацию.
9. После реализации повторить этап локальным skill, prerequisite и constitution
   как приёмку уже собственного комплекта.

Такой порядок предусмотрен разделом Assumptions and Dependencies согласованной
spec.md. Bootstrap-проход не выдаётся за полностью штатный запуск ещё
не существующего локального комплекта.

## Правила адаптации

- Сохранить основные этапы и metadata происхождения skills; не обещать поддержку
  необработанных slash-команд. Фактическое обнаружение локальных skills проверяется
  отдельно; при недоступности интерфейса инструкция читается из известного пути.
- Убрать executable hooks и действия публикации. Доступные этапы именуются
  единообразно; их CLI-вызовы соответствуют contracts/tooling.md.
- Заменить самостоятельный mkdir/copy внутри specify на setup-spec с сохранением
  существующего файла. Он новый и учитывается в отчёте как новая утилита.
- Plan skill не вызывает отсутствующий agent-context script и не меняет общий
  AGENTS.md ради ссылки на план.
- Checklist требований работает при наличии одной spec.md; отсутствие plan.md
  в этой фазе допустимо.
- Constitution skill проверяет реальные .agents/skills, а не отсутствующие
  templates/commands; не ведёт встроенную историю было/стало.
- Implement skill различает чек-листы готовности и будущие проверки приёмки;
  не требует завершить тестирование реализации до начала её написания.
  Шаблонные ignore-файлы не создаются без фактической необходимости и связи
  с согласованной задачей.
- Общие templates не выбирают архитектуру приложения и не требуют неприменимых
  UI/БД-проверок. Достаточность артефактов объясняется в отчёте.
- Политика Git сохраняется, включая staging только по прямой просьбе.

## Проверка и ограничения

- V01–V12: контрактные тесты на временной копии, включая повторные запуски
  и ошибки пути.
- V13–V18: целостность комплекта, правила, реальный read-only анализ,
  политика Git, происхождение и отсутствие реквизитов.
- Reparse-point проверка требует возможности создать такую фикстуру:
  если она недоступна, сценарий отмечается Blocked и полный успех не заявляется.
- Ошибки произвольной конкурирующей программы и полноценная файловая транзакция
  не моделируются; локальный процесс предполагает одного писателя.
- Работоспособность Next.js, Vercel и GREEN-API этой задачей не проверяется.
- Текст license берётся из проверенного официального источника как документ;
  пакеты и программное обеспечение не скачиваются.
