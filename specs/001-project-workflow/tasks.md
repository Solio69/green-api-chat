[data-model.md](data-model.md), [project-rules.md](contracts/project-rules.md),
[tooling.md](contracts/tooling.md), [quickstart.md](quickstart.md).

Все пути без префикса feature относительны корню проекта.

из specs/001-project-workflow/contracts/tooling.md.

документы. Для смысловых правил выполняется ревью по сценариям, а не тесты,
сравнивающие инструкцию с её копией. Установок и изменяющих Git-действий нет.

## Implementation Strategy

- Выполнить одну feature E02.1 после разрешения, проходя задачи по порядку
  и сообщая о результатах смысловых этапов.
- При продуктовой неоднозначности запросить решение до зависимой работы;
  технические исправления в пределах spec выполнять самостоятельно.
- После каждого существенного изменения запускать относящиеся к нему проверки.
  Не повторять неизменные успешные проверки без причины.
- У каждой проверки явно фиксировать Passed, Failed, Blocked или NotRun.
  Непроверенная возможность не считается выполненным критерием.
- Финальный отчёт не заменяет передачу пользовательских решений:
  реализация приложения Next.js потребует отдельной задачи и спецификации.

## Operator-only actions

Установки, миграции, изменения данных и Git с записью здесь не требуются.
Если фактическая среда выявит необходимость установки, агент сообщает причину
и точную команду пользователю; выполнение не включается в автоматический прогон.
