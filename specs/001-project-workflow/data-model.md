# Data Model: документы и состояния рабочего процесса

**Feature**: [spec.md](spec.md).
Модель описывает локальные артефакты E02.1. База данных не создаётся.

## ProjectRules

- Идентификаторы принципов C1–C8.
- Текст правила и локальный документ-источник.
- Ссылки между AGENTS.md, политикой Git, constitution и описанием процесса.
- Источник адаптации хранится как справочная информация.

Инвариант: несколько документов не дают разные разрешения на одно действие.

## FeatureContext

- PROJECT_ROOT: абсолютный корень расположения локального комплекта.
- SPECIFY_FEATURE_DIRECTORY: обязательный выбор текущей сессии.
- ExpectedFeatureDirectory: ожидаемый каталог, явно переданный вызову.
- FEATURE_DIR: проверенный абсолютный каталог одной feature.
- FEATURE_SPEC, IMPL_PLAN, TASKS: пути фиксированных документов этого каталога.

Нормализованный выбор из окружения должен совпадать с ожидаемым путём.
Каталог расположен непосредственно в specs/ проекта; имя соответствует
NNN-slug, где NNN — не менее трёх цифр, slug — строчные латинские слова и цифры,
разделённые дефисами. Корень проекта может содержать пробелы и кириллицу.
Общий активный указатель и автоматический выбор feature отсутствуют.

## Artifact

- Path: путь относительно проекта или каталога feature.
- Role: spec, research, plan, model, contract, quickstart, tasks или checklist.
- CreationResult: CREATED=true либо CREATED=false.
- Content: Markdown-текст; существующий файл не заменяется шаблоном.
- ApprovalState: информационная отметка согласования, когда она применима.

Если объект по ожидаемому пути является каталогом или ссылкой, создание
останавливается. Частичный результат сбоя указывается явно; автоматическая
очистка пользовательского содержимого не применяется.

## WorkflowDecision

- SpecificationApproval: Pending / Approved.
- PreparationState: NotPrepared / Preparing / NeedsRemediation / ReadyForReview.
- ImplementationAuthorization: Pending / Granted.
- ImplementationState: NotStarted / InProgress / Verification / Complete.

Согласование спеки переводит работу в Preparing, сохраняя разрешение
на реализацию Pending. Положительный анализ позволяет ReadyForReview,
но сам не переводит разрешение в Granted. Явное разрешение пользователя
позволяет InProgress. Изменение согласованного поведения требует повторного
решения по этому поведению.

Поля служат документацией текущего состояния; они не заменяют сообщения
пользователя и не являются исполняемым хранилищем авторизаций.

## AnalysisReport

- Scope: текущий каталог feature и версия подготовленных документов.
- Mode: bootstrap либо local.
- Findings: ID, категория, важность, расположение, описание и рекомендация.
- Coverage: FR/SC, связанные задачи и непокрытые требования.
- Metrics: количество требований и задач, покрытие, неоднозначности,
  дублирование и критические замечания.
- ReadOnlyEvidence: снимки списка файлов и хешей до и после анализа.
- Limitations: отсутствующие инструменты и непроведённые проверки.

Отчёт выдаётся в ответе агента. Во время анализа не создаётся analysis.md.
Если после анализа изменён технический документ, требуется новый проход.

## VerificationCase

- ID V01–V18, предусловия, ожидаемый результат и связанное требование.
- Result: NotRun / Passed / Failed / Blocked.
- Evidence: фактический вывод, сравнение файлов или результат смыслового ревью.

Чек-лист качества документов не равен результату выполнения этих сценариев.
