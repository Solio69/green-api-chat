## Смысловое ревью правил и процесса

| Ситуация                            | Результат применения инструкции                                                         |
| ----------------------------------- | --------------------------------------------------------------------------------------- |
| US1.1: новая сессия                 | AGENTS ведёт к локальным workflow, constitution и единой политике Git                   |
| US1.2: согласована только spec      | Разрешена подготовка, реализация ожидает отдельного решения                             |
| US1.3: требуется установка/БД       | Агент даёт объяснение и команды пользователю                                            |
| US1.4: просьба staging              | Только явно перечисленные пути, проверка diff до и после; без разрешения на коммит      |
| US1.5: существенная неоднозначность | Варианты и вопрос до зависимого решения                                                 |
| US2.1: подготовка spec              | Шаблон задаёт сценарии, FR/SC, границы и влияние на данные; readiness не требует plan   |
| US2.2: spec согласована             | clarify/plan/tasks выполняются без согласования каждого технического файла              |
| US2.3: меняется поведение           | Решение возвращается пользователю до зависимых правок                                   |
| US2.4: найдено замечание            | Сначала завершить read-only проход, затем исправить и повторить анализ                  |
| US2.5: документы готовы             | Каждый артефакт и contract перечисляется в отчёте, затем второе решение                 |
| US2.6: реализация завершена         | Соответствие спеке, проверки, ревью, ограничения, следующие действия и название коммита |

Контрольный пример V15: небольшая учебная задача «описать запуск существующей
команды в документации». Проверен маршрут от обсуждения до отчёта: неприменимые
модель данных/API объясняются, а не заполняются выдуманным содержимым; согласование
spec не разрешает реализацию. Для возврата ошибочного решения и завершения
использованы условия соответствующих сценариев US2. Это смысловой разбор
инструкций, не независимый агентный эксперимент и не реализация новой задачи.

## Ограничения проверки

- Штатный внешний quick_validate.py из skill-creator: Blocked из-за отсутствующего
  PyYAML как в системном, так и в доступном bundled Python. Пакеты не устанавливались.
  Вместо него выполнены проверка фактически используемой простой структуры YAML
  frontmatter, имён, описаний и смысловое ревью восьми skills. Это не заявляется
  запуском исходного Python-валидатора. Runtime локального комплекта Python не требует.
- Автоматическое обнаружение skills интерфейсом и slash-команды: NotRun.
  Проверен документированный вариант прямого чтения инструкции и локального запуска.
- V05 использует junction как реальный reparse point. Создание отдельной файловой
  symlink не выполнялось; общий запрет основан на атрибуте ReparsePoint.
- Защита рассчитана на одного локального писателя; атаки конкурирующего процесса,
  произвольные сбои диска и транзакционная запись всей группы файлов не моделируются.
- Поддержка PowerShell 5.1 и других ОС не заявляется.
- Метаданные источника и SHA-256 записаны; точное совпадение с upstream-тегом
  не подтверждено. [Происхождение](../../docs/spec-kit-provenance.md).
- Приложение, Vercel и интеграция с GREEN-API не входят в приёмку E02.1.
