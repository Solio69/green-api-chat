# Contract: локальные инструменты Spec Kit

**Feature**: [spec.md](../spec.md).
**Среда**: Windows, PowerShell 7, встроенные средства .NET.
Контракт описывает локальный комплект GREEN-API Chat. Скрипты проекта-источника
не являются его рабочими зависимостями.

## Контекст каждого вызова

Обязательны SPECIFY_FEATURE_DIRECTORY в окружении процесса и параметр
ExpectedFeatureDirectory — ожидаемый абсолютный путь текущего этапа.
Имя системной переменной SPECIFY_FEATURE_DIRECTORY сохраняется для совместимости
процесса; пользовательские переменные скриптов не переопределяют HOME/CODEX_HOME.

Корень проекта вычисляется от размещения .specify/scripts/powershell/common.ps1.
Перед чтением документов или созданием каталогов выполняется общий контроль:

1. Корень содержит локальный .specify; рабочий каталог — корень или его подкаталог.
2. Выбор из окружения нормализуется относительно корня, если он относительный.
3. ExpectedFeatureDirectory нормализуется; он должен быть абсолютным.
4. Оба пути совпадают с учётом правил Windows и обозначают прямой дочерний каталог
   specs/ с именем NNN-slug по data-model.md.
5. Корень и существующие компоненты пути от него до целевого артефакта не являются
   reparse points. Выход через .., сходный префикс соседнего проекта, junction,
   symlink и несовпадение выбранной задачи приводят к отказу.
6. Все вычисленные пути файлов снова проходят проверку границ.
   Проверка безопасности действует и в PathsOnly.

Отказ происходит до чтения содержимого неверно выбранной задачи.
Help выводится без обязательного контекста и ничего не меняет.
Проверки файловой системы рассчитаны на один локальный процесс записи;
межпроцессная блокировка всех редакторов не является свойством комплекта.

## Общий результат

- Успех: exit 0; с Json в stdout находится один JSON-объект.
- Ошибка: ненулевой exit, понятное сообщение в stderr с названием проблемы;
  stdout не содержит успешного результата.
- FEATURE_DIR и все пути файлов в JSON абсолютные.
- Список AVAILABLE_DOCS содержит только имена внутри выбранной feature.
- Вывод не содержит токены, содержимое пользовательской переписки
  или необязательный список других проектов.
- BRANCH, автоматический поиск последней feature, сетевые обращения,
  вызовы менеджеров пакетов и любые вызовы Git отсутствуют.

## common.ps1

Библиотека определения контекста, проверки путей, проверки необходимых файлов
и создания отсутствующего документа. Импорт библиотеки сам по себе не меняет
файлы. Корень и пути не берутся из Git, глобального feature.json или source-проекта.
Общие функции не выбирают и не запускают расширения.

## check-prerequisites.ps1

**Параметры**: ExpectedFeatureDirectory, Json, PathsOnly, RequireSpec,
RequireTasks, IncludeTasks, Help.

- PathsOnly: проверка контекста и возврат путей; spec/plan/tasks могут отсутствовать.
- RequireSpec: после проверки контекста требуется существующий обычный spec.md;
  plan.md не требуется.
- Без PathsOnly, RequireSpec и RequireTasks: требуются spec.md и plan.md.
- RequireTasks: требуются spec.md, plan.md и tasks.md.
- PathsOnly, RequireSpec и RequireTasks — взаимоисключающие режимы.
- IncludeTasks вне PathsOnly добавляет tasks.md в AVAILABLE_DOCS при наличии;
  не меняет обязательность документов. В PathsOnly этот флаг игнорируется:
  AVAILABLE_DOCS остаётся пустым.
- Проверка полностью read-only, включая состояние без spec.md.

Объект результата: PROJECT_ROOT, FEATURE_DIR, FEATURE_SPEC, IMPL_PLAN, TASKS,
AVAILABLE_DOCS. В режиме PathsOnly список AVAILABLE_DOCS пуст:
перечисление содержимого задачи этому режиму не нужно.

## setup-spec.ps1

**Новый файл**, а не существующий скрипт источника.
Параметры: ExpectedFeatureDirectory, Json, Help.

После проверки контекста:
- существующий обычный spec.md сохраняется побайтно;
- если spec.md отсутствует, сначала проверяется локальный spec-template.md,
  затем создаётся каталог выбранной feature и документ;
- создание документа использует CreateNew, без Force и перезаписи;
- отсутствие шаблона — ошибка без создания пустой спеки или каталога feature.

Результат: PROJECT_ROOT, FEATURE_DIR, FEATURE_SPEC, CREATED.
CREATED=false означает, что существующий документ сохранён; это не утверждение
о качестве его содержимого.

## setup-plan.ps1

Параметры: ExpectedFeatureDirectory, Json, Help.
Требует существующий spec.md. Создаёт только отсутствующий plan.md из локального
plan-template.md. Правила шаблона, CreateNew и сохранения существующего файла
аналогичны setup-spec.

Результат: PROJECT_ROOT, FEATURE_DIR, FEATURE_SPEC, IMPL_PLAN, CREATED.

## setup-tasks.ps1

Параметры: ExpectedFeatureDirectory, Json, Help.
Требует spec.md и plan.md, проверяет локальный tasks-template.md.
Работает read-only и не создаёт/не сбрасывает tasks.md.

Результат: PROJECT_ROOT, FEATURE_DIR, TASKS, TASKS_TEMPLATE, AVAILABLE_DOCS.
После него skill готовит задачи намеренным редактированием своего документа,
учитывая уже выполненные пункты, если документ существует.

## Создание и ошибки записи

Проверка существования не заменяет CreateNew: если другой процесс успел создать
документ, утилита сообщает конфликт и не заменяет файл.
При ошибке записи возвращается ошибка с путём; возможный частичный новый файл
перечисляется явно. Утилита не удаляет пользовательские файлы и не делает
автоматический откат Git. После такого сбоя агент сначала проверяет фактическое
состояние и только затем продолжает работу.

Обновление содержимого spec/plan/tasks остаётся осознанным действием агента
в рамках выбранной задачи, а не побочным эффектом подготовки шаблона.

## Соответствие этапам

| Skill | Подготовка | Минимальные документы |
| --- | --- | --- |
| speckit-constitution | check-prerequisites -PathsOnly | Локальные правила и согласованные принципы |
| speckit-specify | check-prerequisites -PathsOnly; setup-spec | Согласованное описание задачи |
| speckit-clarify | check-prerequisites -RequireSpec | spec.md |
| speckit-plan | check-prerequisites -RequireSpec; setup-plan | Согласованный spec.md и constitution |
| speckit-tasks | check-prerequisites; setup-tasks | spec.md, plan.md и доступные документы проекта решения |
| speckit-checklist | check-prerequisites -RequireSpec | spec.md; план читается только при необходимости |
| speckit-analyze | check-prerequisites -RequireTasks -IncludeTasks | spec.md, plan.md, tasks.md, constitution |
| speckit-implement | check-prerequisites -RequireTasks -IncludeTasks | Подготовленный комплект, анализ и разрешение пользователя |

Все вызовы передают ExpectedFeatureDirectory и проверяют FEATURE_DIR в ответе.
Skills не выводят разрешение из наличия документов или кода выхода 0.

## Приёмка

Проверки V01–V13 в quickstart.md проверяют наблюдаемое поведение scripts.
V14–V18 проверяют инструкции, ограничения, происхождение и локальный процесс.
Контракт не требует записывать тестовые spec/plan в каталог рабочей feature:
для автоматических проверок создаются отдельные временные примеры.
