# Исследование: исходное покрытие рефакторинга

Дата: 2026-10-03. Задача: [028](spec.md). Это исследование для подготовки; результаты запусков будут в [baseline.md](baseline.md).

## Факты проекта

- Приложение: Next.js 16.3.7, React 19.3.0, TypeScript 5.9.3, TanStack Query 5.104.0, iron-session 9.0.1. Node 24.14.1, npm 11.11.0.
- Три набора Playwright 1.63.0: `tests/integration`, `tests/query`, `tests/e2e`. Отдельный PowerShell-набор `tests/spec-kit/workflow.tests.ps1` проверяет локальный процесс, а не приложение.
- Integration работает без webServer. Query запускает отдельное Next.js-приложение через build/start, E2E — production-сборку основного приложения с fake GREEN-API.
- В конфигурациях query/E2E по одному worker, retries=0, reuseExistingServer=false. Наборы выполняются последовательно: их отчёты и сборка могут пересекаться.
- `tests/query/chat-query.spec.ts` называет один сценарий StrictMode replay, но `playwright.query.config.ts` запускает production. Такой запуск проверяет сохранение клиента и rerender, но не development replay.

## Подтверждённые внешние сведения

- React выполняет дополнительный цикл эффектов StrictMode только в development; важна также корневая область StrictMode. Поэтому production-тесту нельзя приписывать доказательство replay. [React StrictMode](https://react.dev/reference/react/StrictMode), проверено 2026-10-03.
- Playwright CLI поддерживает list и JSON reporter; список не является выполнением тестов. [Playwright CLI](https://playwright.dev/docs/test-cli), проверено 2026-10-03.
- Next.js описывает Vitest для unit/component проверок; async Server Components требуют другого уровня, например E2E. Это ориентир целевой классификации, установка относится к 029. [Next.js testing with Vitest](https://nextjs.org/docs/app/guides/testing/vitest), проверено 2026-10-03.

## Решения и ограничения

Новая бизнес-логика, тестовый runner и изменение существующих тестов не входят в 028. Обнаруженный продуктовый дефект регистрируется, без исправления в baseline. Установки не нужны: используются имеющиеся зависимости; отсутствие браузера фиксируется как Blocked и не обходится скрытой установкой.

Пользователь прямо разрешил этому чату полный цикл первой выбранной задачи и локальный commit в текущую ветку `refactor` после анализа и ревью. Это исключение из обычных согласований и запрета commit; push не запрошен. Общие AGENTS и GIT_POLICY не изменяются.
