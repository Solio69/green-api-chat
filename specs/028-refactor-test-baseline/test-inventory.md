## Классификация и перенос

Unit означает отдельное правило или адаптер с контролируемой границей; integration — взаимодействие настоящих модулей, QueryClient, session или Request/Response. Название текущего каталога integration не определяет будущий уровень. React SSR renderToString остаётся Node-проверкой и не доказывает работу эффектов. Асинхронные Server Components и настоящий Next.js runtime проверяются через production HTTP/browser.

До эквивалентного результата в новом окружении текущая проверка сохраняется. ID фиксируются этим baseline; при переносе сохраняется связь с тем же ID, даже если меняются title/file/line или один тест делится на несколько. Нельзя заново перенумеровать реестр и считать это доказательством сохранения покрытия. Сценарии geometry, focus, scroll, Web Locks, browser visibility и pre-hydration остаются браузерными.

## Особые случаи

- 029 переносит два сценария recipient-label как пилот; один простой компонент для пилота выбирается в техническом плане 029, без удаления браузерного контракта геометрии.
- 030 добавляет настоящее development replay. Существующий production StrictMode-сценарий сохраняет полезную проверку rerender и требует корректного названия.
- Query-файлы со смешанными целями разделяются по scenario ID в JSON. Для безопасного текста и отсутствия scroll-fetch в одном сценарии сохраняется браузерная проверка, поскольку он одновременно проверяет браузерное взаимодействие.
- В login-form два простых сценария можно перенести в RTL; сквозной вход, реальные cookie, клавиатурный фокус и защита до гидратации остаются в Playwright.
- Дедупликация, late response и ACK намеренно проверяются на нескольких уровнях. Совпадение темы не является основанием удалить сквозное доказательство соединения слоёв.
- PowerShell-набор относится к инструментам разработки и не увеличивает число продуктовых сценариев. Его V01–V12 сохраняются отдельными ID.
