# Модель реестра проверок

Это модель документов задачи 028, а не новая модель данных приложения. БД и runtime API не создаются.

## TestFile

- `file`: путь от корня репозитория, уникален.
- `suite`: integration, query, e2e или workflow.
- `purpose`: проверяемая ответственность.
- `currentEnvironment`: Node, production query-app, production app или PowerShell.
- `target`: unit, integration, component, browser/E2E либо workflow; смешанный файл может иметь несколько уровней.
- `migrationTask`: задача будущего переноса либо keep.
- `scenarioIds`: ссылки на все развёрнутые сценарии файла.

## Scenario

- `id`: устойчивый ID, присвоенный один раз в исходном реестре.
- `file`, `line`, `title`, `suite`, `project`: исходное местоположение и название из runner; line — свидетельство, а не идентификатор.
- `target`, `migrationTask`: целевое направление и владелец переноса. Классификация файла наследуется сценариями; исключения указываются индивидуально.
- `limitation`: конкретное ограничение доказательства, если оно есть.

При переименовании, разделении или объединении тестов сохраняется отображение старого ID на новые проверки. Удаление записи без причины недопустимо. Один сквозной сценарий может подтверждать несколько гарантий; это не ошибка дублирования.

## Guarantee и Finding

В `coverage-matrix.md` гарантия G01–G08 содержит правило, scenario ID, уровень доказательства и ограничение. Пробел GAP-01 и далее содержит наблюдение, доказательство, влияние и следующую задачу. Статус пробела не смешивается с успешностью тестового прогона.

## Run

В `baseline.md`: command, start/end UTC, exit code, статус Passed/Failed/Blocked/NotRun, число passed/failed/skipped там, где применимо, режим и причина отклонения. Контекст включает HEAD, ветку, версии и отпечаток проверяемых исходников и конфигурации.

Failed означает выполненную неуспешную проверку. Blocked означает препятствие окружения, при котором целевое поведение не проверено. NotRun означает отсутствие запуска. Успех обнаружения тестов не является Passed их выполнения.

Секреты окружения, тела реальных сообщений и персональные реквизиты не входят ни в одну сущность. Используются проектные фиктивные данные.
