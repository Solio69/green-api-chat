# Contract 045: клиентские сценарии входа и выхода

1. `requestLogin({credentials, signal, fetcher?})` выполняет прежний POST `/api/auth/login` с JSON и no-store. HTTP 200 + `status:ok` — успех; известный `status:error`/code — прежняя полевая или общая ошибка; плохой JSON/неожиданный ответ — `INVALID_UPSTREAM_RESPONSE`; сетевой отказ — `SERVICE_UNAVAILABLE`. Адаптер не пишет реквизиты никуда и не возвращает их.
2. `features/auth/ui/LoginForm/useLoginForm` хранит только локальные значения и UI state, вызывает адаптер не более одного раза на активный submit, фокусирует первое пустое поле, позволяет исправить ошибку/повторить. Успех выполняет существующий `router.replace(HOME)`; после unmount старый ответ не вызывает setState/навигацию.
3. `LoginForm` сохраняет form без нативной сериализации реквизитов, `fieldset disabled` до гидратации, без `name` у credential inputs, тексты/aria/error IDs, `noscript`, external link и текущие SCSS классы. Toggle не отправляет форму, Enter отправляет её после гидратации.
4. `requestLogout` выполняет прежний POST `/api/auth/logout` с owned headers/no-store и возвращает успех или отказ. `features/auth/ui/LogoutButton/useLogout` блокирует повтор, на успех закрывает клиентский QuerySession и делает `router.replace(LOGIN)` + `router.refresh()`, на отказ показывает прежнюю ошибку. LogoutButton сохраняет нативный POST action/method и визуальный контракт.
5. Внешние API/cookie/параметры времени/тексты/маршруты не меняются. Все четыре auth UI-компонента размещаются в `features/auth/ui` и экспортируются наружу через public entry. Нового глобального store или библиотеки форм нет.
