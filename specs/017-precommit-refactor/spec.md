# Feature Specification: предкоммитная ревизия

**Feature Directory**: specs/017-precommit-refactor
**Created**: 2026-10-02
**Status**: Завершена; автоматические проверки и read-only анализ Passed
**User Approval / Implementation Authorization**: Прямое поручение пользователя 2026-10-02 привести все спеки и документы в порядок и провести рефакторинг всех текущих изменений. Повторный gate не нужен.

## Результат и границы

Одна техническая задача над текущим общим diff после завершения соседнего чата. Сохранить согласованное поведение, редизайн и пользовательский staging. Не подключать видимый список 015, историю, отправку или уведомления. Без новых зависимостей, Git mutations и обращений к реальному аккаунту.

## Требования

- **FR-001**: Проверить все текущие изменения кода, убрать повторный разбор неизвестного JSON и небезопасные приведения типов при сохранении API и поведения форм.
- **FR-002**: Проверить все каталоги 001–016 и общие документы: актуальные статусы, рабочие ссылки, соответствие реализации; отличать готовый слой 014 от незавершённого списка 015.
- **FR-003**: Сохранить ширину каркаса, стабильность формы поиска, темы, accessibility и авторизацию; не восстанавливать удалённый пользователем консольный потребитель.
- **FR-004**: Удалить случайный корневой файл null с выводом линтера только из рабочего дерева; сохранить индекс Git.
- **FR-005**: Выполнить существующую регрессию, статические проверки и read-only анализ; записать фактические результаты и ограничения.

## Приёмка

- **SC-001**: Те же сценарии API, нормализации и жизненного цикла Query проходят до и после рефакторинга; типы и линтеры не требуют as для разбора JSON в затронутых функциях.
- **SC-002**: README и спеки описывают профиль/каркас и текущую готовность списка; ссылки на существующие локальные артефакты разрешаются, опечатки UI-спеки исправлены.
- **SC-003**: Браузерная регрессия подтверждает внешний вид и сохранение состояния; реальные устройства и ручная приёмка отмечены отдельно.
- **SC-004**: Staged изменения сохраняются: исходные 196 путей, 9599 добавленных и 394 удалённых строк. Агент не выполняет staging или commit; служебный индекс не восстанавливается вручную. Изменение его метаданных при чтении Git отмечается отдельно. Никаких установок.

## Способ проверки

Чистый рефакторинг: использовать существующее покрытие, исходный успешный запуск 167 integration подтверждён до правок. Искусственный Red не требуется. После серии — integration, query browser, полный E2E, root и fixture TypeScript, ESLint, Stylelint, Prettier кода и Markdown, git diff --check и read-only анализ путей/SHA-256. Реальные данные не используются. Ошибка окружения не является Red.
