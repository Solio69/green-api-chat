# Contract: GET /api/chats

Статус: контракт реализован и проверен 2026-10-02. Связь: FR-001–FR-006, FR-011–FR-013.

## Запрос

GET /api/chats, same origin, cookie существующей сессии, fetch cache:no-store. Тело и query-параметры не используются. Заголовок X-Connection-Scope обязателен: 43 символа base64url. Значение передано серверной главной через провайдер; пользователь его не вводит. Заголовок не авторизует запрос.

Порядок: проверить серверную конфигурацию → открыть/проверить сессию → проверить форму scope → сравнить с вычисленным scope текущей сессии → вызвать GetChats с request.signal. Без сессии, при неправильном scope и конфигурации поставщик не вызывается. Несовпадение scope не удаляет cookie. Серверный runtime — Node.js, не Edge. Обработчик данных экспортируется для GET. Next.js автоматически использует его для HEAD (без тела ответа) и возвращает OPTIONS 204 с Allow: GET, HEAD, OPTIONS без вызова обработчика. POST/PUT/PATCH/DELETE получают стандартный 405 и не вызывают поставщика. Ответы автоматических методов не выдаются за JSON-контракт GET.

## Успех

HTTP 200, application/json, Cache-Control:no-store:

```json
{
  "status": "ok",
  "connectionScope": "<opaque-scope>",
  "chats": [
    {
      "chatId": "fictional-chat-id",
      "name": "Демо",
      "username": "@demo",
      "phone": null
    }
  ]
}
```

Нормализация — [data-model.md](../data-model.md). Пустой успех: chats:[]. Пример scope — обозначение, не валидное тестовое значение. Нет сырого ответа, секретов или полей сообщений. Клиент проверяет совпадение connectionScope с привязкой собственного запроса; чужой scope не кэшируется.

## Ошибка

application/json и Cache-Control:no-store для всех ответов нашего обработчика:

```json
{ "status": "error", "code": "session_required" }
```

| Ситуация                                                                                                               | HTTP / code                   | Cookie                                           | Повтор                               |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------ | ------------------------------------ |
| Нет SESSION_PASSWORD требуемого формата                                                                                | 503 server_unavailable        | Сохранить                                        | После исправления конфигурации       |
| Нет/повреждена/истекла сессия                                                                                          | 401 session_required          | Очистить существующий негодный cookie, если есть | Через вход                           |
| Scope отсутствует или неверного формата                                                                                | 400 invalid_request           | Сохранить                                        | Исправить клиентский запрос          |
| Scope не совпадает с текущим подключением                                                                              | 409 connection_changed        | Сохранить                                        | Новый серверный контекст             |
| Provider 401 invalid_token, 403 invalid_instance; однозначные needs_authorization/instance_restricted/instance_expired | 401 session_required          | Удалить через существующий clearSession          | Через вход                           |
| 400 с starting/неоднозначным состоянием                                                                                | 503 retry_later               | Сохранить                                        | Ручной                               |
| 429 после разрешённой второй попытки                                                                                   | 429 rate_limited              | Сохранить                                        | Ручной, без клиентской серии retries |
| Неверный JSON/DTO или неожиданный HTTP                                                                                 | 502 invalid_upstream_response | Сохранить                                        | Ручной                               |
| Provider 5xx, сеть, timeout, неожиданное исключение чтения                                                             | 503 service_unavailable       | Сохранить                                        | Ручной                               |

На ошибке удаления cookie нельзя сообщать, что серверное завершение подтверждено: 503 service_unavailable, клиент не принимает её за успешное завершение. Без сессии клиент всё равно закрывается по 401. Классификация provider 400 использует фактические classifyBadRequest/get-state и сохранённые критерии; непризнанная строка не является доказательством недействительности. GetChats не добавляет вызов состояния для уточнения.

## Адаптер поставщика

GET существующий фиксированный HOST /waInstance{encoded id}/getChats/{encoded token}, cache:no-store, redirect:error. Общий deadline 10000 мс покрывает чтение ответа и единственный retry 429 через 1100 мс. Если request.signal отменён, прекратить дальнейшие попытки; AbortSignal запроса объединяется с timeout. Аккаунт берётся только из серверного контекста. В публичные ошибки и логи не попадают URL, токен или raw body. Никаких изменений Telegram.

Сессия сверяется на начало запроса. Cookie браузера может смениться, пока старый серверный запрос выполняется: старый ответ остаётся привязан прежнему scope, а закрытый/новый клиент его отвергает. Без серверного реестра нельзя обещать глобальную мгновенную отмену уже начатых запросов всех вкладок.

## Обязательные проверки

Фиктивные mixed/empty/unknown/duplicate/malformed/secret payload; 401/403/400/429/5xx/timeout; 429→успех и 429→429 с ровно двумя попытками; неправильный scope и отсутствие сессии с нулём provider calls. Отмена до retry, на чтении тела; подтверждённая cookie очистка, временные ошибки без удаления. HTTP E2E проверяет cookie, no-store GET/HEAD, HEAD без тела, OPTIONS 204/Allow без provider calls, POST 405 без provider calls и отсутствие секретов. Внешний настоящий API не используется автоматическими тестами.
