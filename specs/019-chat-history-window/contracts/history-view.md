# Contract: отображение истории по существующему макету

**Feature**: 019. Источник выбора — [025](../../025-conversation-selection/contracts/conversation-selection.md), истории — [018](../../018-chat-history-console/contracts/history-query.md). Нет нового выбора, оформления списка/поиска, отправки, SSE или подгрузки.

## Компоновка

`src/app/page.tsx` передаёт conversation slot: `<ChatHistoryPanel />` в
ChatWorkspace 025. Provider остаётся в ChatWorkspace. ChatHistoryPanel напрямую использует useChatHistory018; отладочный вывод истории и ChatHistoryController удалены по ревью пользователя2026-10-02. Потребители используют один ключ scope/chat/accessId; Query дедуплицирует запрос, слияние идемпотентно. Мобильный возврат скрывает панель CSS, сохраняя подписки, target/accessId и данные. Header/back/close и фон принадлежат 025.
ChatHistoryPanel читает target, вызывает useChatHistory(target?.chatId ?? null)
и отображает merged data. Состояние не копируется в useState.

Пути и роли:

- `src/components/ChatHistoryPanel/ChatHistoryPanel.tsx`: состояния запроса, ручной повтор ошибки, MessageList; null target не выдаёт пустую переписку.
- `src/components/MessageList/MessageList.tsx`: список по ключу idMessage внутри выбранного scope/chatId. Единственный прокручиваемый контейнер тела переписки.
- `src/components/MessageBubble/MessageBubble.tsx`: направление, исходный текст или нейтральная строка, известное время. Props: `{message: MessageDTO, status?: ReactNode}`. Optional status slot по умолчанию пустой; 024 подключает свой indicator через MessageList после отдельной реализации.
- `src/components/ChatHistoryState/ChatHistoryState.tsx`: отдельное представление загрузки, пустой переписки и ошибки/повтора; бизнес-состояния определяет ChatHistoryPanel.
- index.ts, constants.ts и module.scss в папке каждого компонента: публичный export, подписи и существующие визуальные правила.

## Таблица состояний

| Известные сообщения     | Текущий запрос                          | Представление                                             |
| ----------------------- | --------------------------------------- | --------------------------------------------------------- |
| undefined               | pending                                 | Загрузка; никакой ложной пустоты                          |
| []                      | успешный текущий ответ                  | Пустая история по макету                                  |
| есть                    | новый запрос                            | Сохранённые сообщения и ненавязчивое состояние обновления |
| есть                    | error                                   | Сохранённые сообщения плюс сообщение ошибки/ручной повтор |
| undefined/[]            | error                                   | Ошибка с повтором; не успешная пустая история             |
| есть                    | успешный пустой свежие десять сообщений | Те же известные сообщения; [] snapshot их не стирает      |
| есть только unsupported | success                                 | Строки «Неподдерживаемое сообщение»; это не пустота       |

При merged [] и pending показывается загрузка, даже если прежний запрос когда-то
был пустым. Live message до конца первого запроса показывается со состоянием
загрузки; он не означает successful history response. isPending/isFetching
отражают только текущий accessId. Ручной повтор вызывает общий
refetch(), не создаёт отдельный fetch. A→B→A и close используют guards 018.
Мобильное «Чаты» скрывает панель, но сохраняет target/accessId/Query; повторное
открытие запрашивает свежие десять сообщений. Закрытие target очищает представление, а память
чата остаётся до close подключения. История не меняет mobilePanel сама.

## Текст, время и прокрутка

UI-012/UI-014/UI-016 из [макета](../../../docs/chat-ui-spec.md) остаются
основанием. React text nodes, без dangerouslySetInnerHTML/Markdown/parser;
переносы сохраняются, длинное слово и ссылка не расширяют колонку. Incoming и
outgoing имеют согласованное расположение. Время отображается из provider
timestamp (секунды), при null из acceptedAt с явной локальной семантикой;
если обоих нет, время не выдумывается. При одинаковом времени сортировка и
идентичность следуют message-cache, без схлопывания текста.

Начальное открытие заканчивается на последних известных сообщениях. После
асинхронного обновления не принуждаем читателя внизу, если он сам прокрутил
выше: позиция удерживается; когда он остаётся у низа, новое сообщение остаётся
видимым. Проверка границы низа определяется измерением контейнера и тестируется,
не задаёт новых сетевых запросов. Прокрутка вверх НИКОГДА не расширяет count и
не загружает ещё историю. Вложения не запрашиваются. Online/avatar/name и
галочки не придумываются. Composer и его draft/pending относятся к 021.

## Проверки

Desktop/mobile по макету; initial loading без ложной пустоты; ошибка с/без
кеша; count: 10 плюс >10 merged; HTML как текст; переносы/длинные слова;
unsupported без download; A→B→A/close/back; пользовательская позиция
прокрутки; после 024 status slot без изменения направления/текста.
Изолированная реализация и целевые проверки Passed; совместная интеграция статусов/отправки остаётся NotRunExternal. См. [verification](../verification.md).
