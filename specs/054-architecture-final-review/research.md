# Research 054

- [Карта 035](../035-feature-module-boundaries/ownership-map.csv) уже определила target 63 сохранившихся старых файлов. Шесть файлов появились после её фиксации и получили target по фактической роли. Исключение QueryProvider обосновано его импортом conversation session creation и навигацией; помещение такого компонента в shared сохранило бы инверсию.
- Официальные [Next.js Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components) и [Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) подтверждают: `app` сохраняет специальные имена `page`, `layout`, `route`; client boundary нельзя скрывать server exports в общем barrel. [React context](https://react.dev/reference/react/createContext) позволяет вынести нейтральный provider, оставив feature-specific создание сеанса в conversation UI.
- Установленный ESLint 9 flat config поддерживает file-scoped `no-restricted-imports`; существующий проект уже использует это правило для запрета `../` внутри src. Границы нужно проверять действующим ESLint на положительном и нарушающем импорте, а не лишь текстовым поиском.
- `server-only` package отсутствует в явных зависимостях; без новой установки не вводить импорт, который может не работать в Vitest/Node. Для server/client guard использовать существующие Next route boundaries и ESLint; проверить отсутствие runtime секретов в client graph отдельно.
- Два цикла статического графа: type-only `get-state↔transport` и `chats/server/index↔get-chats`. Несмотря на отсутствие runtime cycle, публичные входы скрывают нежелательное направление и должны быть устранены. Предварительный граф для 261 TS/TSX файлов: 741 связей; CSS не считается TypeScript import node.
- `notifications/model` импортирует тип credentials из server и чистый `isSafeIdentifier` из server/green-api. Оба контракта логически shared/pure, их перенос устраняет model→server без изменения поведения. `sending/model/editor-guards` импортирует PendingAttempt из application; этот type перемещается в model.
