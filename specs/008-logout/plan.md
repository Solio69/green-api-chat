**Разрешение на реализацию**: Пользователь разрешил писать код при положительном анализе полного комплекта: «потом если всё окей, пиши код».

## Summary

На защищённой главной появляется небольшая кнопка «Выйти» — и при JSON-ответе, и при временной ошибке GREEN-API. Клиентский `LogoutButton` отменяет нативную отправку после гидратации, отправляет fetch POST и выполняет `router.replace`/`router.refresh` при подтверждённом ответе. Ожидание блокирует повтор; сбой показывает ошибку и позволяет повторить. HTML action/method остаются fallback без JavaScript. Обработчик удаляет cookie сессии текущего браузера и возвращает 303 на `/login`. Дополнительный текст выхода не показывается. Серверного хранилища, новых пакетов и запросов к GREEN-API для выхода нет.

## Considered Options

| Вариант                                            | Преимущества                                                                      | Ограничения и риски                                   | Выбор и причина                     |
| -------------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------- |
| HTML-форма с POST Route Handler                    | Работает без JavaScript, выход только по действию пользователя, простая навигация | Полная загрузка без JavaScript                        | Fallback                            |
| Клиентский `fetch` существующего POST              | Переход без reload, ожидание и ошибка рядом с кнопкой                             | Небольшое локальное состояние и обработчик            | Выбран; серверный контракт сохранён |
| Отдельный `/api/auth/logout`                       | Отличает добровольный выход от существующей потери доступа                        | Один дополнительный маршрут                           | Выбран                              |
| Переиспользовать `GET /api/auth/end-session`       | Меньше файлов                                                                     | Открытие URL само завершает сессию; смешивает причины | Не выбран                           |
| Удалить cookie через `NextResponse.cookies.delete` | Совпадает с существующим рабочим способом, не читает секрет сессии                | Не отзывает чужие копии cookie                        | Выбран для текущего браузера        |
| Серверный список сессий                            | Глобальный отзыв                                                                  | Хранилище, миграции и новая инфраструктура            | Исключён пользователем              |

## Technical Context

- Next.js 16.3.7, React 19.3.0, TypeScript 5.9.3, SCSS Modules, установленный `iron-session@9.0.1`. Уже есть защищённая серверная `/`, `/login`, `GET /api/auth/end-session`, общие константы и Playwright.
- `POST /api/auth/logout` формирует относительный `Location` для того же домена браузера, статус 303, `Cache-Control: no-store`, удаление cookie с именем и путём существующей сессии. Нет тела запроса и вызова GREEN-API. GET у нового маршрута не реализуется.
- Для выхода не нужен параметр адреса или сообщение на `/login`; отдельный маркер `access_lost` и его сообщение для потери доступа сохраняются.
- На `/` небольшой компонент выхода показывается после определения действительной сессии в обоих результатах: `authorized` и временный `retry`. При `login` и `end-session` страница по-прежнему делает редирект до вывода защищённого содержимого.
- Никаких новых данных или схемы БД нет. Новые пакеты не нужны. Cookie и ранее скопированные копии имеют существующий абсолютный срок 24 часа; удаление в текущем браузере не отзывает копии.

## Tasks and Dependencies

1. Написать сохраняемый E2E-тест серверного контракта POST. Запустить только этот файл на текущем приложении; ожидаемый поведенческий Red — маршрут отсутствует и возвращает 404 вместо 303. Ошибка сборки или импорта Red не подтверждает.
2. После Red добавить константы и POST-обработчик; реализовать компонент и оба состояния `/`.
3. Один раз выполнить целевой Green и итоговый набор регрессии после всех правок. Проверить браузерный сценарий на фиктивной cookie и вручную с реальным инстансом без передачи реквизитов агенту.
4. Сохранить фактические статусы в `verification.md`, обновить обзор проекта и README, проверить соответствие спеке. После этого провести read-only анализ окончательного состояния и предкоммитное ревью.

## Verification

- Red: `npm run test:e2e -- tests/e2e/logout-flow.spec.ts`; тест должен дойти до POST и получить 404 вместо ожидаемого 303.
- Green и регрессия после завершения правок: тот же целевой тест, затем `npm run test:integration`, `npm run test:e2e`, `npm run typecheck`, `npm run lint`, `npm run format:check`, `git diff --check`. Целевой E2E не запускается параллельно с dev-сервером в этой папке.
- Контракт проверяет 303, `Location`, удаление cookie, `no-store`, повтор без cookie и отсутствие обработки GET; браузер проверяет обычную форму `/login` без сообщения о выходе и недоступность `/` после выхода. Кнопку в обоих состояниях `/` пользователь проверяет с действительным инстансом; если ручная проверка не проведена, статус `NotRun`.
- Тесты используют фиктивные значения и не обращаются к реальному GREEN-API. Результаты, включая причину Red и ограничения, записываются в `verification.md`.

## Complexity Tracking

Дополнительного инструмента или хранилища нет. Отдельный маршрут нужен, чтобы добровольный POST-выход не смешивался с уже существующим GET-завершением сессии при потере доступа. Минимальный компонент сохраняет проектное правило отдельной папки и позволяет поставить кнопку в двух состояниях главной без дублирования.
