# Research: E03.3 — явный выход

**Дата**: 2026-10-01

## Исходное состояние

- `/` — серверная страница. Она читает зашифрованную HttpOnly-cookie и показывает JSON при `authorized` либо сообщение о временной ошибке. При потере доступа внутренний `GET /api/auth/end-session` уже удаляет cookie и ведёт на `/login?reason=access_lost`.
- Cookie имеет путь `/` и абсолютный срок 24 часа. Сессия хранится в браузере, отдельной записи на сервере нет.
- `/login` уже читает безопасный параметр `reason` для сообщения о потере доступа. В проекте есть общий набор констант, SCSS-токенов, интеграционные и браузерные тесты.

## Проверенные технические факты

- [Next.js Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route) поддерживают `POST`; изменение cookie должно происходить в обработчике или серверной функции, а не во время рендера серверного компонента ([cookies](https://nextjs.org/docs/app/api-reference/functions/cookies)).
- [NextResponse](https://nextjs.org/docs/app/api-reference/functions/next-response) поддерживает удаление cookie. Обработчик задаёт относительный `Location`, сохраняя исходный домен браузера; абсолютный URL на основе `request.url` в локальном запуске может содержать `localhost`, когда сайт открыт через `127.0.0.1`. После POST используется HTTP 303, чтобы браузер запросил `/login` методом GET ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Redirections)).
- [iron-session](https://github.com/vvo/iron-session) хранит сессию в зашифрованной cookie и описывает `destroy()` как удаление cookie. Без серверного состояния мгновенно отозвать её копию на другом устройстве нельзя. Это ограничение относится к существующей архитектуре, а не к кнопке выхода.

## Проверки

- Интеграционный тест маршрута: POST возвращает 303, фиксированный адрес `/login`, удаление cookie и `Cache-Control: no-store`; повтор без cookie безопасен. GET не завершает сессию.
- Браузерный тест: переход на обычную форму `/login` без сообщения и повторное открытие `/` соответствуют спецификации. Кнопку при JSON и временной ошибке пользователь проверяет с действительным инстансом; автоматический серверный тест не подменяет эту ручную проверку.
- Реальные реквизиты и запросы к GREEN-API для этой задачи не нужны. Новых зависимостей нет.
