## Выбор способа проверки

| Вариант | Преимущество | Риск / решение |
| --- | --- | --- |
| Перенести зелёный результат 054 в финальный отчёт | Быстро | Не доказывает точный финальный SHA; отклонено для 055. |
| Полный локальный прогон после адресных правок + CI того же pushed SHA | Проверяемая локальная и удалённая готовность | Долгий browser run, но он уже настроен и обязателен по FR-001/FR-006; выбран. |
| Добавить новый test runner/пакет для проверки документации | Возможная автоматизация | Новая зависимость и поддержка ради одноразовой сверки; не требуется. Локальные ссылки проверяются read-only скриптом, команды — по `package.json` и запуском. |
| Переписать все исторические specs под новую структуру | Видимое единообразие | Стирает происхождение решений; отклонено. Актуальные точки входа обновляются, история остаётся. |

## Доказательство и пределы

Vitest проверяет чистую логику и React в jsdom, но не layout/настоящие браузерные API. Query Playwright покрывает Next fixture и браузерный lifecycle; production E2E покрывает routes/cookie/focus/layout и сборку. Сохранение сценариев доказывается картами ID и discovery, а не только суммой тестов. Локальный прогон не доказывает GitHub окружение; GitHub run должен иметь точный `head_sha`, два successful job и опубликованные артефакты. Фиктивный провайдер не доказывает настоящую доставку Telegram или deployment. Изменчивые версии/внешние руководства не утверждаются без проверки; в документации используются pinned зависимости проекта.
