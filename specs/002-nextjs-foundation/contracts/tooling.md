# Контракт инструментов и команд E02.2

**Связанные требования**: FR-005–FR-011.
**Статус**: подготовлен к реализации; проверки NotRun.
Все команды запускаются из корня проекта. Версии — в [research.md](../research.md).

## Среда и установка

Node 24.x, npm 11.x. package.json: private: true, engines.node: 24.x,
engines.npm: 11.x, packageManager: npm@11.11.0.
Скачивание и установку выполняет только пользователь.

- Первая установка: npm install; создаёт package-lock.json и node_modules.
- Повторение готовой установки: npm ci; пересоздаёт node_modules по lock-файлу.
- Агент не запускает npm install, npm ci, npx или команду с автоматической установкой.
- Перед next-командами проверить наличие всех прямых зависимостей через npm ls --depth=0,
  чтобы автоматическая установка отсутствующих TypeScript-пакетов не запускалась.
- Переход через конфликт зависимостей с --force/--legacy-peer-deps запрещён планом.

## Команды package.json

| Команда пользователя | Содержимое script            | Назначение                                           |
| -------------------- | ---------------------------- | ---------------------------------------------------- |
| npm run dev          | next dev                     | Локальная разработка                                 |
| npm run build        | next build                   | Production-сборка                                    |
| npm run start        | next start                   | Запуск готовой сборки                                |
| npm run typecheck    | next typegen && tsc --noEmit | Генерация маршрутных типов и проверка TypeScript     |
| npm run lint         | eslint . --max-warnings=0    | Проверка JS/TS; предупреждения также блокируют успех |
| npm run format:check | prettier --check .           | Проверка форматирования в заданной области           |
| npm run format       | prettier --write .           | Явное форматирование этой области по запросу         |

Проверки не выполняют автоисправление исходников. typecheck вправе создать
служебные .next/types и next-env.d.ts; tsc не эмитирует JS.
Производственные проверки запускаются после остановки dev-сервера,
чтобы процессы не работали одновременно с одним каталогом .next.
Turbopack используется по умолчанию; отдельной конфигурации сборщика нет.

## Конфигурации

- Next.js: agentRules false сохраняет проектные инструкции без автоматической
  записи в AGENTS.md/CLAUDE.md при next dev. Остальные настройки стандартные.

- TypeScript: strict, noEmit, moduleResolution bundler, esModuleInterop,
  resolveJsonModule, isolatedModules, jsx react-jsx, plugin next.
  Алиас @/* → ./src/* без необходимости искусственно использовать его.
  include: next-env.d.ts, next.config.ts, src/**/\*.ts, src/**/_.tsx, .next/types/\**/_.ts,
  .next/dev/types/**/*.ts; exclude: node_modules.
- ESLint: flat config с eslint-config-next/core-web-vitals,
  eslint-config-next/typescript и eslint-config-prettier/flat.
  Игнорируются генерируемые файлы, зависимости и комплект PowerShell.
  Проверяемая область — исходники TS/TSX и конфигурации JS/TS в корне.
- Prettier: отступ 2, singleQuote true, trailingComma all, endOfLine lf.
  Форматирование SCSS включено; переименование БЭМ-классов не выполняется.
- .prettierignore: node_modules/, .next/, out/, build/, coverage/,
  next-env.d.ts, package-lock.json, .git/, .vercel/, .env*,
  .agents/, .specify/, docs/, specs/, tests/spec-kit/, AGENTS.md, GIT_POLICY.md.
  README.md остаётся в проверке. Игнорирование старых документов относится
  только к форматтеру, а не к содержательному ревью и Git.
- .gitignore: node_modules/, .next/, out/, build/, coverage/, .vercel/,
  .env*, _.tsbuildinfo, next-env.d.ts, npm-debug.log_ и *.log.
  package-lock.json, правила, skills, specs и документация не игнорируются.
  Когда понадобится безопасный .env.example, исключение проектируется в той задаче.

- .gitattributes: LF закреплён только для src/** и перечисленных новых файлов
  приложения в корне, включая конфигурации, README и lock-файл. Существующие
  правила и документы не перенормализуются; настройки Git не меняются.

## Правила SCSS

Цвета и общие значения оформления объявляются только в src/styles/_tokens.scss.
Компоненты и глобальные стили используют @use с пространством имён tokens.
Повторяющиеся группы свойств находятся в src/styles/_mixins.scss и вызываются
через @include с пространством имён mixins. Частичные файлы определяют переменные
и миксины; самостоятельных селекторов и побочных CSS-правил в них нет.

Миксин typography принимает font-size, line-height и необязательный font-weight;
применяется к заголовку и описанию. Модификаторы, переменные и миксины без
потребителей не создаются. Структурные 0, 100% и auto остаются в месте применения.
Ревью проверяет отсутствие литералов цветов вне tokens и дублируемых групп свойств.

## Подтверждение работы проверок

Для каждого инструмента однократно проверить положительный итоговый запуск
и отрицательный пример. Временный файл src/quality-probe.ts создаётся только
после проверки отсутствия такого файла; при конфликте выбрать свободное имя.
По очереди использовать несовместимый тип, неиспользуемую переменную
и заведомо неформатированный код. Для каждого примера запустить соответствующую
команду, получить ненулевой exit code и понятную диагностику.

Удалить только созданный временный файл; чужие изменения не откатывать.
После удаления повторить итоговые проверки. Временные примеры не входят в коммит.
Команда format не нужна для проверки format:check; при форматировании ограничиться
плановой областью. Набор тестов Spec Kit запускается отдельно под PowerShell 7
только при затрагивании его файлов или выявленной регрессии.
