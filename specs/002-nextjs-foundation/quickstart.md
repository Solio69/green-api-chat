# Quickstart: E02.2

**Статус**: файлы приложения подготовлены; требуется установка зависимостей.
Реализация разрешена пользователем. Команды ниже выполняются по порядку;
установку выполняет пользователь.

## 1. Проверить окружение

~~~powershell
Set-Location -LiteralPath 'D:\Pet-projects\green-api-chat'
node --version
npm --version
~~~

Ожидаются Node 24.x и npm 11.x. В окружении агента обнаружены 24.14.1 / 11.11.0.
Если в терминале пользователя версии отличаются, сначала проверить выбранный
исполняемый файл; установка или переключение среды агентом не выполняется.

## 2. Установить зависимости — действие пользователя

Для первой подготовки, пока package-lock.json отсутствует:

~~~powershell
npm install
~~~

Команда скачивает зависимости по package.json и создаёт lock-файл.
Затем для проверки воспроизводимой установки, а также после получения
готового репозитория с package-lock.json:

~~~powershell
npm ci
~~~

npm ci пересоздаёт node_modules и использует зафиксированное дерево.
Не запускать эту команду при работающем сервере; не использовать --force
или --legacy-peer-deps при конфликте. Агент эти установки не выполняет.

## 3. Проверить зависимости и качество

~~~powershell
npm ls --depth=0
npm run typecheck
npm run lint
npm run format:check
~~~

Продолжать после успешного завершения каждой команды. При missing/invalid
не запускать Next до исправления установки пользователем.
typecheck создаёт служебные типы, затем проверяет исходники; lint проверяет
правила кода; format:check проверяет единый стиль без исправлений.
npm run format — отдельная команда изменения форматирования, в проверках не нужна.

## 4. Запустить разработку

~~~powershell
npm run dev
~~~

Открыть http://localhost:3000/ в браузере; проверить заголовок, пояснение,
применённые стили и консоль. Если порт занят, остановить свой предыдущий процесс
или выбрать свободный порт:

~~~powershell
npm run dev -- --port 3001
~~~

Дальнейшие запросы направлять на реально используемый порт.
Не завершать чужие процессы только для освобождения порта.

## 5. Проверить сервер из второго терминала

При порте 3000:

~~~powershell
$taskHealth = Invoke-WebRequest -UseBasicParsing -Uri 'http://localhost:3000/api/health'
$taskHealth.StatusCode
$taskHealth.Headers['Content-Type']
$taskHealth.Headers['Cache-Control']
$taskHealth.Content
~~~

Ожидается 200, application/json, no-store и {"status":"ok"}.
Повторить запрос. POST по тому же адресу должен дать 405; PowerShell может
представить такой HTTP-ответ как исключение, а не как успешный объект.
Наличие ответа не подтверждает подключение к GREEN-API.

## 6. Проверить production

Остановить свой dev-сервер Ctrl+C. Выполнить:

~~~powershell
npm run build
npm run start
~~~

start выполняется только после успешного build. Повторить проверки / и
/api/health, включая браузер. По окончании остановить свой сервер Ctrl+C.
Публикация на Vercel в эти команды не входит.

## Если проверка не прошла

- Зависимости отсутствуют: установку выполняет пользователь, затем npm ls.
- Версия Node не совпадает: проверить node --version и выбранную среду.
- Порт занят: выбрать свободный порт или остановить свой предыдущий сервер.
- Нельзя запустить start: сначала проверить успешность build.
- Ошибка типов/линтера/форматирования: исправить причину; не отключать проверку.
- Отсутствует доступный браузер: отметить UI-проверку NotRun/Blocked
  и передать её пользователю, не объявлять визуальную приёмку успешной.

Отрицательные примеры команд и финальное ревью описаны в
[tooling](contracts/tooling.md) и [плане](plan.md). Они не требуют установки
Vitest или Playwright для этой задачи.
