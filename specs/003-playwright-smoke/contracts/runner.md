# Контракт запуска и проверки тестового набора

**Связанные требования**: FR-001–FR-004, FR-009–FR-012.
**Статус**: реализован; технические проверки пройдены.
Фактические результаты и итоговый статус — в [verification.md](../verification.md).

## Команды

| npm script           | Значение                    | Назначение                                         |
| -------------------- | --------------------------- | -------------------------------------------------- |
| test:e2e             | playwright test             | Полный регрессионный прогон с собственным сервером |
| test:report          | playwright show-report      | Открыть HTML-отчёт; завершает пользователь Ctrl+C  |
| test:install-browser | playwright install chromium | Явная установка браузера только пользователем      |

@playwright/test фиксируется в devDependencies как 1.63.0.
Все команды обращаются к установленному локальному CLI; npx и автоматические
установки в тестовом прогоне не используются. test:install-browser не вызывается
из test:e2e, build, start, postinstall или других автоматических hooks.

Обычный запуск: npm run test:e2e или ▶ у test:e2e в NPM Scripts.
Перед ним пользователь останавливает dev/production и другие прогоны в этой папке.
Выборочный запуск с фильтрами служит диагностике, не подтверждает полный набор.

## Конфигурация

- playwright.config.ts импортирует defineConfig/devices из @playwright/test
  и общие тестовые параметры из tests/constants.ts.
- testDir: ./tests/e2e; testMatch: **/*.spec.ts. Spec Kit в tests/spec-kit
  не включается. Только проект chromium с Desktop Chrome, headless.
- workers: 1; fullyParallel: false; retries: 0; forbidOnly: true.
  Не добавлять test.skip/fixme/fail/only в постоянный набор.
- baseURL: http://127.0.0.1:3101; URL строится из общих HOST и PORT.
- webServer.command: npm run build && npm run start -- --hostname 127.0.0.1 --port 3101.
  Команда формируется с теми же HOST/PORT. Запуск только из корня проекта.
- webServer.url: baseURL + /; reuseExistingServer: false;
  stdout/stderr: pipe. Имеющийся отвечающий сервер не переиспользуется.
- Константы времени в миллисекундах: SERVER_START=120000, RUN=240000,
  TEST=30000, EXPECT=5000, REQUEST=10000, ACTION=10000, NAVIGATION=10000.
  RUN применяется к globalTimeout, SERVER_START — к webServer.timeout.
  REQUEST передаётся в каждый HTTP-запрос, остальные — к штатным настройкам.
- NEXT_TELEMETRY_DISABLED=1 задаётся в env только запускаемого проверочного
  сервера; глобальное окружение пользователя не меняется.
- Reporter: list и html с open: never, outputFolder: playwright-report.
  outputDir: test-results. trace: retain-on-failure; screenshot: only-on-failure;
  видео и визуальные эталоны не используются.
- Специальные настройки gracefulShutdown, globalSetup/globalTeardown,
  кастомный reporter и собственный скрипт управления процессами не нужны.

Имена заголовков, коды и ожидаемые тела принадлежат тестовым определениям.
Используемые значения деструктурируются. Общие параметры задаются один раз;
числа и строки контрактных ожиданий не импортируются из src/.

## Жизненный цикл и результат

1. Playwright читает конфигурацию и обнаруживает тесты.
2. При допустимом окружении запускает webServer; успешная сборка предшествует start.
3. Ожидает доступности сервера в заданных пределах.
4. Выполняет три независимых теста.
5. Пишет результат, завершает только свою группу процессов и возвращает exit code.

Полный успех: 3 passed, без skipped, failed, flaky и ожидаемых падений.
Пустая выборка является ошибкой; pass-with-no-tests не включается.
Ошибка сборки, старта или теста даёт ненулевой exit code; код после Ctrl+C
также не выдаётся за успешную приёмку.

Прогон выполняется в рабочей папке проекта и проверяет production-сборку:
тесты обращаются к собственному серверу на 127.0.0.1:3101. Чужие слушающие процессы,
включая пользовательский dev, никогда не останавливаются агентом.
Политика последовательной работы описывается в README.

Управление собственной группой процессов выполняет Playwright. Приёмка
жизненного цикла проводится на Windows; оставшийся слушатель/дочерний процесс
означает Failed для FR-004 и требует исправления до завершения задачи.
Это проверка обычного Ctrl+C, а не обещание очистки после отключения питания
или принудительного завершения всей ОС.

## Протокол проверки реализации

Все шаги ниже выполняются только после отдельного разрешения кода.
Команды исполняются из D:\Pet-projects\green-api-chat. Каждая временная правка
начинается со снимка содержимого/хеша; восстановление только собственных правок,
без git restore/reset. Чужие изменения не перезаписываются.

### V01 — установка и обнаружение

Пользователь выполняет npm install и npm run test:install-browser.
Агент проверяет npm ls --depth=0, точную версию в package.json/lock и наличие
локального CLI. npm run test:e2e -- --list должен обнаружить три теста.
Недостающий пакет фиксируется как Blocked, установки агентом нет.

### V02 — успешный прогон

npm run typecheck, npm run lint, npm run format:check; затем npm run test:e2e.
Ожидаются exit 0 и 3 passed. Проверить list/HTML-диагностику, порт 3101
и отсутствие дочерних процессов проверочного запуска после его завершения.

### V03 — контрольная ошибка ожидания

В tests/constants.ts временно заменить только значение ожидаемого JSON-status
на smoke-control-mismatch. Запустить npm run test:e2e.
Должен упасть HTTP-тест с несовпадением тела, exit !=0; сервер освобождается.
Проверить HTML-отчёт. Восстановить исходное значение по снимку.
Это контроль работоспособности тестов, а не Red бизнес-логики.

### V04 — неверный TypeScript и ошибка сборки

Только если tests/e2e/quality-probe.ts отсутствует, создать временный экспорт
с присваиванием строки числовому типу. npm run typecheck должен вернуть
ошибку в этом файле. npm run test:e2e должен завершиться ненулевым кодом
из-за неуспешной сборки без успешного результата тестов и оставшихся процессов.
Удалить только свой probe; сохранить диагностику для verification.
Playwright транспилирует TS, поэтому этот шаг проверяет охват отдельного typecheck
и распространение ошибки сборки на весь запуск.

### V05 — отсутствие тестов

npm run test:e2e -- --grep **missing_smoke_probe**
Ожидается отсутствие найденных тестов и exit !=0. Пакеты/исходники не меняются;
порт не должен оставаться занят проверочным сервером.

### V06 — отсутствующий браузер

Для одного дочернего прогона указать PLAYWRIGHT_BROWSERS_PATH на новый
несуществующий путь внутри игнорируемого test-results. Его отсутствие
проверяется заранее. Ничего не скачивать, не удалять существующий кеш Chromium.
Ожидается диагностика отсутствующего browser executable, exit !=0 и освобождение
проверочного сервера. Переменная не сохраняется в системном окружении.
Итоговый прогон использует обычное окружение.

### V07 — занятый порт

При свободном 3101 запустить собственный временный HTTP-сервер, отвечающий 200.
Зафиксировать его PID. npm run test:e2e должен отказаться от переиспользования
сервера с ненулевым кодом. Временный слушатель остаётся жив и отвечает;
его останавливает только создавший его проверочный шаг.
При изначально занятом чужим процессом порте тест не начинает с остановки этого процесса.

### V08 — ограниченное ожидание и Ctrl+C

Для проверки таймаута сохранить playwright.config.ts и временно заменить
только webServer.command на собственный бездействующий Node-процесс без слушателя,
а timeout — на 1000 мс. Прогон должен вернуть ошибку готовности и убрать
свой процесс. Восстановить конфигурацию; сторонние процессы не затрагиваются.

Для проверки прерывания запустить npm run test:e2e -- --repeat-each=100,
дождаться запуска сервера и выполнения тестов, прервать Ctrl+C.
Повторение нужно только для возможности наблюдаемого прерывания.
Подтвердить завершение группы и освобождение 3101; этот запуск не является
полной приёмкой трёх сценариев.

### V09 — окончательное состояние и ревью

После всех контрольных ошибок восстановить собственные временные изменения
и подтвердить отсутствие quality-probe.ts, фильтров, пропусков и expected failures.
Повторить typecheck/lint/format:check и полный npm run test:e2e.
Ожидаются exit 0, 3 passed, динамический /api/health в build и свободный 3101.
Проверить игнорирование результатов, LF, неизменность src/, Git index и правил.
Зафиксировать результаты V01–V09 в verification, затем выполнить read-only
анализ и предкоммитное ревью.

## Статусы

Passed — ожидаемый результат реально получен.
Failed — проверка обнаружила несоответствие.
Blocked — отсутствуют необходимые установка, доступ или контролируемое окружение.
NotRun — проверка ещё не выполнялась.
Отрицательные сценарии проходят при ожидаемом ненулевом exit и корректной диагностике.
