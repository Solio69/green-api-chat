# Quickstart: E02 — автотесты основы

**Статус**: команды и тесты реализованы; установка пользователем и успешный
прогон подтверждены в verification.md.
**Spec**: [spec.md](spec.md), **план**: [plan.md](plan.md).
Шаги 1–2 нужны для нового окружения. На текущем компьютере установка завершена;
для обычного прогона достаточно шага 3.

## 1. Подготовить окружение

Проект: D:\Pet-projects\green-api-chat. Среда Node 24.x/npm 11.x.
Для npm-команд подходит текущий терминал VS Code; PowerShell 7 нужен только Spec Kit.
Перед установкой или полным прогоном остановить dev, production и другие
проверки этой рабочей папки. Агент не останавливает пользовательские процессы.

После подготовки package.json пользователь выполняет из корня проекта:

```powershell
npm install
```

Это добавляет @playwright/test 1.63.0 и обновляет package-lock.json.
Агент проверяет npm ls --depth=0 и соответствие версии в manifest/lock.
При воспроизведении готового проекта по сохранённому lock используется npm ci.

## 2. Установить Chromium

Пользователь нажимает ▶ у test:install-browser в NPM Scripts либо выполняет:

```powershell
npm run test:install-browser
```

Команда запускает локальный playwright install chromium. Браузер и необходимые
ему служебные компоненты находятся вне исходников проекта в кеше Playwright.
Эта установка не является частью обычного тестового прогона.
При обновлении Playwright может потребоваться повторная установка браузера.

## 3. Запустить проверки

В NPM Scripts доступны:

| Кнопка ▶ у скрипта | Результат                                                           |
| ------------------ | ------------------------------------------------------------------- |
| typecheck          | Проверка типов приложения, конфигурации Playwright и тестов         |
| lint               | Проверка кода ESLint                                                |
| format:check       | Проверка форматирования                                             |
| test:e2e           | Сборка, запуск собственного сервера, три теста и завершение сервера |
| test:report        | Просмотр HTML-отчёта последнего прогона                             |

Эквивалент обычного полного прогона:

```powershell
npm run test:e2e
```

Ожидаемый результат: exit 0 и 3 passed. Страница проверяется в Chromium,
два GET и один POST отправляются через HTTP. Вручную выполнять build/start
перед test:e2e не нужно. Тестовый адрес — http://127.0.0.1:3101.

test:report запускает отдельный просмотр отчёта; его процесс завершить Ctrl+C.
Отчёт находится в playwright-report/, диагностика тестов — в test-results/.
Оба каталога игнорируются Git; автоматического открытия HTML при ошибке нет.

Если нужно только увидеть состав набора:

```powershell
npm run test:e2e -- --list
```

Ожидается ровно три теста одного проекта chromium. Это только обнаружение,
не выполнение проверок приложения.

## 4. Прочитать результат

- 3 passed: полный набор завершился успешно.
- Failed с ожидаемым и фактическим значением: нарушено проверяемое поведение.
- Ошибка executable/package: отсутствует установка; выполняется пользователем.
- Ошибка сборки или готовности сервера: сначала исправить указанную причину,
  результат не считается успешным тестом приложения.
- No tests found: проверить команду и конфигурацию; не включать pass-with-no-tests.
- Занятый 3101: определить, какой процесс запущен пользователем, и остановить его
  самостоятельно при необходимости. Тестовый runner не переиспользует этот сервер.
- Прерывание: Ctrl+C в терминале тестов. На вопрос Windows
  Terminate batch job (Y/N)? ответить Y и Enter; запрос может повториться.
  Если процесс или слушатель сохранился,
  сообщить об этом; проверка очистки не считается пройденной.

Для диагностики агент использует протокол V01–V09 из
[контракта запуска](contracts/runner.md). Контрольные ошибки выполняются только
после разрешения реализации и восстанавливаются до итогового прогона.

## 5. Завершить задачу

Агент проверяет соответствие спеке, качество кода и документации, игнорирование
результатов, сохранность исходников и отсутствие собственных оставшихся процессов.
Фактические результаты фиксируются в verification.md после выполнения.

Пользователь просматривает изменения в Source Control и создаёт коммит сам.
Агент Git index не меняет без отдельной прямой просьбы с путями.
Предлагаемое название коммита:

```text
chore: add Playwright smoke tests for the app foundation
```

Деплой E02.3 и проверки новых возможностей обсуждаются отдельно.
В будущих задачах агент сам определяет необходимое покрытие и потребность
в дополнительных инструментах по правилам проекта.
