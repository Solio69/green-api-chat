## R4. Управление сервером

| Вариант                                  | Преимущества                                | Ограничения                                                | Решение                           |
| ---------------------------------------- | ------------------------------------------- | ---------------------------------------------------------- | --------------------------------- |
| Штатный webServer Playwright             | Управляет запуском, ожиданием и завершением | Поведение прерывания на Windows нужно фактически проверить | Выбран                            |
| Пользователь вручную запускает сервер    | Простой конфиг                              | Не выполняет требование одного запуска                     | Не выбран                         |
| Собственный Node/PowerShell orchestrator | Полный контроль процессов                   | Дополнительный код и собственные проверки жизненного цикла | Не нужен при работающем webServer |

webServer запускает npm run build && npm run start -- --hostname 127.0.0.1 --port 3101.
Порт и baseURL определяются общими тестовыми константами. reuseExistingServer=false
предотвращает использование уже отвечающего сервера. stdout/stderr выводятся,
чтобы ошибка сборки или старта была видна. Готовность проверяется по /;
корректность его ответа отдельно проверяют тесты.

Выбраны лимиты: сервер 120 секунд, полный прогон 240 секунд, тест 30 секунд,
ожидаемое состояние DOM 5 секунд, запрос/навигация 10 секунд.
Это настройки нашего проекта, а не измеренные длительности проверок.

Playwright документирует завершение своей группы процессов; gracefulShutdown
с SIGTERM/SIGINT на Windows не применяется. Используем стандартный механизм,
подтверждаем освобождение порта и отсутствие дочерних процессов при реализации.
Собственный обработчик taskkill и скрипт-обёртка не проектируются.
[Web server](https://playwright.dev/docs/test-webserver),
[таймауты](https://playwright.dev/docs/test-timeouts).

Разработка и проверки выполняются по очереди в одной папке; пользователь
останавливает свой dev. Этот набор не вводит координацию независимых прогонов.
Ошибка освобождения процессов на Windows блокирует приёмку FR-004.

## R5. Независимые ожидания и диагностика

tests/constants.ts содержит параметры runner и ожидаемый контракт.
Никаких импортов src/lib/* или route.ts в тестах: случайная правка продуктовой
константы должна обнаруживаться проверкой. Переиспользование значений и
деструктуризация выполняются внутри тестовых определений.

Для страницы используется getByRole('heading', { level: 1, name: ..., exact: true })
и ожидание видимости. HTTP-ответ проверяется глубоко, включая отсутствие лишних полей.
Два GET проверяются одним тестом последовательно; POST — отдельным тестом.
Всего три теста в одном проекте Chromium, workers=1, retries=0, forbidOnly=true.
Пропуски, expected failures и focused tests в постоянном наборе не допускаются.
Выборочный запуск не считается полной приёмкой.

Результат: list в терминале и HTML-отчёт с open: never.
Трассировка сохраняется при ошибке, снимок страницы — только при ошибке;
видеозапись и сравнение визуальных эталонов не нужны.
[Конфигурация](https://playwright.dev/docs/test-configuration),
[HTML-отчёт](https://playwright.dev/docs/test-reporters#html-reporter),
[параметры диагностических артефактов](https://playwright.dev/docs/test-use-options).

## R6. TypeScript, инструменты и Git

Playwright преобразует TypeScript для исполнения, но typecheck выполняется отдельно.
В tsconfig.json явно включаются playwright.config.ts и tests/e2e/**/*.ts.
Существующая команда next typegen && tsc --noEmit сохраняется.
[TypeScript](https://playwright.dev/docs/test-typescript).

ESLint уже охватывает TypeScript вне своих ignore; новые файлы не исключаются.
test-results/ и playwright-report/ исключаются из ESLint, Prettier и Git.
.gitattributes задаёт LF для новых тестов и конфигурации, как для файлов приложения.
Строгая типизация и стилистические правила остаются действующими.

## R7. Приёмка и ограничения

Полный успешный прогон должен показать 3 passed без skipped/failed.
Контрольное неверное ожидаемое значение подтверждает падение теста и exit !=0,
после восстановления запускается итоговый успешный набор.
Это проверка конфигурации тестов и существующего поведения, не TDD прошлой реализации.

Отдельно проверяются пустая выборка, занятый проверочный порт, отсутствие Chromium
через временный путь кеша и прерывание. Пользовательские пакеты/браузеры
для этих проверок не удаляются. Недостающая npm-зависимость диагностируется
до запуска; ради ошибки пакеты не переименовываются и не удаляются.
Точный протокол — [runner](contracts/runner.md).

Runtime-проверки выполнены на Windows; фактические результаты и ограничения
описаны в verification.md.
Отдельная модель данных не нужна: прикладное хранилище отсутствует.
