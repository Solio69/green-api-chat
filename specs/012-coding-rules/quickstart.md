# Как применять правила проекта

Перед изменением кода агент читает `AGENTS.md`, затем `docs/CODING_RULES.md`. `docs/CODE_STYLE.md` служит картой: ручные решения находятся в CODING_RULES, автоматические — в действующих конфигурациях ESLint, Prettier и Stylelint.

После изменения затронутых файлов запустить подходящие `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run lint:styles` и тесты по риску задачи. Проверка структуры папок остаётся ручным ревью: отдельного скрипта нет.

Для проверки редактора после обновления конфигурации выполнить в VS Code `Developer: Reload Window`. Затем сохранить контрольный TypeScript-файл внутри проекта и убедиться, что результат совпадает с Prettier CLI: необязательные точки с запятой отсутствуют, порядок импортов соответствует ESLint. Это отдельное наблюдение пользователя; успешный CLI сам по себе не подтверждает редактор. Глобальные настройки VS Code не меняются.
