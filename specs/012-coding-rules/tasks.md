Пути относительны корню проекта. Работа последовательная.

## Phase 4 — проверка и отчёт

Цель: документы непротиворечивы, CLI и редактор проверяются раздельно.

- [x] T007 [US1] [US2] Провести read-only ревью матрицы FR-002, ссылок, исключений Next.js и границ автоматизации; проверить синтаксис `.vscode/settings.json`, затем одним итоговым проходом запустить `npm run lint`, `npm run format:check`, `npm run typecheck` и `npm run lint:styles`. На контрольном TypeScript-файле сверить CLI-форматирование и ESLint-порядок импортов. Пользователь после обновления окна VS Code вручную проверяет сохранение; до её наблюдения результат редактора пометить Blocked/NotRun.
- [x] T008 [US1] [US2] Выполнить предкоммитное ревью diff: нет продуктового кода, новых зависимостей, секретов, скрипта структуры, skill и нарушенных ссылок. Сверить FR/SC, сохранить реальные результаты в `specs/012-coding-rules/verification.md`, дать следующие шаги и английское название коммита без создания коммита.

## Dependencies & Execution Order

Завершение 011 → T001 → T002 → T003 → T004 → T005 → T006 → T007 → T008. T007 зависит от готовой конфигурации Stylelint задачи 011. Проверка CLI не заменяет ручное наблюдение VS Code. Продуктовая логика и серверный контракт не меняются; искусственный TDD Red не требуется. Новые смысловые правила применяются к новому и затронутому коду, не вызывают массовой правки существующих функций.

## Completion

Готовность означает единый полный документ ручных правил, рабочие ссылки, проектные настройки без конфликта импортов, успешные CLI-проверки и честно отмеченное состояние редактора. Соответствие спеке, ревью и результаты записаны в `verification.md`; пользователь получает дальнейшие действия и английское название коммита.

## Operator-only actions

Установка пакетов не требуется. Пользователь выполняет `Developer: Reload Window` и наблюдает результат форматирования в VS Code, когда соседняя работа не прерывается. Агент не меняет БД и Git index, не создаёт коммит и не публикует проект.
