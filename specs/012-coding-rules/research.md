# Исследование: правила для агентов и редактора

**Дата**: 2026-10-01
**Spec**: [spec.md](spec.md)

## Факты

- Действующий docs/CODE_STYLE.md смешивает автоматические и смысловые правила. AGENTS.md повторяет часть правил констант и SCSS; constitution и README ссылаются на CODE_STYLE.md. Исторические спецификации также содержат ссылки на него.
- ESLint и Prettier уже выполняют сортировку импортов, некоторые упрощения выражений, типовые ограничения и форматирование без необязательных точек с запятой. Stylelint рассматривается отдельно в specs/011-scss-stylelint.
- Настройки пользователя VS Code включают автосохранение, Prettier как форматтер, ESLint fixAll и встроенный organizeImports при сохранении. Последний может менять порядок импортов независимо от ESLint.
- Журнал установленного расширения Prettier при форматировании файла маршрута показывал конфигурацию без semi: false, хотя текущий проектный Prettier CLI читает semi: false. Расширение было запущено до изменения конфигурации. Это свидетельствует об устаревшем состоянии расширения, но не доказывает конкретный механизм его кеша.
- [Документация расширения Prettier](https://github.com/prettier/prettier-vscode) рекомендует проектный конфиг как единый источник для CLI и редактора. [Руководство VS Code](https://code.visualstudio.com/docs/languages/javascript) описывает значения always и never для codeActionsOnSave; [устранение неполадок Prettier](https://github.com/prettier/prettier-vscode/blob/main/docs/troubleshooting.md) включает перезагрузку окна редактора.

## Технический выбор

- docs/CODING_RULES.md содержит только смысловые решения и положительные/отрицательные примеры. Автоматические правила описываются ссылкой на действующие конфигурации; дублирующая норма из AGENTS.md переносится в один документ, процессные правила AGENTS.md сохраняются.
- docs/CODE_STYLE.md становится короткой картой правил и остаётся на прежнем пути для существующих ссылок. Конституция и активные инструкции направляют агента к ручным правилам.
- Текущий prettier.config.mjs с semi: false остаётся проектным источником. Переименование конфигурации в JSON не требуется: оно затронуло бы действующие ссылки и не заменило бы проверку активного расширения.
- Проектная .vscode/settings.json задаёт Prettier при сохранении, сохраняет ESLint fixAll и отключает встроенный organizeImports в этой папке; глобальные настройки пользователя не меняются. После завершения соседней работы пользователь перезагружает окно VS Code и вручную сверяет один файл с CLI.
- Ручные правила применяются к новому и затрагиваемому коду; массовое изменение действующих сигнатур и компонентов находится за границей задачи. Этот предел явно указан в spec.
