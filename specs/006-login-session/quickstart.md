# Quickstart: E03.2 — вход и сессия

## Подготовка пользователя

1. В `D:\Pet-projects\green-api-chat` установить согласованную зависимость командой `npm install iron-session@9.0.1 --save-exact`. Пакет и lock-файл устанавливает/обновляет пользователь; агент установку не выполняет.
2. Сгенерировать секрет локально: `node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))"`. Скопировать результат только в локальный `.env.local` как `SESSION_PASSWORD=<сгенерированное значение>`. Файл игнорируется Git; секрет нельзя присылать в переписку или добавлять в репозиторий. Для Vercel секрет задаётся отдельно в настройках окружения при согласованной публикации.
3. Запустить `dev` через NPM Scripts в VS Code или командой `npm run dev`. Открыть `/login`. Без `SESSION_PASSWORD` приложение не создаёт сессию и показывает безопасную ошибку настройки.

## Автоматические проверки после реализации

- `npm run test:integration` — серверная классификация ответов и сессия на фиктивных данных, без реального GREEN-API.
- `npm run test:e2e` — маршруты и форма в Chromium. Перед production-проверкой остановить dev-сервер в этой папке, чтобы процессы не мешали друг другу.
- `npm run typecheck`, `npm run lint`, `npm run format:check` — типы, правила и форматирование.
- Результаты Red/Green/Refactor и итоговой проверки записываются в `verification.md`.

## Ручная приёмка пользователя

1. Открыть `/` без входа: приложение направляет на `/login`.
2. Ввести в `/login` реквизиты своего подготовленного инстанса, не передавая их агенту. При `authorized` открывается `/` с JSON `{"stateInstance":"authorized"}` без промежуточного экрана ошибки. Если GREEN-API ограничил частоту запросов, проверка автоматически повторяется один раз после паузы; второй 429 показывает сообщение на форме или возможность повторить проверку на `/`.
3. Обновить `/`: страница остаётся доступной и получает актуальный ответ. Проверить ошибку формы на заведомо неверном токене, затем исправить его и повторить вход.
4. Отдельно проверить временный сбой можно с фиктивным тестовым ответом; не требуется отключать или разлогинивать настоящий Telegram-инстанс.

Чат, сообщения и пользовательский выход относятся к последующим задачам. База данных и миграции для этого шага не нужны.
