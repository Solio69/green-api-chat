# Implementation Plan: Ручное переключение темы

**Spec**: [spec.md](spec.md)

**Дата**: 2026-10-04

**Согласование spec.md**: Макет и поведение подтверждены пользователем; пользователь поручил продолжить без ожидания проверки документов.

**Разрешение на реализацию**: Дано в переписке; локальный коммит разрешён отдельно позже, push исключён.

## Summary

Оставить существующее CSS-оформление от `prefers-color-scheme` при отсутствии выбора. Разместить клиентскую кнопку с луной/солнцем у правого верхнего края окна вне рамки чата; для неё выделить верхнюю полосу и сохранить высоту чата в пределах viewport. Хранить только явный выбор `light`/`dark` в `localStorage`; небольшой скрипт в корневом layout применяет валидное значение до первого отображения. CSS-переменные обеих тем остаются единым источником оформления.

## Considered Options

| Вариант | Преимущества | Ограничения и риски | Выбор и причина |
| --- | --- | --- | --- |
| Только React `useEffect` | Меньше кода в layout | После reload возможна вспышка системной темы | Нет; FR-004 требует раннее применение |
| Ранний скрипт + `data-theme` на `<html>` | Ручная тема действует до отображения, JS-отказ сохраняет системный CSS | Нужно осторожно обработать недоступное хранилище и гидратацию | Да; небольшой код без пакета |
| Сторонняя библиотека тем | Готовое API | Новая зависимость для двух состояний, пользователь не просил пакет | Нет |
| Хранить выбор в cookie/сессии | Сервер видит предпочтение | Дополнительное серверное состояние и запросы | Нет; настройка локальна |

## Technical Context

Next.js App Router, React, TypeScript, SCSS Modules, Vitest/RTL и Playwright уже установлены. Тема определяется в `src/styles/_theme.scss`; серверная главная страница может отображать клиентскую кнопку отдельно от `AccountHeader`. Новых пакетов и переменных окружения нет. Тема не привязана к GREEN-API-сессии и не содержит персональных данных.

## Tasks and Dependencies

Сначала создать компонентный тест и подтвердить поведенческий Red отсутствия переключателя. Затем реализовать минимальное переключение, раннее применение сохранённого выбора и CSS-приоритет, получить Green. После этого улучшить размещение, покрыть browser-сценарий, обновить README и выполнить один итоговый набор проверок. Успешность отсутствующего теста не предполагается. Точный список и покрытие — в [tasks.md](tasks.md).

## Verification

Компонентный Red: `npm run test:component -- tests/component/theme-toggle.test.tsx` должен падать из-за отсутствия доступной кнопки/поведения, а не из-за импорта или окружения. Green и Refactor: тот же тест вместе с `account-header.test.tsx`. Браузер: Playwright-сценарий на фиктивном аккаунте для светлой/тёмной системы, двух нажатий и reload; проверить hit target, отсутствие переполнения и обратный фокус. Итоговые команды: `npm run lint`, `npm run lint:styles`, `npm run format:check`, `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run build`. Ошибка инфраструктуры обозначается Blocked, не Passed.

## Post-design Constitution Check

C1–C8 остаются PASS: выбранный вариант не добавляет серверное состояние, зависимости и действия во внешних системах. Отдельный возврат к системе после ручного выбора не вводится, поскольку пользователь отказался от дополнительного UI.

## Complexity Tracking

Ранний скрипт нужен только для исключения вспышки неправильной темы после reload. Остальная логика ограничена одним клиентским компонентом и существующей палитрой.
