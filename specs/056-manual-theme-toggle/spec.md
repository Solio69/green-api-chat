# Feature Specification: Ручное переключение темы

**Feature Directory**: specs/056-manual-theme-toggle

**Created**: 2026-10-04

**Status**: Выполнена локально; ожидает публикации пользователем

**User Approval**: Пользователь уточнил окончательное расположение: значок в самом правом верхнем углу окна над рамкой чата; разрешение пройти весь цикл без промежуточного согласования сохраняется.

**Implementation Authorization**: Реализация, проверки и документация разрешены; позднее отдельно разрешён локальный коммит, push не разрешён.

**Input**: Последний штрих к уже развёрнутому чату — системная тема при первом открытии и явное переключение кнопкой.

## User Scenarios & Testing

### User Story 1 — Заметное переключение темы (Priority: P1)

Пользователь видит компактный значок в самом правом верхнем углу окна, над рамкой чата, и одним нажатием переключает всё приложение между светлой и тёмной темами.

**Independent Test**: Открыть чат в обеих системных темах на телефоне и на широком экране, нажать кнопку и сравнить отображение приложения и пиктограммы.

**Acceptance Scenarios**:

1. **Given** сохранённого выбора нет, **When** страница открывается или системная тема меняется, **Then** оформление следует системе, а кнопка показывает действие, которое выполнит нажатие: луна для перехода к тёмной теме, солнце для перехода к светлой.
2. **Given** открыто приложение, **When** пользователь нажимает значок, **Then** всё приложение меняет тему без навигации и перезагрузки, значок меняется на противоположный.
3. **Given** пользователь явно выбрал тему, **When** он перезагружает страницу, **Then** выбранная тема применяется до отображения интерфейса и имеет приоритет над системной.
4. **Given** пользователь выбрал тему вручную, **When** он снова нажимает кнопку, **Then** тема переключается обратно и новый выбор сохраняется.

### User Story 2 — Понятная публикация проекта (Priority: P2)

Читатель README открывает опубликованное демо по ссылке пользователя и понимает, что тему можно переключать вручную.

**Independent Test**: Проверить текст и адрес ссылки в README; доступность сайта по сети не выводить из одной лишь корректности Markdown.

**Acceptance Scenarios**:

1. **Given** открыт README, **When** читатель нажимает «Демо», **Then** ссылка ведёт на `https://green-api-chat-two.vercel.app/`.
2. **Given** читатель просматривает пользовательский сценарий, **When** он ищет поддержку тем, **Then** текст описывает системный начальный режим и ручной переключатель.

### Edge Cases

- Хранилище браузера недоступно: нажатие всё равно переключает тему в текущей вкладке без ошибки для пользователя.
- В хранилище записано неизвестное значение: оно игнорируется, применяется системная тема.
- При ручном выборе последующая смена системной темы не переопределяет выбранный режим.
- На узком экране кнопка остаётся над рамкой чата, не перекрывает его содержимое и не вызывает горизонтального переполнения.
- При отключённом JavaScript остаётся существующее системное оформление.

### Verification Approach

Поведение переключателя проверяется сохраняемым компонентным тестом и браузерным сценарием: сначала поведенческий Red на недостающую кнопку/переключение, затем Green и повторный прогон после рефакторинга. Браузер проверяет начальную системную тему, сохранение после reload, ручной приоритет, размещение и мобильный экран. CSS, README и сборка проверяются штатными командами проекта. Реальные реквизиты и сообщения не используются.

## Requirements

### Functional Requirements

- **FR-001**: До первого ручного выбора тема всего приложения соответствует `prefers-color-scheme`, включая изменение системной настройки при открытой странице.
- **FR-002**: Кнопка без видимой подписи находится у самого правого верхнего края окна, над рамкой чата и вне шапки аккаунта; нет выпадающего меню.
- **FR-003**: В светлой теме видна луна, в тёмной — солнце; однократное нажатие меняет тему на противоположную во всём интерфейсе.
- **FR-004**: Ручной выбор сохраняется локально в браузере, применяется при следующей загрузке до первого отображения и имеет приоритет над системой.
- **FR-005**: Повторное нажатие меняет и сохраняет противоположную тему. Отдельный возврат к системному режиму через интерфейс в объём задачи не входит.
- **FR-006**: Кнопка доступна с клавиатуры, имеет видимый фокус и понятное доступное имя; область нажатия не меньше существующего стандарта проекта для иконок.
- **FR-007**: Ошибка доступа к локальному хранилищу и неизвестное сохранённое значение не ломают интерфейс; без JavaScript сохраняется системная тема.
- **FR-008**: На мобильном и широком экранах кнопка остаётся выше рамки чата, не перекрывает его содержимое и не вызывает горизонтальную прокрутку.
- **FR-009**: README содержит указанную пользователем ссылку на демо и описание системной начальной темы с ручным переключением.

### Scope Boundaries

- **В объёме**: небольшое управление темой, необходимые стили, локальное сохранение выбора, проверка поведения и обновление README.
- **За пределами**: меню из трёх режимов, серверное хранение, синхронизация между уже открытыми вкладками, изменение деплоя, новые зависимости и push.

### Data Effects & User Decision

- **Changed data**: Только локальная настройка темы браузера; серверная сессия, GREEN-API и переписка не затрагиваются.
- **Preview**: Текущая тема и луна/солнце видны перед нажатием.
- **Confirmation**: Само нажатие достаточно для обратимого изменения; пользователь разрешил реализацию этой задачи без промежуточного согласования.
- **Cancellation**: Отдельного диалога нет; следующее нажатие выбирает обратную тему.
- **Idempotency and duplicates**: Повторная загрузка не меняет сохранённый выбор; каждое нажатие выполняет один переход.
- **Failure result**: Если браузер блокирует запись, тема изменяется на время текущей страницы, приложение продолжает работать.

### Key Entities

Значение темы: `light` или `dark` при явном выборе; отсутствие корректного значения означает системный режим. База данных не требуется.

## Success Criteria

- **SC-001**: Компонентный и браузерный тесты подтверждают переход в обе стороны, системный старт и сохранение после перезагрузки (FR-001, FR-003–FR-005, FR-007).
- **SC-002**: На мобильном и десктопном экранах кнопка у правого верхнего края имеет доступное имя, видимый фокус, находится выше рамки чата и не создаёт переполнения (FR-002, FR-006, FR-008).
- **SC-003**: README содержит точный адрес демо и актуальное описание темы (FR-009).

## Assumptions and Dependencies

Действующая тема управляется CSS-переменными и `prefers-color-scheme`. React, Next.js, Vitest/React Testing Library и Playwright уже есть в проекте. Демо-адрес предоставлен пользователем; в среде подготовки он не открылся через веб-инструмент, поэтому доступность сайта отдельно не подтверждена. Последнее расположение у правого верхнего края и отсутствие подписи/меню согласованы в переписке.
