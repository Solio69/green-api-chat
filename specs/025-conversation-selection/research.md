# Исследование: выбор переписки

**Дата**: 2026-10-02. Спецификация и код 025 согласованы; реализация проверена в своей границе.

## Фактическая основа

ChatWorkspace принимает ReactNode account/search/chatList/conversation и
содержит SelectionProvider. Без выбора показан ConversationEmptyState;
выбранный чат получает ConversationPane/Header. ChatListPanel использует useChats;
ChatList передаёт подтверждённый chatId, RecipientSearchForm.handleWrite открывает
подтверждённый результат {chatId,label} без сети. Серверная page.tsx передаёт эти слоты под QueryProvider с key scope.
QuerySession имеет isActive/subscribe/close; реализованная история018 использует публичный
connectionScope. Мобильный breakpoint уже равен 680px. Инструменты — Playwright
integration/query/E2E; дополнительные библиотеки не требуются.

## Состояние выбора

| Вариант                                       | Польза                                                                   | Ограничения                                                                                                      | Решение   |
| --------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | --------- |
| Callback через все серверные слоты            | Явный поток props                                                        | Функцию нельзя передать через границу Server→Client как обычный сериализованный prop; придётся менять композицию | Не выбран |
| Узкий клиентский Context внутри рабочего чата | Список и результат поиска читают один выбор, серверные слоты сохраняются | Нужна небольшая публичная модель переходов                                                                       | Выбран    |
| Query/Zustand/global store для выбора         | Общий доступ                                                             | Выбор — локальное UI-состояние; дополнительный store не нужен                                                    | Не выбран |

[Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components)
разрешает серверу передавать уже созданные узлы в клиентскую оболочку; клиентский
Context доступен клиентским потребителям под ней. Серверную главную и профиль
не переводим в клиентские модули. Провайдер размещаем в ChatWorkspace, внутри
существующего QueryProvider.
[React createContext](https://react.dev/reference/react/createContext) и
[useContext](https://react.dev/reference/react/useContext) описывают подписку
потребителей на ближайший провайдер; Context здесь хранит только выбор и панель.

## Два счётчика

accessId увеличивается при каждом явном открытии, даже того же chatId: это
идентичность свежего обращения 018/019. selectionEpoch увеличивается при смене
chatId или закрытии: это граница очистки ввода 021. Один счётчик не подходит:
повторное обращение должно обновлять историю, но не объявляется переключением
на другого получателя. Оба значения локальны текущему экземпляру, не являются
идентификаторами GREEN-API и не сохраняются после закрытия Query-сессии.

## Мобильная панель

Выбор хранится независимо от viewport. openConversation показывает conversation,
showChatList — list, closeConversation снимает выбор. CSS при ширине более 680px
показывает обе панели независимо от mobilePanel, при меньшей скрывает одну через
display:none, исключая её из tab-порядка. Нет окна/ширины в первом SSR render.
Resize не создаёт открытие и не сбрасывает выбранный chatId. Фокус по действиям
проверяется браузером, а не предположением о DOM.

[React StrictMode](https://react.dev/reference/react/StrictMode) выполняет
дополнительные проверки в разработке. Действия выбора запускаются обработчиком
пользователя, не эффектом монтирования; один клик не увеличивает accessId дважды.

## Граница отображения истории

025 создаёт оболочку ConversationPane/Header и children-слот. 019 предоставляет
ChatHistoryPanel и состояния загрузки/ошибки/пустоты. До успешного чтения 025
не рисует приглашение как доказанную пустую историю. SC-002 проверяется отдельно
на контрактном слоте, а полный сценарий — при интеграции 019. Новых запросов
GetChatHistory, SendMessage или читателя очереди в 025 нет.

## Хук фокуса

Выбран приватный useWorkspaceFocus: React capture handlers отслеживают фокус
внутри workspace, refs ограничивают DOM-поиск панелями, ResizeObserver сообщает
об их изменении, включая display:none. Глобальные слушатели и viewport-state
не нужны. Навигация и подписка разделены; эффект навигации реагирует на выбор.

[React useEffectEvent](https://react.dev/reference/react/useEffectEvent) позволяет
обработчику, созданному эффектом, читать последние значения без пересоздания
подписки. Он не заменяет зависимости эффекта навигации и не вызывается из
React capture handlers. [React refs](https://react.dev/learn/manipulating-the-dom-with-refs)
подходят для явного управления фокусом; [Resize Observer](https://www.w3.org/TR/resize-observer/)
уведомляет об изменении наблюдаемых элементов и их скрытии через display:none.

Только извлечение прежнего эффекта оставило бы глобальные DOM-listeners.
Callback refs с cleanup могут управлять подпиской, но отдельный эффект здесь
проще для пары постоянно смонтированных панелей. Activity потребовал бы менять
жизненный цикл вложенных эффектов истории; это выходит за границы рефакторинга.
