# Feature Specification: D04 — адаптивный каркас чата MAX

**Feature Directory**: specs/015-chat-workspace-ui
**Created**: 2026-10-01
**Status**: Каркас, список и согласованная карточка восстановления реализованы; автоматическая приёмка Passed, пользовательская приёмка NotRun
**User Approval**: Подтверждено поручением пользователя «Пиши весь комплект документов» 2026-10-01; ранее согласованные границы и решение о кнопке сохраняются
**Workflow Mode**: Standard
**Implementation Authorization**: Реализация разрешена пользователем после завершения чата правил кода; старт подтверждён 2026-10-02
**Input**: Собрать адаптивный каркас главной по согласованному MAX-макету: аккаунт, существующий поиск и область списка слева; область переписки с пустым выбором справа. Редизайн поиска — отдельная D05; открытие переписки — D06. Источник списка и TanStack Query реализованы в 014; D04 потребляет готовый публичный контракт.

## User Scenarios & Testing

### User Story 1 — Видеть рабочие области чата (Priority: P1)

После подтверждения подключения пользователь видит понятное расположение аккаунта, поиска, списка чатов и области переписки.

**Why this priority**: Каркас даёт место существующим функциям и будущей переписке, не меняя серверные сценарии.
**Independent Test**: Открыть защищённую главную на desktop с вымышленным подтверждённым профилем; проверить две панели, один выход, работающий прежний поиск и пустую область переписки.

**Acceptance Scenarios**:

1. **Given** подключение подтверждено, **When** главная открыта на широком экране, **Then** слева размещены существующая шапка аккаунта, форма поиска и область «Чаты», справа — приглашение выбрать чат или найти получателя.
2. **Given** чат не выбран, **When** каркас показан, **Then** отсутствуют имя вымышленного собеседника, сообщения, статусы и форма отправки.
3. **Given** пользователь ищет получателя, **When** запрос завершается, **Then** поиск сохраняет действующий результат и обработку ошибок; правая панель не открывает переписку автоматически.
4. **Given** сессии нет либо главная не подтвердила подключение, **When** страница открывается, **Then** сохраняются существующие redirect/end-session/retry, без показа рабочего каркаса при неподтверждённом доступе.

### User Story 2 — Пользоваться интерфейсом на узком экране (Priority: P1)

На телефоне пользователь видит аккаунт, поиск и список в одной доступной колонке.

**Why this priority**: Компоновка должна быть пригодна для мобильного поиска до реализации переходов в переписку.
**Independent Test**: Проверить 320, 360, 390, 768 и 1280 px, длинную подпись аккаунта и масштаб текста 200%.

**Acceptance Scenarios**:

1. **Given** узкий экран, **When** главная открыта без выбранной переписки, **Then** видна левая область; декоративная правая область не занимает место и не участвует в клавиатурном обходе.
2. **Given** введён запрос или показан результат поиска, **When** ширина меняется между мобильной и настольной, **Then** ввод, режим, результат и состояние запроса сохраняются, новый поиск сам не запускается.
3. **Given** длинная подпись или увеличенный текст, **When** пользователь просматривает главную, **Then** нет горизонтального переполнения страницы; поиск и выход доступны.

### User Story 3 — Отличать данные списка от его отсутствия (Priority: P2)

Область списка показывает подтверждённые данные и состояния из публичного слоя 014, без вымышленных превью и ложного «Пока нет чатов».

**Why this priority**: Согласован GetChats; существующие чаты аккаунта нельзя выдавать за отсутствующие ради макета.
**Independent Test**: Подать вымышленные состояния слоя 014: первоначальная загрузка, успешный пустой список, непустой список, ошибка и фоновое обновление.

**Acceptance Scenarios**:

1. **Given** список ещё загружается, **When** область показана, **Then** ожидание различимо и не оформлено как подтверждённо пустой список.
2. **Given** подтверждён корректный пустой список, **When** загрузка завершена, **Then** показано «Пока нет чатов».
3. **Given** получены личные чаты, **When** список показан, **Then** видны доступные подписи; отсутствующие фото, превью и время не выдумываются.
4. **Given** данных ещё нет и запрос завершился ошибкой, **When** область показана, **Then** видны безопасное сообщение и действие повтора по контракту 014.
5. **Given** есть подтверждённый список, **When** обновление завершается временной ошибкой, **Then** карточка ошибки заменяет строки, сохранённые данные остаются в кэше; «Пока нет чатов» не показывается. Во время повтора карточка остаётся на месте; после успеха показывается список.

### Edge Cases

- Длинные аккаунт и подписи чатов, отсутствие доступных необязательных полей.
- Узкая высота окна и длинный список: контент остаётся достижимым прокруткой, элементы не обрезаются.
- Светлая и тёмная системная тема; переключение темы не сбрасывает ввод и не инициирует запрос.
- Декоративный узор не перекрывает текст, не перехватывает события и скрыт от вспомогательных технологий.
- Серверный retry-экран не получает ложный список или профиль из каркаса.
- Контракт 014 ещё не готов: интерфейс списка нельзя подключать к придуманному хуку или заменять производственные данные фикстурой; готовность интеграции отмечается отдельно.

### Verification Approach

Оформление проверяется браузерной регрессией и визуальным сравнением с локальным макетом: геометрия двух панелей, узкая колонка, темы, декоративный фон, переполнение и keyboard focus. Для новой логики представления загрузки/ошибки/повтора списка после разрешения реализации применить TDD с подтверждённым поведенческим Red. Проверить сохранение состояния формы при изменении ширины, существующие вход, профиль, поиск, выход и retry. Проверки выполняются после завершённой серии правок; источники API фиктивные, настоящих секретов нет. Команды и результаты Red/Green, регрессии и визуальной проверки записаны в [verification.md](verification.md); реальные устройства и полная ручная приёмка остаются NotRun.

## Requirements

### Functional Requirements

- **FR-001**: Рабочий каркас отображается только в подтверждённой ветке защищённой главной; решения доступа и retry не меняются.
- **FR-002**: На desktop две панели соответствуют композиции макета: слева аккаунт, поиск, список; справа область переписки.
- **FR-003**: Без выбранной переписки правая панель показывает «Выберите чат» и приглашение найти получателя; имитация реальной переписки отсутствует.
- **FR-004**: На mobile в этом шаге доступна левая панель; правая пустая область скрыта также для вспомогательных технологий. Переходы в переписку относятся к D06.
- **FR-005**: Изменение ширины/темы не размонтирует форму с потерей её ввода, режима и результата и не выполняет новый поиск.
- **FR-006**: Действующие AccountHeader, поиск и LogoutButton сохраняют свои контракты; в успешной ветке есть одно действие выхода.
- **FR-007**: Область списка использует подтверждённые данные и состояния публичного слоя 014; собственные запросы GetChats, свой кэш и копия списка в состоянии каркаса не создаются.
- **FR-008**: Первоначальная загрузка, подтверждённая пустота, непустой список и ошибка различимы. Повтор и фоновое обновление соответствуют контракту 014; при любой временной ошибке карточка ошибки заменяет видимые строки или пустой список, не удаляя данные из кэша 014. Постоянной кнопки обновления нет. «Обновить» доступно только в карточке ошибки; при повторе карточка сохраняет размер и содержание, кнопка блокируется и показывает «Обновляем…». Успех убирает карточку и показывает подтверждённые данные либо «Пока нет чатов».
- **FR-009**: Строки списка в D04 показывают реальные доступные подписи без действия открытия переписки; интерактивный выбор, сообщения, превью из истории и выбранная строка относятся к зависимым шагам. Инертные кнопки открытия не добавляются.
- **FR-010**: Пустой список показывается только после подтверждённого результата. Отсутствие интеграции 014 не выдаётся за отсутствие чатов аккаунта.
- **FR-011**: Цвета, поверхности, границы, мягкие скругления и статичный узор области переписки следуют MAX-референсу и текущей системной теме приложения.
- **FR-012**: Нет горизонтальной прокрутки на 320/360/390/768/1280 px и при увеличении текста 200%; длинный текст переносится, поиск и выход остаются достижимыми. Исправить внешние отступы страницы и внутренние отступы между аккаунтом, поиском и списком по согласованному макету; на mobile убрать лишние desktop-отступы, не обрезать элементы и сохранить доступную прокрутку.
- **FR-013**: Контраст обычного текста не ниже 4.5:1, у доступных действий видимый клавиатурный фокус; мобильные цели не меньше 44×44 CSS px. Декор не становится доступным действием.
- **FR-014**: D04 не меняет серверные API, сессию, валидацию поиска, профиль, настройки уведомлений, зависимости и правила кэша 014. Правки общих файлов других агентов сохраняются и повторно сверяются до реализации.

### Scope Boundaries

- В объёме: компоновка главной, пустой выбор переписки, декоративный фон, адаптивность, размещение существующих шапки/поиска, представление состояний и подписей списка через контракт 014, доступность и регрессия.
- За пределами: редизайн внутренней формы поиска D05; выбор и открытие чата, возврат/закрытие D06; отправка, история и уведомления; реализация API/провайдера/хука TanStack Query 014; постоянное хранение; изменение login и серверного retry.
- Макет — [max-chat-mockup.html](../../docs/ui-references/max-chat-mockup.html). Основание — [общая UI-спецификация](../../docs/chat-ui-spec.md), UI-001–UI-004, UI-010, UI-022–UI-027. В макете боковая область 310 px и переход на одну колонку при 680 px; точные CSS-значения определяются техническим планом с проверкой узкого содержимого.

### Data Effects & User Decision

- **Changed data**: Новых записей о чатах/сообщениях нет. Список приходит через слой 014; поиск и выход сохраняют существующие последствия.
- **Preview**: Пользователь видит подтверждённый аккаунт, поиск, список/его состояние и приглашение выбрать переписку.
- **Confirmation**: Для компоновки отдельного подтверждения внутри приложения нет; поиск, повтор списка и выход запускаются существующими действиями.
- **Cancellation**: Просмотр и изменение ширины не меняют данные Telegram.
- **Idempotency and duplicates**: Каркас не инициирует повторные запросы из-за адаптивности и не создаёт записи чатов; ответственность за query-кэш остаётся у 014.
- **Failure result**: Ошибка списка показывается в его области; существующие поиск и выход остаются доступны по действующим контрактам.

### Key Entities

- Рабочая область: две визуальные панели, без собственной истории сообщений.
- Представление списка: данные и состояния публичного слоя 014, без дублирования источника.

## Success Criteria

- **SC-001**: На 768/1280 px присутствуют две области и пустой выбор; на 320/360/390 px доступна левая область без горизонтального переполнения. FR-002–FR-004, FR-011–FR-012.
- **SC-002**: Ввод, режим и результат сохраняются при resize/смене темы, не появляется дополнительный запрос поиска. FR-005–FR-006.
- **SC-003**: Все пять состояний списка из US3 различимы; отображаются только подтверждённые подписи; поведение повтора согласовано с 014. FR-007–FR-010.
- **SC-004**: Клавиатура, контраст, 200% текст и мобильные цели проверены; декор не участвует во взаимодействии. FR-011–FR-013.
- **SC-005**: Вход, профиль, поиск, выход и retry сохраняют регрессию; отсутствуют новые серверные контракты и переписанные чужие изменения. FR-001, FR-006, FR-014.

## Assumptions and Dependencies

- D04 и D05 остаются отдельными задачами. Пользователь разрешил реализацию D04 и подтвердил продолжение вывода чатов 2026-10-02.
- 013 поставляет реальную шапку; 009 — работающий поиск; 014 поставляет готовые провайдер, хук и контракт списка. Данные 014 не создаются в D04.
- Публичный контракт 014 и установленная пользователем Query 5.104.0 доступны. Интеграция списка выполнена через useChats без изменения его политики.
- Общая системная тема и правила кодстайла сверены по актуальным файлам. Реализация сохраняет завершённый редизайн 015/016 и пользовательские изменения.
- Эта спецификация не разрешает отправку, выбор чата или получение сообщений.

## Уточнения интерфейса — 2026-10-02

Каркас успешной главной занимает доступную ширину окна с существующими небольшими адаптивными внешними отступами. Ограничение общей ширины 75rem снимается; ширина боковой панели 310 CSS px сохраняется, правая панель получает оставшееся место. На mobile сохраняется одна колонка. Login и серверный retry сохраняют своё оформление.

Требования: FR-002, FR-012, FR-014, SC-001.

Условие начала выполнено: завершение задачи 014 подтверждено итоговым сообщением соседнего чата. QueryProvider/useChats сохранены; консольного потребителя в продукте нет.

## Оформление по согласованному макету

Подписи списка расположены в строках без разделительных линий, с круглыми декоративными инициалами. Инициал выводится из той же подтверждённой подписи name/username/phone/chatId; префикс @ не становится инициалом. Декор скрыт от вспомогательных технологий, подпись и доступное имя остаются прежними. Это локальное оформление, без загрузки фотографии, новых DTO или вымышленных данных.

Боковая панель сохраняет ширину 310 CSS px. Заголовок списка, внутренние отступы и промежутки соответствуют референсу. Индикатор подключения использует синий акцент темы. Фон переписки содержит плотный статичный узор с контурами сообщений и G; он скрыт от вспомогательных технологий и не перехватывает события. На mobile остаётся одна колонка, правая пустая область скрыта. Открытие чата и отправка по-прежнему относятся к D06 и следующим задачам.

## Восстановление списка после ошибки

Макет карточки ошибки согласован пользователем 2026-10-02. Заголовок «Чаты» не содержит действий. Карточка показывает значок ошибки, отдельные заголовок и пояснение и кнопку «Обновить» со значком повтора. Для общего сбоя: «Не удалось загрузить чаты» и «Попробуйте ещё раз.»; для лимита: «Слишком много запросов» и «Попробуйте позже.». Состояние повтора объявляется отдельно от alert. Одинаковое место под значок и оба текста кнопки исключает изменение её размера. На 320 px, в обеих темах и при 200% тексте нет горизонтального переполнения; минимальная цель — 44×44 CSS px. При reduced motion значок не вращается. Поиск и выход остаются доступны. FR-008, FR-010–FR-014, SC-003–SC-005.
