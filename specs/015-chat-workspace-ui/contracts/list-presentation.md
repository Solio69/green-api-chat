# Контракт потребления списка 014 → D04

**Статус:** контракт 014 опубликован; слой 014 реализован; интеграция видимого списка NotRun.

ChatListPanel — единственная точка подписки D04 на публичный хук 014. ChatList — чистое представление подготовленных личных чатов и состояний. Контракт производителя не переписывается: финальные import path, имена полей DTO и callback повтора берутся из его опубликованных contracts/plan и проверяются до реализации. Опубликованные сигнатуры описаны в [query-layer.md](../../014-chat-list-query/contracts/query-layer.md), DTO в [data-model.md](../../014-chat-list-query/data-model.md); исполняемые экспорты готовы; перед интеграцией сверить их актуальные файлы.

| Результат источника                    | Представление                                               |
| -------------------------------------- | ----------------------------------------------------------- |
| Нет подтверждённых данных, запрос идёт | Объявление ожидания, без «Пока нет чатов»                   |
| Успех, подтверждённый пустой массив    | «Пока нет чатов»                                            |
| Успех, непустые данные                 | Семантический список доступных подписей                     |
| Первоначальная временная ошибка        | Безопасный текст и «Повторить» через публичное действие 014 |
| Фоновое обновление с данными           | Данные остаются, обновление различимо                       |
| Временная ошибка обновления            | Данные остаются, ошибка/повтор доступны                     |
| Ошибка доступа                         | Решение производителя/сессии; не переводить в пустой список |

UI не фильтрует Telegram-типы и не нормализует сырое тело GREEN-API второй раз. Данные и query identity не копируются в собственный store. Повтор не запускает параллельный дубль при уже выполняющемся запросе; guard берётся из состояния/действия производителя. Не угадывать HTTP-коды и endpoint.

Строки пока не кнопки: выбор переписки D06. Нет вымышленных превью, дат и аватаров. Необязательные поля не ломают уже подготовленную подпись; не использовать собственный аккаунт как получателя.

Изменение продуктовых правил возвращается пользователю, уточнение имён/типов фиксируется как техническое уточнение плана.
