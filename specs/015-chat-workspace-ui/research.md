## Техническое решение

Серверные `ChatWorkspace`, `ChatSidebar`, `ConversationEmptyState`, `ConversationBackground` компонуют slots; client `ChatListPanel` читает слой 014 и передаёт данные чистому `ChatList`. Оболочка не меняет query-настройки. Геометрия: боковая колонка 310 px + `minmax(0, 1fr)`, одна колонка до 680 px включительно. На узком экране правая пустая область `display: none`; никаких копий формы. При 200% тексте/320 px допускается вертикальная прокрутка, но не обрезание.

Фон имеет невысокую прозрачность, локальную векторную сетку, `aria-hidden`, `pointer-events: none`, без внешней загрузки/анимации. Используются текущие semantic CSS variables из темы; дополнительные размеры/узорные значения добавляются в `_tokens.scss` только при фактическом использовании. `_theme.scss`, globals и общие компоненты этой задачей не переоформляются.

## Первичные источники

- [React: сохранение состояния](https://react.dev/learn/preserving-and-resetting-state): тип и положение компонента определяют сохранение состояния; для адаптивности выбран стабильный экземпляр формы.
- [MDN: Grid columns](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/grid-template-columns): размеры колонок и minmax; применимо к двухпанельной оболочке.
- Локальный макет и спецификация 014 являются источниками дизайна и границы ответственности, не внешние примеры UI.

## Ограничения

Chromium/Playwright уже используются. Новой тестовой зависимости не требуется. Сценарии списка подставляются на нашем HTTP API по контракту 014, а не на выдуманном endpoint. Контракт известен; тест представления списка T002 ещё не написан. Ошибки импорта не объявляются Red. Автоматический zoom 200% дополнить ручным browser zoom; реальный iPhone/screen reader остаются ручными проверками.
