# Проверка D04

**Сейчас**: адаптивный каркас и уточнения ширины Passed в Chromium; видимый список и его приёмка NotRun. Слой 014 готов. Авторизация реализации сохраняется.

## Проверить готовый каркас

1. Пользователь входит самостоятельно своими реквизитами; агент их не запрашивает. Проверить профиль, один выход, поиск и сохранение заполненного поля при resize.
2. Desktop показывает две панели и приглашение выбрать чат; mobile — левую область. Область «Чаты» пока содержит только заголовок. Кнопка «Написать» не открывает переписку до D06.
3. Проверить обе темы, 320/360/390/768/1280 и широкие 1440/1920/2560 px; нет потолка 1200 px, горизонтального переполнения и потери формы. Проверить текст 200%, длинный аккаунт, короткую высоту окна.
4. При остановленном dev выполнить npm run test:e2e, npm run lint, npm run lint:styles, npm run typecheck и npm run format:check. E2E включает production build. [Фактические результаты](verification.md), [общая регрессия](../017-precommit-refactor/verification.md).

## Продолжение списка

Сверить готовый [контракт потребления 014](contracts/list-presentation.md). Выполнить T002 с постоянным chat-list-ui.spec.ts и подтвердить Red по отсутствующему представлению. Затем T005/T006/T007/T008. Список, его повтор и состояния ещё не проверены как продуктовый UI; их нельзя выдавать за успешную приёмку каркаса.

Реальный GetChats получен пользователем; ручные сценарии UI списка пока невозможны. Реальные устройства, iPhone/VoiceOver и browser zoom — NotRun. Автоматические тесты используют фиктивные данные. Не запускать dev и production build в одном .next одновременно; чужие процессы агент не завершает.
