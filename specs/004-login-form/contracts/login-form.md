# Контракт интерфейса: форма входа E03.1

Источник: [spec.md](../spec.md). Контракт описывает браузерное поведение.
HTTP-контракт для входа в этой задаче отсутствует; /api/health не меняется.

## Страница и элементы

- Адрес: /. Единственный h1: «Подключение к GREEN-API».
- Два label/input с доступными именами idInstance и apiTokenInstance.
- Поля обязательны; placeholder не заменяет подпись.
- ID — текст, не число. Токен — password, при показе text.
- Кнопка «Войти» (submit). Справа внутри поля токена — глаз (button type=button)
  без видимого текста, с aria-label/title «Показать токен» / «Скрыть токен».
  При видимом токене глаз перечёркнут. SVG декоративный, aria-hidden=true.
  Внутренний отступ поля оставляет место иконке; область нажатия не меньше 44×44 px.
- Подсказка из FR-011; ссылка на https://console.green-api.com/ с target=_blank,
  rel=noopener noreferrer и видимым указанием новой вкладки.
- Поля и кнопки внутри disabled fieldset до готовности клиентского кода.
  Ссылка и noscript вне него; поля не имеют name для HTML-сериализации.

## Проверка и ошибки

При submit первым действием отменяется стандартная отправка.
Оба поля проверяются на обязательность; пробельная строка считается пустой.
Сообщения: «Введите idInstance» и «Введите apiTokenInstance».
С первого submit флаг hasSubmitted остаётся включён до закрытия/перезагрузки
страницы, поэтому изменение поля сразу обновляет его ошибку.

Ошибки выводятся рядом с полями, связаны aria-describedby и aria-invalid.
Постоянные зоны сообщений имеют aria-live=polite. Первая попытка с ошибками
фокусирует idInstance, если оно пусто; иначе apiTokenInstance.
Это правило действует и для следующих попыток. При исправлении фокус не меняется.
Обязательность обозначена текстом «Оба поля обязательны» и required/aria-required.
form noValidate исключает конкурирующие всплывающие ошибки браузера.

При полном вводе сохраняются значения, URL и экран; сообщений об успешном входе,
ожидания API и перехода в чат нет. Отсутствие API в этом шаге описывается
в документации разработки, а не техническим баннером в интерфейсе.

## Клавиатура и начальное состояние

Порядок Tab: idInstance → apiTokenInstance → переключатель → «Войти» → ссылка.
Shift+Tab идёт в обратном порядке; фокус видим. Enter в поле запускает submit.
Enter/Space на переключателе меняет только видимость.
До гидратации форма не принимает ввод; отключённый JS сопровождается сообщением
«Для работы формы включите JavaScript в браузере».

## Данные и проверяемые границы

Ввод хранится только в локальном состоянии React. Приложение не пишет его
в логи/URL/хранилища и не отправляет по сети. Браузерные ресурсы приложения
могут загружаться; запрет касается передачи введённых реквизитов.

Автотесты используют вымышленные значения и независимые от src ожидаемые тексты.
Сеть наблюдается в течение сценария: URL, тела и заголовки запросов не содержат
тестовые реквизиты ни в исходном, ни в URL-кодированном виде.
Перезагрузка не восстанавливает ввод со стороны приложения.
Проверка хранилищ, клиентских логов и ревью прикладного кода дополняют наблюдение сети.
Ссылка в тесте получает локально перехваченный ответ, без обращения к кабинету.
