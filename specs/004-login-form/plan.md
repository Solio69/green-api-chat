## Summary

На / размещается компактная карточка с согласованным заголовком и клиентской
формой. Проверка обязательности запускается после первого submit; далее ошибки
вычисляются из текущего ввода. Токен скрывается/показывается без изменения значения.
Проверка доступа, HTTP API входа и сессия относятся к следующим задачам.

## Technical Context

Основа: Next.js 16.3.7, React 19.3.0, TypeScript 5.9.3, Sass 1.105.0,
Playwright 1.63.0, Chromium, Node 24.x. Версии и конфигурации инструментов
не обновляются. Работа локальная, состояние временное, внешние запросы и БД не нужны.

Форма: useState для строк, hasSubmitted, isTokenVisible; ошибки производные.
useRef задаёт фокус при submit; идентификаторы label/ошибок создаются стабильно
через useId. События используют типы React и существующие строгие настройки TS.
Синхронный onSubmit сначала вызывает preventDefault, затем проверяет поля.
trim определяет только пустоту и не переписывает ввод.

До готовности React fieldset отключён. useSyncExternalStore с постоянными
серверным false / клиентским true и стабильной пустой подпиской разблокирует его.
Это локальный признак готовности, не хранилище сессии. Поля не имеют name,
показывается noscript-подсказка. Переключатель type=button, вход type=submit.
Пустые поля допускают нажатие «Войти» после гидратации; form noValidate
оставляет управление ошибками приложению.

Ссылка на кабинет вне fieldset открывает отдельную вкладку с безопасным rel.
В тестах внешний адрес перехватывается. Поля управляются React; autocomplete
может быть отключён как подсказка браузеру, без обещания управлять его менеджером паролей.

| Файл | Назначение |

| `README.md`, `docs/CODE_STYLE.md` | Текущее состояние и правила кода |

Константы формы локальны её предметной области; потребители деструктурируют
нужные значения. Тесты используют общие значения при совпадении смысла,
а ожидания пользовательского и HTTP-контракта задают независимо от кода.
SCSS использует БЭМ с `&` и `@use tokens/mixins`. Повторяющиеся стили фокуса
и ошибок вынесены в миксины; цвета и размеры — в токены. Глаз — локальный inline SVG
с currentColor; библиотека иконок и другие новые зависимости не нужны.
Текущая компоновка body используется; карточка и её содержимое должны оставаться
доступны при малой высоте окна. Глаз расположен справа внутри поля токена
во всех размерах окна. Обёртка задаёт позиционирование, padding-inline-end
защищает ввод от наложения. Кнопка 44×44 px имеет aria-label, title и видимый фокус.
Сначала тест вида, положения и смены иконки, затем код и повторная проверка.

Документы реализации: актуализировать spec.md, plan.md, tasks.md,
checklists/acceptance.md, quickstart.md и docs/project-overview.md;
создать specs/004-login-form/verification.md для фактов и ограничений.

## Verification

TDD-команда для браузерной части:
npm run test:e2e -- tests/e2e/home.spec.ts tests/e2e/login-form.spec.ts tests/e2e/login-form-safety.spec.ts

Red: тесты собраны, приложение запускается, но новые элементы/поведение отсутствуют.
Ошибка импорта, отсутствующий Chromium, порт, сборка и общий timeout не считаются Red.
Если инфраструктура мешает, обозначить Blocked и устранить причину, не начинать продуктовый код.
Green: тот же набор проходит. Refactor: повторить затронутые тесты, затем полный набор.

Покрытие: все 11 сценариев spec и edge cases; проверка whitespace без изменения
значений, ведущих нулей, клавиатуры и повторной отправки.
До submit ошибок нет; после submit ошибки вычисляются и при повторном очищении.

Safety-сценарии используют новые browser contexts: обычный, javaScriptEnabled=false
и с заблокированной загрузкой JS через route.abort. Наблюдаются URL/тела/заголовки
запросов и сообщения console; cookie/Web Storage/IndexedDB не содержат введённых
фиктивных значений. Перезагрузка проверяется в чистом контексте без автозаполнения.
Нативная отправка не должна включать данные; при неготовом JS поля/кнопки отключены.
Проверка сети ограничена выполненным сценарием и дополняется ревью кода и
вывода сервера на отсутствие прикладного логирования реквизитов.

Внешняя подсказка: перехват адреса кабинета на уровне browser context до открытия
новой вкладки; проверка URL/target/rel и сохранения ввода без реального внешнего запроса.
Доступность: роли/имена, aria-invalid/describedby, клавиатурный фокус; ручная
проверка видимого кольца, читаемости и сообщения noscript.
Визуальная приёмка: 320×568 и 1280×720, начальное состояние и ошибки;
скриншоты в игнорируемом test-results при необходимости.
Это не полная проверка всех браузеров и вспомогательных технологий.

Финал: typecheck, lint, format:check, полный test:e2e (включает build),
сохранение двух HTTP-тестов health; новых тестов только на константы нет.
Если после проверок меняется код — повторить затронутые проверки.
Непроведённые действия отмечаются NotRun/Blocked, а не Passed.
