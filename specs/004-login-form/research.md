# Исследование: E03.1 — экран входа

Дата: 2026-09-30. Spec согласована. Исследование не запускает реализацию.

## R1. Граница серверного и клиентского кода

Факт: в текущем проекте App Router, страница / — Server Component.
Next.js допускает вложенный Client Component для состояния и обработчиков событий.
[Официальная документация Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components).

Выбор: `src/app/page.tsx` оставляет статическую карточку и заголовок; вложенный
`src/components/LoginForm/LoginForm.tsx` управляет сценарием формы. Поле и две
кнопки находятся в отдельных папках компонентов с публичными `index.ts`.
Альтернатива — сделать всю страницу клиентской: проще на один файл, но расширяет
границу интерактивного кода. API/Server Actions для этого шага не нужны.

## R2. Состояние и обязательность полей

Выбор: контролируемые строки в React, два флага hasSubmitted и isTokenVisible.
Ошибки вычисляются из текущих строк, а не хранятся дублирующим состоянием.
Проверка trim используется только для определения пустоты; значения не меняются.
ID остаётся строкой. submit предотвращает стандартную отправку и фокусирует
первое незаполненное поле. После первой попытки изменения сразу обновляют ошибки.

React требует согласованного value/onChange для контролируемого input.
[Документация input](https://react.dev/reference/react-dom/components/input).

Альтернативы: React Hook Form/Zod полезны для более сложных форм, но добавляют
зависимости и настройку ради двух полей; встроенные всплывающие ошибки браузера
не дают нужного управления обоими сообщениями и моментом их обновления.
Выбрана локальная проверка с form noValidate и явными required/aria-атрибутами.

## R3. Защита до готовности JavaScript

Одного preventDefault недостаточно до подключения обработчика React.
Выбор: HTML содержит disabled fieldset для полей и кнопок до гидратации.
Признак готовности определяется локальным useSyncExternalStore:
getServerSnapshot возвращает false, getSnapshot — true, subscribe стабилен
и не создаёт внешнего хранилища. Это наше применение документированного
различия серверного и клиентского снимка, а не готовый рецепт аутентификации.
[React: серверный снимок и гидратация](https://react.dev/reference/react/useSyncExternalStore#adding-support-for-server-rendering).

Входные поля в текущем шаге не имеют name, поэтому штатная HTML-сериализация
не включает их значения. Это дополнительная защита, а не замена disabled
и preventDefault. noscript объясняет необходимость JavaScript.
Ссылка на кабинет находится вне disabled fieldset.

Альтернатива — useEffect с дополнительным состоянием готовности: знакомый
подход, но создаёт отдельное обновление и избыточно хранимый признак.
Полный отказ от SSR ради этой формы лишает страницу первоначальной разметки.
Выбранный приём проверяется на реальном Next.js в трёх режимах:
обычный запуск, отключённый JS и заблокированные JS-ресурсы.

## R4. Доступность и оформление

Сохраняются видимые label; обязательность задаёт нативный required, ошибки связаны через
aria-describedby, состояние — через aria-invalid. Зоны сообщений существуют
заранее с aria-live=polite. Фокус перемещается только при попытке входа,
а не при каждом вводе. Переключатель — button type=button с меняющимся
доступным именем, «Войти» — type=submit.
[W3C: сообщения об ошибках](https://www.w3.org/WAI/tutorials/forms/notifications/).

SCSS Modules, БЭМ, общие токены и mixin фокуса соответствуют текущим правилам.
Глаз внутри поля — локальный inline SVG; библиотека компонентов или иконок
не требуется. Действие передаётся через aria-label/title, SVG скрыт от скринридера. Карточка использует существующую светлую основу; конкретные отступы
и контраст проверяются в браузере на 320×568 и 1280×720, включая ошибки.

## R5. Достаточность Playwright

Выбор: существующий Playwright/Chromium против production-сборки покрывает DOM,
фокус, Enter, локальные состояния, сеть и режимы JavaScript. Vitest/RTL сейчас
не добавляются. Альтернатива с unit/component runner ускоряет изолированные тесты,
но требует дополнительных пакетов и настройки; для этого размера поведения
достаточна одна уже работающая среда.

Проверка ссылки открывает тестовую вкладку с перехваченным ответом кабинета;
реальный внешний сервис не вызывается. JS можно блокировать через route.abort.
[Playwright: управление запросами](https://playwright.dev/docs/network).
Наблюдение запросов и логов проверяет отсутствие утечки только в выполненных
сценариях; его дополняет ревью отсутствия сетевого и сохраняющего кода.

## R6. Фактическая основа и ограничения

Локальный package.json: Next.js 16.3.7, React 19.3.0, TypeScript 5.9.3,
Playwright 1.63.0, Sass 1.105.0, Node 24.x. Версии не обновляются.
Runner уже строит production, использует 127.0.0.1:3101, один worker, retries=0
и собственный сервер; установки при обычном запуске отсутствуют.

Реальные реквизиты не нужны. Все тестовые значения вымышленные.
Хранение и серверная проверка не проектируются под видом формы.
apiUrl относится к последующей серверной задаче. Это не открытый вопрос E03.1.
