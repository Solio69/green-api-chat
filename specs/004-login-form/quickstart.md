# Проверка экрана входа E03.1

**Статус:** форма реализована; результаты проверок фиксируются в [verification.md](verification.md).
Новые пакеты, Chromium, аккаунт, токен и база данных для этой задачи не требуются:
используются уже установленные зависимости проекта.

## Ручная проверка после реализации

1. В VS Code открыть D:\Pet-projects\green-api-chat.
2. В NPM Scripts нажать ▶ у dev и открыть http://localhost:3000/.
3. Проверить карточку, два поля, скрытый токен и подсказку.
4. Нажать «Войти» с пустыми полями: две ошибки, фокус на первом поле.
5. Заполнять поля вымышленными значениями: ошибки исчезают по мере исправления.
   Очистить поле: его ошибка возвращается. Enter в поле повторяет «Войти».
6. Нажать глаз справа внутри поля токена: меняется видимость и иконка;
   текст сохраняется, отдельной текстовой кнопки нет. Проверить фокус через Tab.
7. Полный ввод оставляет форму на экране без сетевой проверки или успешного входа.
8. Проверить клавиатуру и ширины 320 и 1280 CSS-пикселей. Ссылка на кабинет
   открывается в отдельной вкладке, введённые данные остаются в форме.
9. Перезагрузить страницу: приложение не восстанавливает ввод.
10. Остановить dev через Ctrl+C перед автоматическими проверками.

Не вводить реальные реквизиты для проверки этого промежуточного шага.

## Автоматические проверки после реализации

Через NPM Scripts последовательно запускать typecheck, lint, format:check
и test:e2e. Прогон сам строит production, запускает сервер на 127.0.0.1:3101,
выполняет проверки и завершает сервер. Существующие dev/start должны быть остановлены.

Полный успех: exit code 0, без failed/skipped и с непустым набором.
Ожидается 17 passed: 15 браузерных проверок формы и 2 HTTP-проверки health.
Проверки формы и прежние два HTTP-теста health должны присутствовать.

test:report открывает последний локальный HTML-отчёт; завершить просмотр Ctrl+C.
Если Windows спрашивает Terminate batch job (Y/N)?, подтвердить Y;
запрос вложенных npm-процессов может повториться.

## Команды для фиксации Red/Green агентом

После отдельного разрешения на реализацию:
npm run test:e2e -- tests/e2e/home.spec.ts tests/e2e/login-form.spec.ts tests/e2e/login-form-safety.spec.ts

Команда запускается до продуктового кода для Red, после минимальной реализации
для Green и после рефакторинга. Ожидаемый Red вызван отсутствием формы/поведения.
Ошибка окружения или сборки не является Red.

## Ограничения

Серверная проверка токена, сетевые статусы, сохранение входа, выход и чат появятся
в других задачах. Способ хранения сессии здесь не выбран.
Автотесты не обращаются к кабинету GREEN-API: вкладка подсказки перехватывается.
Фактические Red/Green, итоговые проверки и ограничения — в [verification.md](verification.md).
