# Research: форма и отправка

**Дата**: 2026-10-02. Spec согласована; код/тесты не разрешены.

## Факты и существующие средства

[TanStack mutations](https://tanstack.com/query/latest/docs/framework/react/guides/mutations)
поддерживает useMutation, не делает retry по умолчанию, а scope.id сериализует
попытки посредством очереди. Дополнительные callbacks mutate могут не выполниться
после unmount. Поэтому компонентный unmount нельзя использовать как границу
критической записи принятого сообщения или снятия общего pending.

[Network mode](https://tanstack.com/query/latest/docs/framework/react/guides/network-mode)
online способен приостановить операцию до возвращения сети; always не сохраняет
такое ожидание. Выбраны retry:false и networkMode:'always': явное действие сразу
получает результат/ошибку, не отправляется позже автоматически из offline queue.

Фактическая QueryProvider создаёт отдельный QueryClient на scope и close()
закрывает кэш; cancelQueries не является отменой внешней мутации. useChats даёт
политику 014; новые принятые чаты объединяет 019, а не второй список в форме.
ChatWorkspace пока имеет server slots и ConversationEmptyState; ручка
RecipientSearchForm.handleWrite пока не выбирает переписку. Это будущая задача
025, не скрытая правка sending этапа.

## Варианты и выбранное решение

| Вариант                               | Плюсы                                                 | Ограничения                                      | Выбор                                        |
| ------------------------------------- | ----------------------------------------------------- | ------------------------------------------------ | -------------------------------------------- |
| Hook только внутри условного composer | Минимум компонентов                                   | Unmount/смена чата может потерять latch/callback | Не выбран                                    |
| MessageSendProvider в живом workspace | Один useMutation + синхронный ref, не зависят от pane | Один provider и публичный hook                   | Выбран для одной попытки                     |
| Mutation scope.id queue               | Библиотека сериализует                                | Вторая попытка автоматически отправится позже    | Не соответствует поведению                   |
| Optimistic temp message               | Мгновенный пузырь                                     | Корреляция временного id, ошибки и rollback      | Пользователь выбрал подтверждённый idMessage |

MessageSendProvider расположен внутри QueryProvider/NotificationProvider/
ConversationSelectionProvider, но вне условной ConversationPane. Одно действие
синхронно занимает ref до await/mutateAsync. Server lock 022 независимо защищает
весь инстанс; client latch обеспечивает обратную связь и не заменяет server proof.

## Состояние текста и поздние ответы

Composer держит только текущий текст и editorRevision; выбранный получатель и
selectionEpoch из 025. Смена chatId/close очищают текст и увеличивают revision;
same-chat refresh увеличивает accessId, но не является переключением и не должен
стирать ввод. На pending поле исходной попытки заблокировано, отправка любого
чата заблокирована; переход/close разрешены. Набранный текст другого чата не
стирается при результате прежней попытки.

В snapshot попытки: scope/chatId/attemptId/selectionEpoch/editorRevision/text/label
и owner proof. accepted факт применяется к исходному чату, если исходная Query
сессия ещё активна и owner lifetime не сменился. Временный SSE disconnect
в пределах grace не сменяет lifetime: canSend:false блокирует новую отправку,
но уже начатый accepted результат сохраняется. Изменение выбранного чата
не запрещает сохранить фактическое подтверждение исходного сообщения. Очистка
поля допускается лишь при совпадении selectionEpoch и editorRevision.
Окончательный close/смена QueryProvider игнорируют поздний ответ.

## Общие факты

addAcceptedMessage из 019 принимает idMessage, исходный text и local acceptedAt;
provider timestamp=null. История может уже содержать этот idMessage: повторного
пузыря нет. Ранний outgoingMessageStatus сохраняет partial fact по id, без
пузыря и угадывания текста; 024 обрабатывает статусы и отказ без idMessage.
rememberPersonalChat хранит подтверждённый local label отдельно от provider
PersonalChat.name; форма не выдумывает имя человека по строке телефона/username.

## Неопределённый исход

Сохранить текст только в прежнем открытом редакторе; сначала предложить
«Проверить историю», используя refetch 018 с count:10 и общим merge 019.
Ручная «Повторить отправку» имеет явное предупреждение: «Сообщение могло быть
отправлено. Повтор может создать дубликат». Обновление истории не вычисляет
успех/отказ по тексту. У пользователя остаётся явное действие повторения без
автоматического retry; дополнительного запроса SendMessage из SSE нет.

Точное кодирование ошибок, доступные тексты и проверки описаны в контрактах;
тексты действия не создают дополнительный modal/новый экран.

## Инструменты и действия пользователя

Playwright query fixture поддерживает реальные React lifecycle и фиктивный HTTP;
integration проверяет чистые guards; E2E — найденный получатель/первый принятый
чат. Новая библиотека/store не нужна. Query 5.104.0 уже установлена пользователем.
Deployment/настройки GREEN-API/Git не выполняются; реальные SendMessage не входят
в автоматическую проверку.
