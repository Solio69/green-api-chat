# Research: данные своего аккаунта и шапка

**Дата**: 2026-10-01
**Spec**: [spec.md](spec.md)
**Статус**: Исследование завершено; решения применены в реализации. Фактические проверки — в [verification.md](verification.md).

## Источники и фактическая основа

- [GetAccountSettings](https://green-api.com/telegram/docs/api/account/GetAccountSettings/) — серверный GET, поля `stateInstance`, `avatar`, `username`, `phone` и собственный `chatId`. Отображаемого имени человека в контракте нет. Пример аватара является внешним URL, а не локальным файлом.
- [GetStateInstance](https://green-api.com/telegram/docs/api/account/GetStateInstance/) — действующая проверка входа. Набор состояний позволяет сохранить принятые решения о доступе на главной.
- [Next.js Image](https://nextjs.org/docs/app/api-reference/components/image#unoptimized) — `unoptimized` сохраняет исходный источник изображения; `onError` поддерживает обработку неудачной загрузки. Пустой alt допустим для декоративного изображения рядом с подписью.
- Локальный Next.js 16.3.7: `node_modules/next/dist/shared/lib/get-img-props.js`, функция `generateImgAttrs`, при `unoptimized` возвращает исходный `src`, без вызова оптимизирующего loader. В этой ветке не требуется расширять `remotePatterns`.
- Прочитаны `src/app/page.tsx`, `src/lib/auth/resolve-home.ts`, `src/lib/auth/session.ts`, `src/lib/green-api/get-state.ts`, конфигурации Playwright, существующие home/login/logout-тесты и серверная подстановка GREEN-API.
- Доступны SCSS Modules, MAX-токены, существующие миксины, `LogoutButton` и Playwright. Пакеты устанавливать не требуется.

## R1. Метод на главной

| Вариант                                                       | Польза                                                                      | Цена                                                                                     | Решение              |
| ------------------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------- |
| `GetStateInstance` и затем `GetAccountSettings`               | Два отдельных результата                                                    | Лишний запрос для уже присутствующего в настройках состояния; дополнительный риск лимита | Не выбран            |
| `GetAccountSettings` на главной, `GetStateInstance` при входе | Профиль и состояние за один запрос на главной; сохраняется проверенный вход | Требуется новый адаптер ответа и передача профиля                                        | Выбран пользователем |
| `GetAccountSettings` также при входе                          | Единый метод                                                                | Меняется работающий контракт входа без необходимости                                     | Вне объёма           |

Главная получает профиль внутри существующего серверного открытия страницы. Новый публичный endpoint и запрос из браузера не нужны.

## R2. Повторное использование классификации

| Вариант                                                                              | Польза                                                                                         | Цена                                                         | Решение   |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | --------- |
| Копировать все правила состояний и ошибок                                            | Не затрагивает существующий модуль                                                             | Две версии одних решений могут разойтись                     | Не выбран |
| Экспортировать существующие `classifyState` и `classifyBadRequest` из `get-state.ts` | Одинаковые категории при входе и чтении аккаунта; изменение состоит в доступности двух функций | Небольшое изменение существующего файла; нужна его регрессия | Выбран    |
| Перестроить весь транспорт GREEN-API в универсальный клиент                          | Общий слой всех методов                                                                        | Затрагивает вход и поиск, расширяет задачу                   | Не выбран |

Новый `getAccountSettings` использует эти классификаторы, существующие HTTP-константы, host, общий таймаут и задержку повтора. `getStateInstance` не вызывает новый метод и сохраняет собственное поведение. Универсальный транспорт не добавляется.

## R3. Загрузка аватара

| Вариант                      | Польза                                                                           | Цена                                                                                                           | Решение                      |
| ---------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| Оптимизация через Next.js    | Изменение размера и формата                                                      | Сервер обращается за внешним изображением; требуются правила разрешённых источников и дополнительная обработка | Не требуется для этой задачи |
| `next/image` с `unoptimized` | Существующий компонент, исходный URL, обработка ошибки; сервер не скачивает фото | Браузер обращается к источнику изображения; нет уменьшения размера на сервере                                  | Выбран                       |
| Отдельный proxy изображений  | Полный контроль загрузки                                                         | Новый endpoint, дополнительные запросы и проверки                                                              | Не выбран                    |

Профиль формируется на сервере. Ссылка принимается только как абсолютный HTTPS URL без встроенных login/password и без реквизитов текущего инстанса в сыром или URL-кодированном виде. Относительные, `http:`, `data:`, `javascript:` и некорректные URL заменяются пустым значением. Allowlist доменов не добавляется: источник приходит из `GetAccountSettings`, а сервер приложения не загружает изображение. Браузер получает ссылку с `referrerPolicy: no-referrer`.

Допустимая ссылка всё равно может перестать работать. `AccountAvatar` заменяет фото нейтральной иконкой после `onError`; это не меняет подтверждённую авторизацию. При получении нового источника ошибка старого изображения не сохраняется для него.

## R4. Серверные данные и компоненты

Профиль для отображения имеет только `label` и `avatarUrl`. Username и телефон приводятся к непустым строкам без пробелов по краям; неверный тип считается отсутствием. Username имеет приоритет, но не заменяется выдуманным именем и не получает дополнительный префикс. При отсутствии обоих `AccountHeader` использует собственный текст «Telegram-аккаунт».

Проверка полей также исключает значения с реквизитами текущего инстанса. Произвольные поля ответа, собственный `chatId`, телефон при выбранном username и другие служебные данные не передаются в шапку.

`AccountHeader` остаётся серверным компонентом. Клиентский `AccountAvatar` хранит только источник изображения, загрузка которого не удалась; Redux или глобальный state для профиля не нужны. Вместо обрезки подписи применяется перенос, поэтому полный идентификатор доступен на телефоне без hover.

Для выхода переиспользуется `LogoutButton`. Локальные CSS-переменные шапки задают компактное оформление выхода; цвета поступают из единой системной палитры. Самостоятельная кнопка на экране временной ошибки также наследует текущую тему. Новая кнопка с собственной логикой выхода не создаётся.

## R5. Проверки

Интеграционная конфигурация Playwright запускает TypeScript-сценарии без браузера; она подходит для адаптера API, нормализации и решения о доступе. E2E использует существующий production-сервер и подстановку `globalThis.fetch` для GREEN-API.

Новый набор вымышленных сценариев профиля подключается к той же подстановке. Он не перехватывает наш login endpoint: вход, cookie и серверное получение профиля остаются реальными внутри тестового приложения. Изображения подставляются браузерным `page.route`, без сетевого доступа к чужим аватарам.

Для отдельных сценариев профиля используются разные фиктивные idInstance. Их серверная подстановка разрешает один `GetStateInstance` при входе и возвращает ошибку при лишней проверке этим методом; `GetAccountSettings` также проверяет этот бюджет. Так регрессия лишнего вызова на главной видна в пользовательском результате, без нового диагностического endpoint.

Используются общие проектные константы по совпадающему смыслу и независимые ожидания внешнего контракта из тестовых констант. Red требует поведенческого падения; отсутствующие файлы, ошибки импорта, сборки или окружения им не считаются.

## Ограничения исследования

Реальные реквизиты и личные данные не читались. Реальный ответ `GetAccountSettings` для аккаунта пользователя не запрашивался; его ручная приёмка запланирована после реализации. Поведение входа сохраняется; оформление входа и главной использует общую системную палитру.
