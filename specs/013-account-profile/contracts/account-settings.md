# Contract: серверное получение аккаунта

**Spec**: [spec.md](../spec.md)
**Статус**: Реализованный внутренний контракт; нового публичного endpoint нет.

## Запрос

Метод GREEN-API: **GetAccountSettings**, HTTP GET на согласованный host, путь `waInstance{idInstance}/getAccountSettings/{apiTokenInstance}`. Части с реквизитами кодируются отдельно; URL и исходное исключение не журналируются.

Параметры `getAccountSettings` — именованный объект:

- `credentials`: действующие `InstanceCredentials`;
- `fetcher`: подставляемая функция fetch, по умолчанию штатная;
- `waitForRetry`: подставляемое ожидание, по умолчанию существующий подход на `node:timers/promises` с AbortSignal.

Запрос использует существующие `GET`, `no-store` и запрет следования редиректам. Один общий AbortSignal ограничивает запрос, чтение ответа и повтор 10 секундами.

## Классификация ответа

| Ответ                                                            | Результат                                                      |
| ---------------------------------------------------------------- | -------------------------------------------------------------- |
| 401                                                              | `invalid_token`                                                |
| 403                                                              | `invalid_instance`                                             |
| 400 с действующим признаком запуска или неоднозначного состояния | `retry_later`                                                  |
| 400 с действующим признаком истечения доступности                | `instance_expired`                                             |
| Другой 400                                                       | `invalid_upstream_response`                                    |
| 5xx, сетевая ошибка, таймаут или отклонённый редирект            | `service_unavailable`                                          |
| Первый 429                                                       | Ожидание 1100 ms и единственный повтор в том же общем таймауте |
| Повторный 429                                                    | `rate_limited`, дальнейших автоматических повторов нет         |
| Прочий неожиданный HTTP-код                                      | `invalid_upstream_response`                                    |
| 200 с некорректным JSON, не объектом или неизвестным состоянием  | `invalid_upstream_response`                                    |
| 200, `notAuthorized` или `pendingPassword`                       | `needs_authorization`                                          |
| 200, `blocked` или `suspended`                                   | `instance_restricted`                                          |
| 200, `starting`                                                  | `retry_later`                                                  |
| 200, `authorized`                                                | Подготовленный `AccountProfile` и подтверждённое состояние     |

Правила состояния и 400 переиспользуют действующие `classifyState` и `classifyBadRequest`. Их экспорт из `get-state.ts` не меняет `GetStateInstance` при входе.

## Данные отображения

`normalizeAccountProfile` принимает именованный объект с исходным `unknown` и серверными реквизитами. Выдаёт только `{ label, avatarUrl }`; пустые значения берутся из общего `EMPTY_STRING`.

Username имеет приоритет над телефоном. Поля отображения с неверным типом или пустым значением отсутствуют. Их отсутствие не отменяет валидное подтверждение авторизации.

Аватар — абсолютный HTTPS URL без userinfo. Значения с текущими реквизитами в сыром или URL-кодированном виде не передаются в профиль. Некорректный URL и неподходящий протокол дают пустой аватар. Дополнительные поля ответа поставщика не сериализуются.

## Подключение к главной

`resolveHome({ credentials, getAccountSettings })` сохраняет действующие решения о доступе и возвращает подготовленный профиль только в успешном варианте. Главная вызывает этот путь один раз на открытие; внутри адаптера допустим только согласованный повтор 429.

`src/app/page.tsx` передаёт безопасный профиль в `AccountHeader`. При успехе выход расположен только в шапке. При временной ошибке шапки и поиска нет, но отдельный существующий выход доступен. Без сессии или при завершении доступа используются существующие фиксированные маршруты.

Срок cookie не продлевается чтением профиля. Новый API `/api/account`, клиентский fetch профиля, автоматическая настройка инстанса и вызов `GetAccountSettings` при входе не добавляются.
