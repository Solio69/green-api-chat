**Spec**: [spec.md](spec.md)

**Согласование spec.md**: Получено в переписке 2026-09-30: «делай остальные спеки и если аналайз ок то пиши код».

**Разрешение на реализацию**: Получено тем же сообщением; успешный read-only анализ выполнен до изменения кода.

## Summary

Оформить только существующий экран `/` по [референсу А](../../docs/ui-references/login-palette.svg): нейтральный фон, белая карточка с лёгкой тенью, `#abffac` сверху, граница `#b7eb8f`, тёмный текст и читаемые зелёные интерактивные элементы. Значения хранятся в семантических SCSS-токенах; логика формы не меняется.

## Considered Options

| Вариант | Преимущества | Ограничения и риски | Выбор и причина |
| --- | --- | --- | --- |
| Референс А и разделение ролей зелёного | Спокойная форма, нужный контраст текста, общий источник цветов | Чуть больше семантических токенов | Выбран пользователем; соответствует FR-001–FR-005 |
| Полная светло-зелёная заливка и один зелёный для всего | Меньше различий между зелёными | Более насыщенная композиция; текстовая ссылка и белый текст кнопки на `#3b9702` недостаточно контрастны | Не выбран |

## Technical Context

Next.js 16.3.7, React 19.3.0, Sass 1.105.0, Playwright 1.63.0, Node 24.x. Используются только уже установленные средства; БД, сеть и внешние API не затрагиваются. Текущие `src/styles/_tokens.scss`, SCSS Modules и `focus-ring` обеспечивают нужные точки изменения. Рабочие изменения E03.1 в Git уже staged пользователем; они сохраняются, Git-команды записи не выполняются.

## Tasks and Dependencies

Последовательность: исходная проверка доступности инструментов и тестов → обновление семантических токенов → применение к карточке и форме → проверка визуальных состояний/контраста и существующих E2E → ревью и verification. Для CSS нет изменяемой бизнес-логики или серверного контракта, поэтому Red не требуется. Текущие `test:e2e`, `typecheck`, `lint`, `format:check` выполняются без установки пакетов. `test:e2e` сам строит production и запускает свой сервер; dev-сервер в этой папке одновременно не запускается.

## Verification

- Вычисленные стили `/`: точные цвета FR-001–FR-004, достаточный контраст ссылки и кнопки, видимые фокус и ошибки.
- Ручной осмотр исходного, фокусного и ошибочного состояния на 320×568 и 1280×720. Скриншоты допустимы в игнорируемом `test-results`, но не являются единственной проверкой контраста.
- `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run test:e2e`. Последняя команда включает production-сборку и существующие тесты формы/health.
- Failed при нарушении видимого требования или теста; Blocked при недоступности инструмента/занятом порте. Не объявлять неисполненную проверку Passed.
