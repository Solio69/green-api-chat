# Контракт формы поиска D05

Источник поведения — 009; HTTP-маршрут, request/response, auth и server errors не меняются.

RecipientSearchForm остаётся единственным владельцем ввода/запроса и определяет handlers до return. RecipientSearchModeSwitch получает текущий режим, disabled и handlers двух кнопок; семантика group и aria-pressed сохраняется. RecipientSearchField сохраняет label/ref/error/описание; новый визуальный ряд содержит поле и контейнер SubmitButton ограниченной ширины, с переносом при недостатке места.

SubmitButton используется с существующим isLoading; его SCSS допускает локальные CSS-переменные размера, отступов, скругления и веса шрифта с прежними значениями по умолчанию. Контейнер формы задаёт эти переменные и ширину/позицию локально; оформление login сохраняется. На 320 px и 200% тексте допускается новый ряд для кнопки. Поле не теряет видимую подпись, а label не заменяется placeholder.

Ожидание — индикатор кнопки плюс одно постоянное role=status вне disabled fieldset; не объявлять одно и то же сообщение несколькими live regions. Errors поля остаются связаны через aria-describedby; general/not-found получают безопасные тексты текущих категорий. Phone hint и действие перехода к username сохраняют контракт 009, тексты макета не заменяют согласованные сообщения.

Никакого дополнительного fetch/query/retry при typing, mode switch, theme или viewport. Hydration/no-JS сохраняют прежнее отключение и пояснение. Инертная «Написать» — исключение по прямому пользовательскому решению, не новый pattern для остальных действий.

## Уточнения интерфейса — 2026-10-02

В режиме username под вводом всегда видна подсказка «Можно вводить с @ или без него». При переключении phone/username высота формы без результата, ошибки и ожидания остаётся одинаковой при той же ширине окна, теме и масштабе текста. Области подписи поля и подсказки учитывают переносы более длинного текста в каждом режиме. Ошибки и результаты могут естественно расширять форму.

Добавить текст username в константы формы. Обе подсказки разместить в одной области CSS Grid: скрытая подсказка участвует в расчёте естественной высоты, но имеет visibility:hidden и aria-hidden. Видна и доступна для чтения только активная подсказка; aria-describedby указывает на действующее описание. Для подписи применить тот же естественный расчёт: связанный label и скрытый aria-hidden span являются соседями в одной ячейке Grid. Не задавать фиксированную высоту формы и не измерять DOM через JavaScript.

Проверка: Проверить точный текст username и одинаковую высоту пустой формы до/после переключения в обоих направлениях на 320/390/1280 px и при тексте 200%, включая переносы. Убедиться, что вспомогательные технологии получают только активную подсказку; переключение не отправляет запрос. Повторить существующую регрессию поиска.

## Оформление по согласованному макету

Поиск использует нейтральную поверхность поля и переключателя; выбранный режим выделен синим текстом и отдельной поверхностью. В покое у поля нет тени; при фокусе видны тонкая синяя рамка и мягкая подсветка, при ошибке — красная рамка и подсветка. В forced-colors остаётся системный контур фокуса.

Заголовок, подпись поля, отступы, скругления и компактная кнопка соответствуют референсу. Локальные CSS-переменные формы задают размеры SubmitButton; значения по умолчанию общей кнопки сохраняют оформление login. Цвета и размеры вынесены в используемые SCSS-токены; обе темы используют общий system-theme. На mobile интерактивные цели не меньше 44 CSS px, текст поля не меньше 16 px. Подсказки, стабильная высота при смене режима, валидация, Enter и количество запросов сохраняют действующий контракт.
