# Модель представления поиска D05

Нового серверного DTO, хранилища или query-key нет.

| Данные               | Владелец                            | Правило                                                |
| -------------------- | ----------------------------------- | ------------------------------------------------------ |
| mode/value/валидация | RecipientSearchForm                 | По действующему 009                                    |
| normalized query     | Существующий parseSearchRequest     | Валидированный телефон либо username                   |
| pending/guard/error  | RecipientSearchForm                 | Прежняя блокировка и категории                         |
| found result         | Единственное состояние result формы | chatId ответа + label текущего валидированного запроса |
| not-found result     | То же result                        | Без label/chatId карточки успеха                       |
| ModeSwitch/Result    | Чистые пропсы                       | Не запускают fetch и не хранят копию результата        |

label формируется из captured parsedInput после успешного ответа и хранится в том же found-result. При смене режима/редактировании result очищается; текущий ввод другого поиска не подставляется в старую карточку. Несовпадение успеха с malformed body сохраняет существующую ошибку. Функция форматирования принимает готовый RecipientQuery, не переопределяет валидатор.

«Написать» вызывает только placeholder из формы: нет selectedChat, записи списка или передачи токена. У placeholder нет состояния loading/success. Список 014 и будущая история в модель поиска не входят.

## Уточнения интерфейса — 2026-10-02

В режиме username под вводом всегда видна подсказка «Можно вводить с @ или без него». При переключении phone/username высота формы без результата, ошибки и ожидания остаётся одинаковой при той же ширине окна, теме и масштабе текста. Области подписи поля и подсказки учитывают переносы более длинного текста в каждом режиме. Ошибки и результаты могут естественно расширять форму.

Новых сущностей, API DTO, query keys и хранилищ нет; уточнение относится к представлению.
