# Карта правил кода GREEN-API Chat

Смысловые решения, которые требуют ревью агента, находятся в [правилах написания кода](CODING_RULES.md). Там описаны структура компонентов, условия, обработчики, константы, тестовые ожидания, доступность и выбор SCSS-токенов/миксинов.

Исполняемые источники автоматических правил:

| Область                                                                           | Конфигурация                                    | Проверка               |
| --------------------------------------------------------------------------------- | ----------------------------------------------- | ---------------------- |
| TypeScript/JavaScript, Next.js, импорты, стрелочные функции и упрощение выражений | [eslint.config.mjs](../eslint.config.mjs)       | `npm run lint`         |
| Форматирование, в том числе отсутствие необязательных точек с запятой             | [prettier.config.mjs](../prettier.config.mjs)   | `npm run format:check` |
| Синтаксис и стандартные правила SCSS, вложенный БЭМ                               | [stylelint.config.mjs](../stylelint.config.mjs) | `npm run lint:styles`  |

Порядок импортов TypeScript/JavaScript: встроенные и сторонние библиотеки → внутренние типы, функции и хуки → константы из файлов `constants` или `*.constants` (сначала через `@/`, затем локальные) → компоненты → CSS/SCSS последними. Категория определяется путём импортируемого файла: `@/features/auth/ui/LoginForm/constants` относится к константам. ESLint проверяет порядок, в том числе для глобального стиля без импортируемого имени, и запрещает `../` в импортах из `src`. Правило выбора между `./` и `@/` описано в [правилах для агента](CODING_RULES.md#импорты).

Правила процесса, тестирования и ревью задаёт [AGENTS.md](../AGENTS.md), ограничения Git — [GIT_POLICY.md](../GIT_POLICY.md). Команды и локальный запуск описаны в [README.md](../README.md). Исполняемые конфигурации являются источником автоматических норм; этот файл служит навигацией и сохраняет действующий адрес для ссылок проекта.

Настройки сохранения файлов в VS Code находятся в [проектном settings.json](../.vscode/settings.json). После изменения конфигурации форматтера используй `Developer: Reload Window` и проверь сохранение файла внутри проекта отдельно от CLI: успешная командная проверка сама по себе не подтверждает состояние расширения.

## Проверка Promise с типами

В TS/TSX/MTS действуют @typescript-eslint/no-floating-promises и
@typescript-eslint/no-misused-promises. ESLint читает три проекта TypeScript
из общей команды typecheck; JS-конфигурации сохраняют обычные правила.

Ожидаемые операции нужно await/return либо обработать rejection.
Promise в синхронном callback, условии или JSX event handler диагностируется.
Синхронная граница React-события может запускать операцию через явный void
только когда ошибки уже обрабатывает сама операция или Query/controller state.
ignoreVoid:true обозначает это исключение; сам void не ловит rejection.
Владелец ошибки и сохранение порядка проверяются на ревью и в тестах;
пустой catch ради lint недопустим. JSX-проверка правила не отключена.

Проверка: npm run lint. Настройки и аудит текущих async-контрактов —
[032 research](../specs/032-type-aware-eslint/research.md).
