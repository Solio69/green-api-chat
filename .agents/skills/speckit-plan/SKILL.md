# plan

Применять только к выбранной задаче этого проекта. Пользовательские решения
и ограничения сохраняются между этапами. Общий порядок:
[workflow](../../../docs/spec-kit-workflow.md);
правила: [AGENTS](../../../AGENTS.md),
[constitution](../../../.specify/memory/constitution.md),
[Git](../../../GIT_POLICY.md).
Происхождение: [provenance](../../../docs/spec-kit-provenance.md).

## Контекст вызова

Определить абсолютный $taskProject по расположению этого SKILL.md (три уровня
вверх). Взять ожидаемую задачу из текущего обсуждения, а не из имени ветки.
Явно задать SPECIFY_FEATURE_DIRECTORY и абсолютный $taskFeature.
При неизвестной задаче запросить её, не выбирать последнюю.

Любой именованный ниже script расположен в
.specify/scripts/powershell/ относительно $taskProject. Вызов из корня
или подкаталога проекта, например:

~~~powershell
& (Join-Path $taskProject '.specify/scripts/powershell/check-prerequisites.ps1') -Json -RequireSpec -ExpectedFeatureDirectory $taskFeature
~~~

В каждом вызове передавать -ExpectedFeatureDirectory $taskFeature.
Проверить успешный exit code и точное совпадение FEATURE_DIR с ожидаемым путём
до чтения документов. При ошибке остановить зависимую работу и объяснить причину.
Рабочие зависимости только локальные; hooks, публикация, установки и автоматические
Git-действия отсутствуют.

## Порядок

1. Убедиться, что spec согласована по переписке. Выполнить
   check-prerequisites.ps1 с -Json -RequireSpec, затем setup-plan.ps1 с -Json.
   Оба вызова с тем же ExpectedFeatureDirectory. Существующий план сохранить.
2. Прочитать spec, принципы и фактическое состояние проекта. Проверить C1–C8
   до проектирования; не применять правила исходного чужого продукта.
3. Исследовать существенные технические решения и существующие средства.
   В research.md зафиксировать факты, варианты, преимущества/риски и выбор.
   Проверить изменчивые внешние факты по официальным источникам. Ничего не
   устанавливать. Существенные новые продуктовые решения согласовать.
4. Заполнить [plan-template.md](../../../.specify/templates/plan-template.md).
   Подготовить необходимые data-model.md, каждый contracts/*, quickstart.md;
   для неприменимого артефакта объяснить отсутствие. Указать полный перечень
   новых/изменяемых файлов, зависимости, проверки и действия пользователя.
5. Повторить C1–C8 после проектирования. Не менять общий AGENTS.md ради ссылки
   на текущий план. Не вызывать отсутствующие средства обновления контекста.
6. Передать готовые документы этапу tasks. Наличие плана не разрешает код.
